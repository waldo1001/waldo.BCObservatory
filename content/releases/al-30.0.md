## Permission set descriptive help

- Added `AboutText`, `AboutTitle`, `AboutTextML`, and `AboutTitleML` to permission sets and permission set extensions for runtime 30.0.

## Localized About descriptions

- Fixed false AL0839 errors when a page and its extension provide About descriptions in different languages. Page textstore conflicts in the same language remain errors. A permission set and its extension can provide different About descriptions in the same language; both are stored in their respective metadata.

## Development tools runtime

- .NET 10 is now the sole supported .NET runtime for the development tools and their NuGet packages. Building the tools or launcher requires a .NET 10 SDK.

## Word layout diagnostics

- Warning AL0935 identifies Word layouts that reference dataset elements marked `ObsoleteState = Pending`, separately from ordinary AL0432 symbol-reference warnings. It points to the AL layout declaration; unused dataset elements do not warn.
- Warning AL0936 identifies Word layout references that cannot be fully resolved without rejecting otherwise valid layouts. It is independently suppressible from AL0935; existing layout-generation errors remain unchanged.

## Parallel workspace compilation

- Fixed package-cache lock conflicts being reported as invalid-package errors during parallel workspace compilation on Linux and macOS. They are now reported as the existing package-locked warning.

## Markdown page fields

- Added `ExtendedDatatype = Markdown` for page fields bound to a `Text` variable, `Text` table field, or `Text`-returning procedure, including bounded `Text`. Requires `MultiLine = true` and an only-child field in a root-level group in the Content area. The value remains raw Markdown; direct table-field declarations and `BigText`, `Code`, `Label`, `TextConst`, string literals, and concatenation sources are not supported.

## Modify several fields in one ModifyAll call

`ModifyAll` now accepts up to five field and value pairs on both `Record` and `RecordRef`, so a bulk update of
several fields no longer needs one call per field. `RunTrigger` stays optional and last:

```al
Customer.ModifyAll(Blocked, Blocked::All, "Payment Terms Code", 'CM', true);
RecRef.ModifyAll(AmountFieldNo, 0, DescriptionFieldNo, 'Cleared');
```

`RecordRef.ModifyAll` is new and requires runtime version 30.0 for every call, including a single pair.
`Record.ModifyAll` keeps its existing single-pair form unchanged; only its new multi-pair forms require runtime
version 30.0.

`Record.ModifyAll` rejects repeated fields, even when their values are identical. Calls exceeding the
five-pair limit now report the overload argument-count error instead of reporting valid excess field
names as unknown. `RecordRef.ModifyAll` behavior is unchanged.

## Inherent permissions validation in multi-root workspaces

The compiler now reports AL0720 when an `InherentPermissions` attribute in one project references an object from another project in a multi-root workspace.

## ALTool code coverage export

`altool runtests` can now export code coverage in BC JSON and Cobertura XML formats. Coverage can include per-line hit data and per-test procedure lookup, with optional AL source enrichment for uncovered lines and procedures.

## Snapshot MCP test coverage

Snapshot Debugging MCP `run_tests` now returns opt-in, inline code coverage alongside test results. Set `coverageMode` to `procedure` (test identities and procedure edges), `line` (line hits), or `all` (both). Names are case-insensitive; omitted or `none` preserves existing behavior and omits coverage. Null, blank, numeric, and unknown values are rejected before execution. Standalone test-running MCP tools are unchanged.

Call `initialize_snapshot_debugging` to arm a WebClient context (omit `sessionId`), then pass the returned context to `run_tests`:

```json
{
  "debuggingContext": "<context returned by initialize_snapshot_debugging>",
  "testCases": [{ "codeunitId": 50100, "testMethods": ["MyTest"] }],
  "coverageMode": "all"
}
```

Always finish with `stop_snapshot_debugging` using the same context to retrieve the snapshot, including after failed tests or coverage errors. Coverage preserves the initialized snapshot verbosity. Ordinary AL test failures still return coverage with `success: false`, not an MCP tool error.

Each `codeunitResults` entry has its own `coverage` object: `schemaVersion: "1.0"`, normalized `coverageMode`, `dataScope: "server-recorded"`, and `tests`, `procedureEdges`, and `lines` arrays. Empty arrays are valid; test IDs and edges remain scoped to each entry, including repeated codeunits. These recorded facts do not establish a whole-project coverage percentage. No local files, source enrichment, stored coverage resources, or pagination are added.

Coverage requires support in the owning server's `run_tests` schema; unsupported servers are rejected before tests execute, while omitted/`none` remains compatible. Coverage-enabled responses are limited to **4 MiB of serialized MCP `CallToolResult` UTF-8 JSON**, including text-content escaping. Collection or limit failures are explicit MCP tool errors, never truncated success or automatic retries. Tests may already have run: stop the context, then use a new context with fewer codeunits/methods or a narrower mode for a later run.

- Fixed report and query compilation producing unstable generated C# ordering for identical AL input, so repeated builds now produce consistent output hashes.
- Fixed server-side C# compilation failing with CS0119 when an AL application object declares a procedure named `Array` and performs a no-argument application object method call.
- Fixed report extensions generating invalid C# when a column's `AutoFormatExpression` references a protected variable from the base report.
- Fixed AA0150 (do not declare parameters by reference if their values are never changed) false positive on codeunit methods that implement an interface. The parameter direction (`var`) is dictated by the interface contract and cannot be changed by the implementor, so the rule no longer fires on these methods.
- Fixed handler names in the `TestHandlers` property not being syntax highlighted.
- Fixed AL0327 missing-file errors when compiling control add-ins with Windows-style resource paths on Linux or macOS. Script, stylesheet, and image paths now accept either directory separator during lookup and packaging.
- Fixed agentic AL LSP symbol searches returning an unexplained failure when requested while the workspace was still loading. The `al/symbolSearch` endpoint now waits briefly for initialization and otherwise returns guidance to retry after workspace loading completes.
- Fixed the BCal CLI `/reset` command remaining unavailable in remote MCP sessions after the server advertised workspace reset support.
- Word report layouts containing `INCLUDETEXT` or `INCLUDEPICTURE` field codes now produce a compiler warning.
- `al_symbolsearch` now finds top-level application objects by exact numeric object ID, including objects from dependency symbols.
- Fixed `al_symbolsearch` retaining fully materialized symbol descriptors for the active project and its dependencies after searches. Searches now traverse only the requested symbol scope and return additional results through continuation tokens.
- Fixed culture identification in extension translations, preserving distinct language variants and preventing duplicate-translation errors during publishing.
- Improved AL source formatting in Visual Studio Code and after BCal file writes and edits. Formatting now applies CodeCop-compatible operator, block, and control-keyword layout while keeping empty blocks and blocks with a single property compact. Set `al.legacyFormatting` to `true` to restore the previous formatting behavior in Visual Studio Code; BCal always uses the improved behavior.
- Fixed inconsistent event subscriber ordering when metadata-based event binding is enabled.
- Fixed AS0072, AS0073, AS0074, AS0075, and AS0076 being reported for unchanged obsolete members when a new extension object with a lower object ID targets the same object as an existing extension object.
- Fixed downloads of dependency symbols failing without retrying when another process temporarily locks the destination package. `altool listtests --force` still reports a locked cache-replacement failure instead of retrying.
- Fixed an issue where semantic token processing could crash when a preprocessor `#if` or `#elif` condition appeared inside a report data item, query data item, or XMLport table element.
- Fixed the AL Table Proxy Generator (altpgen) omitting lookup FlowFields, such as `ParentAccountIdName`, when the looked-up Dataverse table already exists in the project or a dependency. For a table in a dependency, the FlowField shows the first field of the table's `DropDown` field group and is still omitted if the table declares none.
- Fixed breakpoints in default interface method implementations not being hit when continuing execution with F5, including when interfaces share a name across namespaces.
- Improved diagnostics for private NuGet symbol feeds. A feed that returns HTTP 401 now reports "requires authentication", while HTTP 403 reports "requires authentication or additional permissions" at the failed request, and any credentials embedded in a feed URL are stripped before the URL is written to logs.
- Fixed RoleCenter bookmarks created by Designer disappearing when their action targeted an invalid position in the Sections area. The bookmark is now placed in the default navigation location.
- Fixed generated reference previews omitting the `Subtype` and `TestHandlers` properties from test codeunits.
- Fixed AppSourceCop upgrade rules failing with `AD0001` when an extension's dependencies include another version of the same extension.

## ALTool changes

- Added `altool downloadsymbols` to download the symbol packages required by an AL project from a Business Central server or global NuGet sources. Use `--project` to select the project (the current directory is used by default), `--packagecachepath` to select the destination cache, and `--force` to refresh cached packages. `--globalsourcesonly` downloads without a server and supports country/region, custom-feed, custom-feeds-only, and minor-version options. Server downloads use the same connection options as other `altool` commands. The command emits structured JSON by default for pipeline use; pass `--raw` for human-readable output.
- Added `altool listtests <appId>` to discover an app's test codeunits and procedures without running tests, loading a workspace, or requiring source access. It reuses the highest-version matching package in `.alpackages` and downloads only on a cache miss, preserving the downloaded package for later calls. Use `--project` for launch settings and the default cache location, `--packagecachepath` for another cache, or `--force` to download fresh symbols. `altool listtests --appfile <path>` inspects an existing `.app` file entirely offline. Successful stdout contains compact JSON with `appId`, `appName`, `appPublisher`, `appVersion`, and `codeunits` containing `id`, `name`, `namespace`, and `methods` (`name`, `isDataDriven`). Ordinary and data-driven procedures are included; runtime-generated cases are not enumerated. The version identifies the inspected package, not necessarily the installed server version. Logs and contextual metadata errors go to stderr; failures return nonzero instead of a partial or empty success result.

- Added `al workspace restore` to download missing external NuGet symbol dependencies for all projects in a workspace from public NuGet feeds.

### AL Tool: Workspace restore command

The `al workspace restore` command downloads missing external NuGet symbol dependencies for all projects in a workspace. It reads the workspace file, collects references from each project's `app.json`, skips workspace-internal and already-cached packages, and downloads the rest from public NuGet feeds. Only public (unauthenticated) feeds are supported today.

By default, stdout contains one JSON result with the restore status, counts, and notices; progress and diagnostics go to stderr. Use `--raw` for the human-readable output. Success returns exit code 0; incomplete restore and command failures return exit code 1.

```bash
al workspace restore myworkspace.code-workspace
```

The following options are available:

| Option | Description |
|---|---|
| `--packagecachepath` | Package cache directory where symbols are downloaded and looked up. Defaults to `.alpackages` in the workspace directory. |
| `--symbolscountryregion` | Country/region code for NuGet downloads (for example, `w1`, `us`, `dk`). Defaults to `w1`. |
| `--nugetfeeds` | Additional NuGet feed URLs to search alongside the built-in Microsoft feeds. |
| `--useonlycustomfeeds` | Skip the built-in Microsoft feeds and only search custom feeds. |
| `--enforceminorversion` | Restrict NuGet download selection to the requested major/minor, except for platform symbols. Does not pin cached packages or workspace references, or change compiler binding. |
| `--raw` | Emit human-readable progress and result text instead of structured JSON. |

Restore combines each dependency's declared minimum versions across projects using the highest minimum per AppId. When a download is needed, an exact version match is selected first; otherwise, `--enforceminorversion` selects the highest available patch in that major/minor (platform symbols retain their same-major fallback). Already-compatible cached packages and workspace source projects remain usable even when their minor differs from the requested version.
