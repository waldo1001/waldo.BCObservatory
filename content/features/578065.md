# Run multiple Sales Order Agents per company with smarter item matching, relevance filtering, and streamlined setup

> Copilot and agents: Run multiple Sales Order Agents per company with smarter item matching, relevance filtering, and streamlined setup. Generally available, GA 2026-07 (Microsoft 365 roadmap). You can now configure and run multiple Sales Order Agent instances in a single company. Each instance operates independently with its own mailbox, folder settings, email signature, and processing rules. Each agent instance tracks its own KPI metrics, such as emails received, quotes created, orders created, and time saved.

[Microsoft 365 roadmap 578065](https://www.microsoft.com/microsoft-365/roadmap?id=578065) · Copilot and agents · generally available · roadmap status "Launched", phase General Availability

## What Microsoft says

You can now configure and run multiple Sales Order Agent instances in a single company. Each instance operates independently with its own mailbox, folder settings, email signature, and processing rules. Each agent instance tracks its own KPI metrics, such as emails received, quotes created, orders created, and time saved. The setup page is restructured to support per-instance configuration, and an upgrade path migrates existing single-instance setups to the new architecture. This change allows organizations to set up separate agents for different sales teams, product lines, or customer segments, each monitoring their own personal or shared mailbox. Improved items search: When a customer requests items, the agent now uses a multi-layer matching strategy: Exact identifier match: direct lookup by item number, vendor item number, GTIN, or cross-reference. Semantic attribute matching: extracts attributes from the customer's message (color, material, size) and ranks candidates by relevance using AI. Broader fuzzy search: falls back to a global item search when direct and attribute-based searches produce no results. Message and attachment relevance: The agent now validates incoming messages and attachments against a detailed relevance model before processing. Messages that fall outside the agent's responsibilities (such as offers to sell, requests for discounts, or attempts to extract internal information) are identified and filtered. A separate relevance check runs on attachments, ensuring that non-sales-related documents don't trigger unnecessary processing. The validation considers the full conversation history and the agent's defined scope to make accurate relevance decisions. Larger attachment files with diagnostics. The maximum number of pages per PDF attachment has been raised from 10 to 50, addressing customer feedback about the agent not reading larger purchase orders. A new cumulative content length limit of 150,000 characters is also enforced across all attachments in a single email (approximately 50K tokens). When an attachment is skipped, Business Central now stores the specific reason directly on the attachment record (page count exceeded, cumulative content length exceeded, attachment count exceeded, unsupported format, or analyze-attachments not enabled). This information is visible on the Attachments page and logged in telemetry, making it straightforward to diagnose why a particular document wasn't processed. Try it out. You can now create tasks for the Sales Order Agent without sending an email. From the agent's setup page, a new Try it out section lets you compose a message by selecting a sender (from your contact or customer list), entering message text, and attaching files. The agent acts like it received a real email. To help you get started quickly, two sample messages are included. One is a text-only message that references items from your catalog, and the other is a message with a sample purchase order attachment. The sample order is generated based on your actual item data, so the agent has realistic content to work with. These samples are particularly useful for first-time setup, demos, and testing agent behavior with specific scenarios without needing to send an actual email. Handling of unknown senders When the agent receives an email from an unregistered email address, you now have three options instead of just one: Create a new contact: register the sender as a new contact (existing behavior) Use another contact once: pick an existing contact from the contact list and link them to this specific task only, without modifying any master data. The override is stored per task message and does not affect future emails. Update an existing contact's email: select an existing contact and update their email address to the sender's address More control over email New configuration options give administrators more control over how the agent interacts with the monitored mailbox: Mark email as read: a new toggle to mark processed emails as read in the mailbox. This works in addition to the custom Processed by Sales Order Agent category, giving users a visual signal in their inbox. Mandatory folder selection: the agent now requires you to select a specific mailbox folder before activation. Previously this was optional and could lead to the agent monitoring an unexpected folder. If in doubt, choose Inbox . Stricter activation validation: trying to activate the agent without a mailbox folder now shows a clear error message instead of allowing activation in an ambiguous state. Prompts as embedded resources. The agent's AI prompts (instructions, item search logic, mail template checks, irrelevance validation) are now shipped as embedded resource files within the app extension package. This change reduces latency on first task processing and makes the prompt structure more transparent for engineering iteration. Business Value: The Sales Order Agent now handles more complex organizational structures and higher volumes with less manual intervention. You can run multiple agent instances in one company, each dedicated to a different team or shared mailbox with independent settings and performance tracking. The agent finds the right items more reliably by understanding product attributes, informal descriptions, and identifiers across multiple matching layers. The agent now processes PDFs up to 50 pages (previously, the limit was 10) and clearly shows why any attachment was skipped. It also filters irrelevant messages before processing, so credits aren't consumed by marketing emails or out-of-scope inquiries. If a customer writes from an unregistered email address, you can link an existing contact to that single task without creating duplicates. You can test the agent directly from the setup page without sending a real email, reducing the time to validate your configuration. Enabled for: Enabled for end users automatically
