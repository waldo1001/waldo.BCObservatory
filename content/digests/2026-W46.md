## Code changes

The largest change this week is #9587, which adds concurrent posting for General Ledger entries. It touches G/L Entry, G/L Register, Bank Account Ledger Entry and the Gen. Jnl.-Post Line and Gen. Jnl.-Post Batch codeunits, and the PR description gives no further detail, so partners with posting extensions should test them. Several fixes change posting and reporting behaviour. #13628 fills Your Reference, Vendor Order No. and Vendor Shipment No. on posted purchase receipt lines created by drop shipments. #12770 makes project ledger entries reflect modified invoice discounts on G/L Account purchase lines. #13482 aligns non-deductible VAT amounts in purchase invoice statistics with VAT and G/L entries. #13607 makes report 713 export one aggregated row per Item and Customer in Excel data-only format. #13616 disables table relation validation on SWIFT fields in the Czech localization, so codes missing from the SWIFT Code table are accepted. The Expense Agent gets three changes: #13730 adds an upgrade that initializes missing vendor number series, #13672 adds VAT settings to the setup wizard, and #13792 adds the Is Feature Trial field to the legacy consumption table. Finally, #13765 sets a maximum output token budget in the E-Document MLLM Handler for the upcoming 5.6 model version.
