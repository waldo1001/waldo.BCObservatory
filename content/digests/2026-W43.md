## Code changes

Three pull requests in microsoft/BCApps change behaviour this week. #12846 adds a Country/Region of Origin Code field to document lines for Czech Intrastat reporting. The value starts from the item card, can be changed per transaction, and there is an option to retrieve values from posted entries instead. #11998 makes the system check that a General Posting Setup combination exists before journal invoices are posted, which avoids problems later with Adjust for Payment Discount. Partners with data that relied on missing combinations may now see posting errors. #12552 is a fix on the 29.x line. Validating the "No." field on a sales order with a linked released production order caused repeated production order status warnings and possible modal dialog errors in write transactions. It touches Sales Line and Check Prod. Order Status. The one refactor, #12443, renumbers the SII table extensions, page extensions and codeunits in the Spanish Base Application layer. Extensions that reference those object IDs should be checked. In microsoft/BCQuality, no behaviour changes. #230 adds five knowledge articles on report layouts, report dataset contracts, and query join and grouping defaults. #223 adds an article on rounding calculated unit prices to the currency's Unit-Amount Rounding Precision. #231 lets the al-agents-review skill derive the target Business Central version from app.json.
