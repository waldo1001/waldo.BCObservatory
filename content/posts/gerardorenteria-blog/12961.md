# 🕐 Remember When Lists Could Sort By Any Key? 🔄

[Read the post](https://gerardorenteria.blog/2025/12/01/%f0%9f%95%90-remember-when-lists-could-sort-by-any-key-%f0%9f%94%84/) · Gerardo Renteria (Gerardo Renteria) · 2025-12-01 · 1180 words · tier community · reviewed (checked by Opus)

> A developer creates a solution to sort Business Central list pages by any predefined table key, not just single fields. The pattern uses temporary metadata storage, dynamic RecordRef reflection, and page extensions to offer flexible multi-field sorting that restores functionality from the NAV/C/SIDE era.

## Key points

- Tables in Business Central have predefined keys optimized for data retrieval; the solution leverages these keys to enable sorting by multiple fields in order.
- The architecture consists of a temporary table for metadata, a codeunit using RecordRef to read table keys, and a selection page that lets users choose which key to sort by.
- When a user selects a sort order, a new list window opens with the applied sorting, while the original remains unchanged.
- Page extensions add a 'Change Sort Order' action to any list page, making the feature reusable across tables like Customer and Sales Order.
- The solution includes example extensions and permission set configuration for integration into daily Business Central workflows.

## Quotes

- "Every BC table has predefined keys designed for optimal data retrieval and sorting." (Explains why leveraging table keys instead of arbitrary field combinations makes sense for performance and intentional sorting patterns.)
- "After selecting the desired key, a new customer list window will open with the additional key title." (Shows that the solution preserves the original view while opening a separate sorted view, allowing users to compare sort orders without losing context.)
