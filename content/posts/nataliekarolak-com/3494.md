# How to write good tooltips as a BC developer

[Read the post](https://nataliekarolak.wordpress.com/2025/08/04/how-to-write-good-tooltips-as-a-bc-developer/) · The BC Docs Librarian (Natalie Karolak, MVP) · 2025-08-04 · 1775 words · tier community · reviewed (checked by Opus)

> This guide teaches Business Central developers how to write effective tooltips for fields and actions by following patterns like starting with 'Specifies' for fields and imperative verbs for actions, keeping content under 200 characters, using sentence-style capitalization, and leveraging code analyzer rules to detect missing or non-compliant tooltips.

## Key points

- Define tooltips at table field level rather than page level to ensure consistency across all pages and simplify page code
- Field tooltips must begin with 'Specifies' followed by clear explanations of what data the field contains or how it is used
- Action tooltips should start with imperative verbs like 'View', 'Open', 'Calculate', or 'Update' depending on the action type
- Keep tooltips under 200 characters, avoid line breaks, use sentence-style capitalization, and always end with a period
- Use code analyzer rules like AA0218, AA0220, AC0015, AC0016, and AC0017 to detect missing or non-compliant tooltips

## Quotes

- "Rather provide no tooltip than one with no actual content, please!" (Emphasizes that unhelpful tooltips are worse than no tooltips, guiding developers away from empty rephrasing)
