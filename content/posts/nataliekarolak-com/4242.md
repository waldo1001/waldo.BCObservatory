# Still locking strings on table (field) removal?

[Read the post](https://nataliekarolak.wordpress.com/2026/07/02/still-locking-strings-on-table-field-removal/) · The BC Docs Librarian (Natalie Karolak, MVP) · 2026-07-02 · 335 words · tier community · **unreviewed** (model text not yet checked)

> When removing table fields in AL, translatable strings like Caption and OptionCaption used to require manual locking to avoid unnecessary translation work, but since April 2020 this is no longer needed because removed fields and tables are automatically excluded from translation files.

## Key points

- Previously, translatable properties on removed table fields had to be locked manually or with conditional directives to prevent them from being processed by translation workflows
- As of April 2020, Business Central automatically excludes translatable strings from removed tables and fields from translation files
- Labels in removed tables still require locking or deletion since they are not automatically excluded
- The AZ AL Dev Tools extension provided a command to lock removed table field captions, but manual locking is now unnecessary

## Quotes

- "You don't need to lock translatable strings since a BC + AL language update in April 2020" (This clarifies that a long-standing best practice became obsolete, saving developers time on manual locking work)
- "Labels placed somewhere in your removed table are still considered in the translation file until you lock or delete them." (Important exception showing that automatic exclusion does not apply to all translatable elements, requiring developers to still handle labels manually)
