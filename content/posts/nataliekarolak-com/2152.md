# BC docs and the DO_NOT_EDIT area

[Read the post](https://nataliekarolak.wordpress.com/2025/05/19/bc-docs-and-the-do_not_edit-area/) · The BC Docs Librarian (Natalie Karolak, MVP) · 2025-05-19 · 453 words · tier community · reviewed (checked by Opus)

> Explains how contributors opening pull requests against Business Central technical docs should treat sections enclosed in DO_NOT_EDIT comments. These parts of AL Language reference pages are autogenerated and refreshed periodically, so changes there cannot be merged. Add new content in later sections, or leave page feedback to report typos and errors.

## Key points

- AL Language reference documentation pages contain autogenerated content gathered from AL Language documentation that updates with each BC release
- DO_NOT_EDIT comments mark protected areas that should not be modified directly in pull requests
- Additional author-written content can be added below autogenerated sections in unprotected areas like Remarks or Example
- For typos or errors in DO_NOT_EDIT sections, leave feedback on the page instead of submitting a PR
- Understanding these restrictions prevents PRs from failing to merge and reduces work for Microsoft's technical writing team
