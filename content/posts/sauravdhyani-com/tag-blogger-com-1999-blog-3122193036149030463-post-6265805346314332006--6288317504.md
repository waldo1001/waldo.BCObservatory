# Business Central 29: How Many Fields Can a Table Really Have?

[Read the post](https://www.sauravdhyani.com/2026/09/business-central-29-how-many-fields-can.html) · Saurav Dhyani (Saurav Dhyani, MVP) · 2026-10-09 · 1856 words · tier community · **unreviewed** (model text not yet checked)

> Business Central 29 stores table-extension fields in the same database table as the base table instead of separate companion tables, making SQL column limits more relevant. The post investigates the practical field limit for tables, which Microsoft documents as 500 fields with an 8,060-byte record size, and explains how the new compiler warning helps developers detect tables approaching SQL extensibility limits.

## Key points

- BC 29 changed table-extension storage from companion tables to a single database table, combining base and extension fields together
- Field data type affects the practical limit because SQL Server enforces both column-count and record-size constraints, not just field count
- The new BC 29 compiler warning signals when tables approach SQL extensibility limits, serving as early detection before hard database blockers occur
- Developers must consider the combined field load from multiple extensions on a single table, not just their own extension's fields
- The 300-field limit often cited should not be treated as definitive; testing with different field types is needed to determine real practical limits
