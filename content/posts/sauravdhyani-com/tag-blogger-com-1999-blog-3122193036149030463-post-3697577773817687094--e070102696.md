# How to Migrate Business Central Table Fields from Integer to BigInteger.

[Read the post](https://www.sauravdhyani.com/2026/09/how-to-migrate-business-central-table.html) · Saurav Dhyani (Saurav Dhyani, MVP) · 2026-10-08 · 2364 words · tier community · **unreviewed** (model text not yet checked)

> Business Central version 29 enables developers to migrate table fields from Integer to BigInteger without data loss during upgrades when targeting runtime 18.0 or later. This addresses scenarios where record identifiers exceed the 32-bit integer limit, while requiring careful handling of dependent code that may face narrowing conversions.

## Key points

- Integer to BigInteger field migration is a non-destructive schema change supported only in runtime 18.0 and later.
- AppSourceCop rule AS0141 warns about potential breaking changes when BigInteger fields are narrowed to Integer, Option, or Enum types in dependent expressions.
- Developers must update dependent variables, fix compiler narrowing warnings, and validate CalcFormula assignments before publishing upgraded extensions.
- The feature solves long-standing problems with high-volume systems that accumulate millions of records and exceed the 32-bit integer maximum of 2,147,483,647.

## Quotes

- "Every valid Integer value is also a valid BigInteger value. The conversion is widening, not narrowing, so existing data is preserved." (This clarifies the technical foundation that makes the feature safe and non-destructive compared to other field type changes.)
- "A BigInteger value assigned to an Integer can overflow silently or throw a runtime error. Treat every warning as a potential bug." (This emphasizes the critical importance of addressing compiler warnings to prevent runtime failures in dependent code.)
