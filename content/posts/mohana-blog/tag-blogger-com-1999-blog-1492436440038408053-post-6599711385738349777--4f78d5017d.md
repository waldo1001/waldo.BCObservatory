# BC28.5 Upgrade: Fixing the OpenTelemetry Error in Invoke-NAVApplicationDatabaseConversion

[Read the post](http://mohana-dynamicsnav.blogspot.com/2026/11/bc285-upgrade-fixing-opentelemetry.html) · Mohana's Dynamics NAV & BC blog (Mohana Yadav) · 2026-11-27 · 225 words · tier community · **unreviewed** (model text not yet checked)

> During a Business Central 25 to 28.5 on-premises upgrade, the Invoke-NAVApplicationDatabaseConversion cmdlet fails with an OpenTelemetry error because PowerShell 5.1 cannot resolve newer .NET dependencies required by OpenTelemetry.Instrumentation.Http 1.16. Upgrading to PowerShell 7.6.6 or newer resolves the issue.

## Key points

- Invoke-NAVApplicationDatabaseConversion fails in PowerShell 5.1 with OpenTelemetry.Instrumentation.Http type initialization exception during BC upgrades
- The issue is a regression in BC 28.5 where OpenTelemetry.Instrumentation.Http was upgraded from 1.9 to 1.16, requiring newer .NET dependencies
- Binding redirects in Microsoft.Dynamics.Nav.Management.dll.config do not apply in PowerShell 5.1 because .NET Framework only reads the host's .exe.config
- The service tier runs fine; only admin cmdlets are affected
- Upgrading to PowerShell 7.6.6 or newer resolves the error

## Quotes

- ".NET Framework only reads the host's .exe.config, so inside powershell.exe or ISE they never apply." (Clarifies why binding redirects do not work in PowerShell 5.1 and identifies the technical limitation)
- "Update PowerShell 7 to PowerShell 7.6.6 or newer." (Provides the direct solution to resolve the OpenTelemetry error)
