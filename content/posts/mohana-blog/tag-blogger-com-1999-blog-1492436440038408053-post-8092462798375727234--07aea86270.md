# Building BcMCPProxy.exe and Connecting to Claude Desktop (BLOG 3 OF 4)

[Read the post](http://mohana-dynamicsnav.blogspot.com/2026/02/building-bcmcpproxyexe-and-connecting.html) · Mohana's Dynamics NAV & BC blog (Mohana Yadav) · 2026-02-11 · 829 words · tier community · **unreviewed** (machine-generated)

> Building and configuring BcMCPProxy.exe as a self-contained executable in Visual Studio, then connecting it to Claude Desktop via Azure App Registration for delegated authentication to Business Central. This enables Claude to interact with BC through the MCP protocol.

## Key points

- Create an Azure App Registration with delegated permissions for Dynamics 365 Business Central (Financials.ReadWrite.All and user_impersonation)
- Build BcMCPProxy.exe as a self-contained release using either Visual Studio UI or command line dotnet publish with --self-contained flag
- Configure Claude Desktop by editing claude_desktop_config.json with the BcMCPProxy.exe path and parameters including TenantId, ClientId, Environment, Company, and ConfigurationName
- Publish as a single file (~60-80 MB self-contained) and place in a permanent location like C:\Tools\BcMCPProxy\
- Authenticate via Azure AD on first Claude Desktop launch to enable BC MCP tools access

## Quotes

- "The BcMCPProxy uses delegated permissions - it authenticates as the signed-in user via Azure AD." (Clarifies the authentication model: the proxy acts as the user, not as a separate service principal, enabling proper user-level access to Business Central.)
- "On first launch, an Azure sign-in prompt will appear. Authenticate with a user from the same tenant." (Documents the expected user interaction flow and confirms that Claude Desktop will prompt for Azure credentials before tools become available.)
