# BC 29 lets a single index span base table and table extension fields

> Business Central 29 allows table extension keys to span both base table and extension fields in a single index, eliminating a long-standing constraint. This enables simpler indexing solutions for filtered lists, reporting extractions, and performance problems that previously required architectural workarounds.

[Read the post](http://mohana-dynamicsnav.blogspot.com/2026/09/bc-29-lets-single-index-span-base-table.html) · Mohana's Dynamics NAV & BC blog (Mohana Yadav) · 2026-09-07 · 1031 words · tier community · **unreviewed** (machine-generated)

## Key points

- Version 29 removes the restriction that keys must contain either all base table fields or all extension fields, but not both
- The change is enabled by storing all AL table fields in the same physical database table instead of separate companion tables
- Cross-boundary keys solve real performance problems like filtering on base table fields while sorting on extension fields
- Developers must still consider the 40-key-per-table limit and write performance costs when adding new indexes
- The capability is in public preview for online sandboxes only; on-premises guidance will follow general availability in October 2026

## Quotes

- "Every index costs writes. An index that makes one list fast makes every insert and modify on that table slower." (Critical caution for developers considering new cross-boundary indexes to avoid unforeseen performance degradation)
