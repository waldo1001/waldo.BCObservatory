# Managing Apps in the Business Central Admin Center

> The Manage Apps page in the Business Central admin center controls the stack of apps running on an environment, including the Base Application, Microsoft first-party apps, ISV apps, and per-tenant extensions. You can view, upload, install, update, or uninstall apps depending on their type, though new global apps must be sourced from the marketplace rather than installed directly.

[Read the post](http://mohana-dynamicsnav.blogspot.com/2026/09/managing-apps-in-business-central-admin.html) · Mohana's Dynamics NAV & BC blog (Mohana Yadav) · 2026-09-10 · 444 words · tier community · **unreviewed** (machine-generated)

## Key points

- BC environments consist of multiple app layers: Base Application, Microsoft apps, ISV apps, and per-tenant extensions that are all managed from the admin center
- Different app types have different capabilities: global apps can be updated or uninstalled but not installed locally; per-tenant extensions support full lifecycle management; dev extensions are view-only
- Per-tenant extension deployment has moved to the admin center with options for immediate or scheduled installation using either Add or Force Sync modes
- Extension Management in the client is being phased out, with PTE deployment moving entirely to the admin center or Admin Center API by 2027 release wave 1
- Always test uninstalls in a sandbox environment first and export database backups before deleting app data, as recovery requires point-in-time restore within 28 days

## Quotes

- "A BC environment is really a stack of apps: Base Application, Microsoft first-party apps, ISV apps, and your own per-tenant extensions." (Establishes the architectural layers that the admin center must manage, foundational to understanding app governance)
- "Extension Management is being phased out as an upload surface. Move PTE deployment to the admin center or the Admin Center API now." (Critical actionable warning about deprecated functionality that admins must address before 2027 to avoid disruption)
