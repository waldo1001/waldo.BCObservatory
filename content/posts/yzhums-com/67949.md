# Business Central 2025 wave 2 (BC27): Editable fields in page customizations

[Read the post](https://yzhums.com/67949/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-09-30 · 407 words · tier community · reviewed (checked by Opus)

> In BC27, page fields defined in page customizations can be made editable; before this they were always read-only. This needs runtime 16.0 or later, and the source table field must have AllowInCustomizations set to AsReadWrite. Standard fields default to ToBeClassified, so they cannot be made editable, and page extensions are not affected by this property.

## Key points

- Page customization fields can now be marked editable, where before they were always read-only
- Runtime 16.0 or later is required, and older runtimes give error AL0666
- The source field needs AllowInCustomizations set to AsReadWrite; ToBeClassified and Always behave like AsReadOnly and give error AL0808
- On table extensions the property applies only to fields declared in the extension, not to base table fields
- Page extensions are not controlled by this property

## Quotes

- "You can now make page fields defined in page customizations editable. Previously, such fields were always read-only." (This addresses a key limitation in page customizations that previously restricted all customization fields to read-only status.)

## Heads up

- gotcha: "Previously, such fields were always read-only, unlike fields declared in pages or page extensions." (about version BC27)
- gotcha: "This has limitations and you need to define the AllowInCustomizations property as AsReadWrite in the field properties in advance." (about version BC27)
- gotcha: "On table extensions, this only applies to fields declared in the table extension and does not affect the base table fields." (about version BC27)
