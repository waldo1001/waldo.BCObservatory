# Dynamics 365 Business Central: Make sure to generate the permission set file before installing your extension

[Read the post](https://yzhums.com/69809/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-01-08 · 428 words · tier community · **unreviewed** (model text not yet checked)

> Permission set files must be generated for AL extensions so non-Super users can access customized pages and reports. Without a permission set, only Super users see new objects, and production deployments will fail validation if permissions are missing.

## Key points

- Generate permission set files explicitly using AL commands; they do not update automatically when new objects are added
- UsageCategory and ApplicationArea properties alone are insufficient; a permission set must be included with extensions
- Production environments enforce permission set requirements and block extension installation if permissions are missing
- Code Analysis with PerTenantExtensionCop analyzer can detect missing permission sets during development

## Quotes

- "If you don't include a permission set with your extension, only users with the SUPER permission set will be able to use the extension." (Explains the root cause of why non-Super users cannot access customized features without explicit permissions)
- "Please make sure that the permission file has been generated." (The core directive for developers to resolve the issue of limited feature visibility)
- "This file will not update automatically. If you add new objects, please update this file using the same command." (Critical to understand that permission sets require manual updates when extensions are modified)
