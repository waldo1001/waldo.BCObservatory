# Business Central 2026 release wave 2 (BC29): Control transaction isolation for queries and isolated storage (Query ReadState supports ReadCommitted)

[Read the post](https://yzhums.com/76233/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-09-21 · 497 words · tier community · reviewed (checked by Opus)

> BC29 lets AL queries set ReadState to ReadCommitted so they read only committed data, and it adds isolation level choice for isolated storage reads, including row locking for safer read-modify-write work. This extends to queries what the ReadIsolation method gave Records in BC22.

## Key points

- Query ReadState options are ReadUncommitted (default), ReadCommitted, ReadExclusive and ReadShared
- ReadCommitted reads committed data only, but rows may change during the transaction
- ReadExclusive places update locks and ReadShared places share locks on rows read, blocking changes by other transactions
- ReadUncommitted allows dirty reads but can perform better than the locking modes
- Mirrors the Record ReadIsolation method introduced in BC22

## Quotes

- "ReadCommitted: Reads only data that has been committed to the database. Rows read are not guaranteed to remain consistent throughout the current transaction." (Explains the trade-off between consistency and performance with the new ReadCommitted isolation level)
- "Setting the property to ReadUncommitted can improve performance compared to ReadShared and ReadExclusive." (Highlights the performance implications developers should consider when choosing isolation levels)
