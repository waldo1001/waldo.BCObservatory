# Business Central 2026 release wave 2 (BC29): Control transaction isolation for queries and isolated storage (Query ReadState supports ReadCommitted)

[Read the post](https://yzhums.com/76233/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-09-21 · 497 words · tier community · **unreviewed** (model text not yet checked)

> Query ReadState now supports ReadCommitted isolation levels in Business Central 2026 wave 2 (BC29), allowing AL queries to read only committed data and apply row locks for safer read-modify-write operations with configurable transaction isolation modes.

## Key points

- Queries can now use ReadState with four isolation levels: ReadUncommitted (default), ReadCommitted, ReadExclusive, and ReadShared
- ReadCommitted reads only committed data without row consistency guarantees, improving performance over locked read modes
- ReadExclusive and ReadShared place update or share locks on read data to prevent modification by other transactions
- This feature brings query functionality in line with the ReadIsolation method introduced for Records in BC22

## Quotes

- "ReadCommitted: Reads only data that has been committed to the database. Rows read are not guaranteed to remain consistent throughout the current transaction." (Explains the trade-off between consistency and performance with the new ReadCommitted isolation level)
- "Setting the property to ReadUncommitted can improve performance compared to ReadShared and ReadExclusive." (Highlights the performance implications developers should consider when choosing isolation levels)
