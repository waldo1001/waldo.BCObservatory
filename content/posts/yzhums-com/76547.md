# Business Central 2026 release wave 2 (BC29): Evolve AL interfaces with default implementations (Default interface method implementations)

[Read the post](https://yzhums.com/76547/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-10-26 · 908 words · tier community · reviewed (checked by Opus)

> Default interface method implementations in BC29 allow interfaces to include method bodies so existing implementors can omit them and inherit default behavior or override them. This feature, requiring runtime 18.0 or later, lets extension publishers add behavior without forcing immediate changes to implementing extensions, with RequiredPending and AppSourceCop rules supporting a managed transition path.

## Key points

- Interfaces can now have method bodies serving as default implementations that codeunits can inherit or override
- The RequiredPending attribute marks default methods as becoming required in future versions, with compiler warnings to guide developers
- AppSourceCop rules AS0148 and AS0149 enforce safe transitions by flagging removed defaults without prior RequiredPending marking and runtime identifier changes
- Default methods dispatch through interface variables only; calling them on codeunit variables directly will fail
- Feature requires runtime version 18.0 or later, introduced in BC29 (2026 wave 2)

## Quotes

- "Default methods are dispatched through the interface variable, not inherited by the implementing codeunit's public API." (This clarifies an important implementation detail that developers must understand to avoid runtime errors when calling default methods)
- "Extension publishers can add behavior to an interface without immediately requiring every implementing extension to change." (This is the business value that enables managed API upgrades and reduces disruption to dependent developers in the extension ecosystem)
