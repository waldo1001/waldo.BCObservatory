# Business Central 2026 release wave 2 (BC29): Detect tables approaching SQL column limits (New warning)

[Read the post](https://yzhums.com/76053/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-09-14 · 560 words · tier community · reviewed (checked by Opus)

> Business Central 2026 release wave 2 introduces compiler warnings (AL0914 and AL0915) to alert developers when tables or table extensions contain many fields that approach SQL column limits, helping prevent extensibility issues before deployment fails. The warning triggers when a table exceeds 294 normal fields (plus 6 system fields) or when a table extension adds many fields to an existing table.

## Key points

- New compiler warnings flag tables (AL0914) and table extensions (AL0915) that declare a large number of normal fields
- Business Central allows up to 1,018 fields per table because the platform adds 6 system fields to every table
- The author's test shows the table warning starts at roughly 300 fields in total, meaning about 294 normal fields plus the 6 system fields
- For table extensions the trigger count is different, because the base table's standard fields also count
- The deployment error now lists how many fields each source app adds when the column limit is exceeded

## Quotes

- "Receive compiler warnings when tables or table extensions contain many normal fields, helping identify data models that are approaching SQL extensibility limits." (This explains the core purpose of the feature: preventing developers from creating data models that limit other extensions from adding fields.)
- "The answer is 300 - excluding the 6 system fields, exceeding 294 normal fields will trigger it." (Provides the exact threshold where the warning activates, which is essential practical information for developers designing tables.)
