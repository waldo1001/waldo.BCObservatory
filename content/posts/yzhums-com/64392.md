# Using OAuth 2.0 to connect Dataverse tables (APIs) in Postman (Using Grant type: Client Credentials, not Implicit) – Get, Patch, Post and Delete

[Read the post](https://yzhums.com/64392/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-06-03 · 1262 words · tier community · **unreviewed** (model text not yet checked)

> This post explains how to use OAuth 2.0 with Client Credentials grant type to authenticate and interact with Dataverse APIs via Postman. It covers app registration setup, configuration of API permissions, adding the app to Power Platform environments, and performing CRUD operations (Get, Patch, Post, Delete) on Dataverse tables.

## Key points

- OAuth 2.0 Client Credentials is a simpler alternative to Implicit Grant Type for accessing Dataverse APIs
- App registration requires API permissions including user_impersonation, and the app must be added as an application user in Power Platform Admin Center
- Dataverse tables are accessible directly via Web API endpoints without requiring special API pages or Web Service publishing
- CRUD operations use standard HTTP methods with the Dataverse Web API endpoint, supporting query parameters like $select and $filter

## Quotes

- "Unlike Business Central, tables (entities) in Dataverse are accessible by default, without the need for special API pages or publishing to Web Services." (Key difference that simplifies API access to Dataverse compared to Business Central API setup)
