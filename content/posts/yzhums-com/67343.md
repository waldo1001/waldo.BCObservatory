# Business Central 2025 wave 2 (BC27): Truncating table data with new AL method (procedure Truncate)

[Read the post](https://yzhums.com/67343/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-09-04 · 560 words · tier community · **unreviewed** (model text not yet checked)

> Business Central 2025 Wave 2 introduces the new Rec.Truncate AL method for efficiently deleting large volumes of table data in a single operation. This method improves performance over row-by-row DeleteAll operations by locking the table during the transaction, with configurable AutoIncrement behavior and delete permission checks, though it has several limitations including incompatibility with temporary tables, try functions, security filters, and tables with media fields.

## Key points

- Truncate method deletes all matching records in a table efficiently by locking the table until the transaction commits, significantly faster than DeleteAll for bulk operations
- Supports parameters to check truncation support and control whether AutoIncrement fields reset to 0 or retain previous values
- Not supported for temporary tables, system tables, tables with OnBefore/OnAfterDelete event subscriptions, security filters, media fields, flow fields, or when used within try functions
- When used with filters, the method copies data to a temporary table first, creating overhead - use only when deleting a significant portion of table rows

## Quotes

- "The new Rec.Truncate method in AL provides a powerful and efficient way to delete large volumes of data from a table." (Establishes the core value proposition of the feature for bulk data cleanup operations)
- "Truncate with a filter should only be used when the majority of the table is being deleted, as otherwise DeleteAll will be more efficient." (Critical guidance for developers on when to apply this method to avoid performance degradation with filters)
- "Truncate allows for less concurrency than DeleteAll, as the entire table will be locked until the transaction is committed." (Important trade-off consideration showing the performance benefit comes at the cost of table-level locking)
