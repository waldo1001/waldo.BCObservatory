# Business Central 2026 release wave 2 (BC29): Retained DEV extensions (DEV extensions remain installed during environment update)

[Read the post](https://yzhums.com/76570/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-10-08 · 515 words · tier community · **unreviewed** (model text not yet checked)

> Business Central 2026 wave 2 (BC29) now retains DEV extensions during environment updates instead of removing them, eliminating the need to republish extensions after upgrades. This change simplifies development and testing workflows for developers and consultants.

## Key points

- DEV extensions (published from Visual Studio Code) previously were removed during environment updates or relocations; BC29 changes this behavior
- DEV extensions now persist after updates, similar to globally scoped Tenant Published Extensions (PTEs), reducing manual republishing work
- Extension scopes include Global (Marketplace/AppSource), PTE (Tenant scope uploaded via admin center), and Dev (VS Code published)
- Data from DEV extensions was never lost during updates, but the extensions themselves had to be reinstalled after UAT or client verification

## Quotes

- "Dev extensions will now behave like PTEs and won't be uninstalled after an update." (This is the core feature change that eliminates the hassle of reinstalling DEV extensions during environment updates.)
- "Extensions that have been published from Visual Studio Code are removed when the environment is updated or relocated within our service." (This explains the previous behavior that BC29 now addresses, showing why the change is a significant improvement.)
- "It can be a hassle, especially during UAT or client verification when the feature suddenly disappears the next day." (Illustrates the practical pain point that this feature eliminates for developers and consultants during testing cycles.)
