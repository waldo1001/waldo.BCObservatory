# Dynamics 365 Business Central: Regarding the issue where the Source Currency Amount in G/L Entry differs from the pre-posting Amount in BC27

[Read the post](https://yzhums.com/69290/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-12-03 · 652 words · tier community · reviewed (checked by Opus)

> When posting general journal lines with foreign currencies in BC27, the Source Currency Amount field in G/L Entry is recalculated from the LCY amount using the exchange rate, resulting in a value that differs from the original journal amount. This occurs because the posting logic recalculates the source currency amount instead of using the amount directly from the journal line.

## Key points

- In BC24, the G/L Revaluation feature added the Source Currency Code and Source Currency Amount fields to the G/L Entry table
- In BC27, posting recalculates Source Currency Amount from the LCY amount and the exchange rate instead of taking the journal line Amount
- Because of rounding, the recalculated value can differ from the journal amount (in the JPY test, 20,008.00 became 20,008.61)
- Possible workaround: subscribe to OnBeforeInsertGLEntryBuffer in Gen. Jnl.-Post Line and set Source Currency Amount to the journal Amount (only lightly tested)
- Vendor Ledger Entry and Detailed Vendor Ledger Entry amounts are not affected

## Quotes

- "the Source Currency Amount does not match the amount before posting" (Identifies the core issue: posted amounts differ from what users entered, affecting financial record accuracy)
- "I'm not sure if this is by design or a bug" (Highlights uncertainty about whether this behavior is intentional or an issue, important for understanding whether a fix is needed)
