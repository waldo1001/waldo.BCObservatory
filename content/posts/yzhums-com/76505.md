# Business Central 2026 release wave 2 (BC29): Faster data loading with improved data model for table extensions (all fields on an AL table are stored in the same table)

[Read the post](https://yzhums.com/76505/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-10-06 · 505 words · tier community · reviewed (checked by Opus)

> Business Central 2026 wave 2 (BC29) consolidates all table extension fields into a single physical database table instead of companion tables, eliminating SQL JOINs and improving database operation performance across the system.

## Key points

- BC23 put all extension fields into one companion table ($ext) per base table, so queries needed at most one SQL join.
- In BC29 the companion table is gone. Fields from table extensions are stored in the base table itself, so no joins are needed.
- Adding more table extensions adds columns, not tables. The columns keep the FieldName$ExtensionID naming.
- The AL table model does not change, so extension publishers do not need to change any code.

## Quotes

- "No matter how many extensions and table extensions you have, in the actual database, there will always be only one table." (Clarifies the fundamental architectural change and its scalability advantage)
- "This change does not impact the table model as seen from the AL language, so no code changes are needed from extension/app publishers." (Key insight that backward compatibility is maintained despite significant internal changes)
