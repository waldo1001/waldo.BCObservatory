# How to connect to Dynamics 365 Business Central On-Premises in VS Code (Use the On-Premises version for customization)

[Read the post](https://yzhums.com/64148/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-08-08 · 1048 words · tier community · reviewed (checked by Opus)

> This post explains how to configure VS Code to connect to a Business Central On-Premises environment for AL development. It covers modifying the launch.json file with correct server settings, enabling Developer Services in the BC instance configuration, and verifying authentication methods.

## Key points

- Replace the default server and serverInstance in launch.json with the URL and instance name seen when opening the on-premises web client, or check them via Get-NAVServerInstance
- Look up DeveloperServicesPort in CustomSettings.config and add it as the port in launch.json; set DeveloperServicesEnabled to true, or use Set-NAVServerConfiguration
- Restart the server instance after changing settings and make sure launch.json uses the right authentication, usually Windows on-premises
- Do not build SaaS extensions against on-premises since some methods available on-premises are not usable in the cloud
- From 2023 wave 1 the CRONUS demo license grants RIMDX on all objects, allowing AppSource apps to be run on-premises for testing

## Heads up

- warning: "You should not use the On-Premises version to customize extensions for Cloud (SaaS)."
- gotcha: "Setting the "server" to http://localhost:8080/ can also connect to the environment, but it will affect the URL opened during debugging."

- Features: Developer Services configuration, launch.json setup, On-Premises connectivity, Windows authentication, Snapshot Debugger, CRONUS demo license RIMDX permissions
