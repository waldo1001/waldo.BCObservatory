# How to connect to Dynamics 365 Business Central On-Premises in VS Code (Use the On-Premises version for customization)

[Read the post](https://yzhums.com/64148/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-08-08 · 1048 words · tier community · **unreviewed** (model text not yet checked)

> This post explains how to configure VS Code to connect to a Business Central On-Premises environment for AL development. It covers modifying the launch.json file with correct server settings, enabling Developer Services in the BC instance configuration, and verifying authentication methods.

## Key points

- Update launch.json with the actual On-Premises server URL and instance name from the BC web interface or PowerShell commands
- Enable DeveloperServicesEnabled and configure the DeveloperServicesPort in CustomSettings.config or using Set-NAVServerConfiguration
- Verify your authentication method (Windows is typical for On-Premises) and confirm it matches the launch.json configuration
- Avoid using On-Premises environments for SaaS extension development as available methods differ between the two versions
- The CRONUS demo license now includes RIMDX permissions on all objects, enabling partners to test with AppSource apps in on-premises environments

- Features: Developer Services configuration, launch.json setup, On-Premises connectivity, Windows authentication, Snapshot Debugger, CRONUS demo license RIMDX permissions
