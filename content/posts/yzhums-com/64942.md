# Dynamics 365 Business Central: How to set a condition on a breakpoint in debugging (Conditional breakpoints)

[Read the post](https://yzhums.com/64942/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-11-06 · 698 words · tier community · **unreviewed** (model text not yet checked)

> Conditional breakpoints allow developers to pause code execution only when specified conditions are met during AL debugging in Business Central. This feature lets you filter breakpoints by variable or field values, reducing unnecessary pauses and focusing debugging efforts on specific scenarios.

## Key points

- Set conditional breakpoints by right-clicking the code margin and selecting Add Conditional Breakpoint, or edit existing breakpoints to add conditions
- Conditions use comparison operators and can evaluate multiple criteria with AND/OR logic, supporting simple types like Text, Integer, and complex types like Array and Record starting in version 26
- Only trigger breakpoints when conditions are true, such as when a specific record number is accessed, avoiding constant stops during irrelevant code flow
- Supported operators include equality, comparison (<, >, <=, >=), logical operators (AND, OR, NOT), and numeric negation

## Quotes

- "If the condition evaluates as true, then code execution breaks at the breakpoint. If the condition is false, then code execution continues." (Clarifies the fundamental behavior of conditional breakpoints and how they filter execution pauses based on true/false evaluation.)
- "The condition can include any variables or fields that are currently in scope." (Defines the scope of what can be used in conditions, showing flexibility in debugging complex scenarios with multiple variables and fields.)
