# Dynamics 365 Business Central: Integrate with Microsoft Dataverse via APIs (Not using the standard Dataverse connector)

[Read the post](https://yzhums.com/64775/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-06-04 · 993 words · tier community · **unreviewed** (model text not yet checked)

> This post demonstrates how to integrate Dynamics 365 Business Central with Microsoft Dataverse using direct REST APIs instead of the standard connector. It provides step-by-step guidance on authenticating with OAuth 2.0 and implementing GET, POST, PATCH, and DELETE operations to synchronize data between Business Central and Dataverse tables.

## Key points

- Use OAuth 2.0 with Client Credentials grant type to authenticate with Dataverse APIs before performing any operations
- Create custom tables in Business Central to store Dataverse data, using Guid fields as primary keys for proper association
- Implement CRUD operations (Get, Insert, Update, Delete) using specific API endpoints and handling response headers like Prefer: return=representation
- This approach doesn't require Dataverse licenses but requires custom development for each synchronized table

## Quotes

- "Using this way, users do not need a Dataverse license and can achieve real-time synchronization." (This is the main advantage of this approach over standard connectors, making it cost-effective for organizations that need Dataverse integration without additional licensing.)
- "This requires setting the DelayedInsert property of the page to true" (This technical detail is critical to ensure the Guid returned from Dataverse can be used as a primary key when inserting data into Business Central.)
- "The disadvantage is that each synchronized table needs to be customized." (This acknowledges the trade-off of using direct APIs versus standard connectors, helping developers make informed decisions about which approach suits their needs.)
