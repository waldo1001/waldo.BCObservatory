# Dynamics 365 Business Central: Regarding the default field name/table name in the error message thrown by Record.TestField Method

[Read the post](https://yzhums.com/66277/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-07-31 · 425 words · tier community · **unreviewed** (model text not yet checked)

> The Record.TestField Method in Business Central automatically generates error messages when field validation fails, but customizing field or table captions through TableExtension will affect these error messages. PageExtension modifications do not affect TestField error messages since the method uses standard table and field captions.

## Key points

- Record.TestField Method validates that a field is not empty or zero and automatically generates user-friendly error messages without custom code.
- TableExtension modifications to field or table captions are reflected in TestField error messages, potentially affecting standard error display.
- PageExtension modifications to captions do not affect TestField error messages because the method uses standard captions from the table definition.
- When calling TestField without an ErrorInfo object, Business Central automatically creates navigation links to relevant card pages for error correction.
- Navigation links are not generated if the error occurs on the currently open page or if the user lacks permissions to modify the record.

## Quotes

- "Record.TestField(Any) Method: Tests that the content of the field is not zero or blank (empty string)." (Explains the core validation functionality that developers rely on for field validation without custom error code.)
- "If you use TableExtension to modify the captions of tables and fields, it will also affect the Record.TestField Method." (Critical distinction showing that TableExtension changes impact standard error messages, unlike PageExtension modifications.)
