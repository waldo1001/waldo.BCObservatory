# Business Central 2026 release wave 2 (BC29): Migrate table fields from Integer to BigInteger (Support for BigInteger field migration)

[Read the post](https://yzhums.com/76388/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-10-01 · 433 words · tier community · **unreviewed** (model text not yet checked)

> Business Central 2026 wave 2 (BC29) supports migrating table fields from Integer to BigInteger data types with compiler warnings for dependent expressions that may overflow. Conversion from Integer to BigInteger is allowed without data loss, but reverse conversion is not permitted.

## Key points

- Integer to BigInteger field migration is supported in runtime 18.0 (Fall 2026) or later
- BigInteger stores values from -9,223,372,036,854,775,807 to 9,223,372,036,854,775,807 while Integer ranges from -2,147,483,647 to 2,147,483,647
- AppSourceCop rule AS0141 warns about consequences for dependent extensions referencing changed fields
- Compiler emits warnings for narrowing conversions (BigInteger to Integer) in property contexts to alert about potential overflow
- Reverse conversion from BigInteger to Integer is not allowed and causes an error

## Quotes

- "Changing an existing table field from Integer to BigInteger is now supported when targeting runtime version 18.0 (Fall 2026) or later." (Clarifies which runtime versions support the new feature, essential for developers planning migrations)
- "Converting BigInteger to Integer will cause an error." (Critical constraint showing the one-way nature of migration, preventing unexpected failures)
