# Dynamics 365 Business Central: How to restrict certain tables from importing data through Configuration Package

[Read the post](https://yzhums.com/64265/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-07-18 · 454 words · tier community · reviewed (checked by Opus)

> Configuration Packages can import data into Business Central, but posted tables, entry tables, and system tables are blocked by default. To restrict additional tables from being imported, you can use customization with the OnAfterIsSystemTable event in a codeunit to mark unwanted tables as system tables and prevent users from importing them.

## Key points

- Posted and entry tables like G/L Entry cannot be inserted, modified, or deleted through Configuration Package
- System tables cannot be imported or exported through Configuration Package
- Security Filters alone cannot prevent access to system tables with InherentPermissions Property set
- The OnAfterIsSystemTable event allows custom marking of tables as system tables to block import access
- You can create a configuration table to manage prohibited tables or add user-level controls for granular restriction

## Quotes

- "For posted tables and entry tables, we cannot insert, modify, or delete them through the Configuration Package." (Explains the built-in restriction that protects transactional data from accidental modification during import)
- "So we can only do it through customization, there are many ways. I will mainly introduce one that uses a standard event, OnAfterIsSystemTable." (Identifies the recommended approach for extending table restrictions beyond built-in limitations)
