# Business Central 2026 release wave 1 (BC28): Download Symbols from Global NuGet Sources (without any environment)

[Read the post](https://yzhums.com/70782/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2026-02-24 · 742 words · tier community · reviewed (checked by Opus)

> Business Central 2026 wave 1 introduces a new AL command to download symbol files directly from Microsoft's public NuGet feeds without needing a running environment, supporting country/region-specific packages and custom feeds through VS Code settings.

## Key points

- A symbol file acts as the source code of an extension, letting an AL project reference tables, pages and codeunits from the base app or other extensions
- The new AL: Download Symbols from Global Sources command gets app packages from Microsoft's public NuGet feeds, so no Docker container or sandbox is needed
- al.symbolsCountryRegion sets the localization using two-letter ISO codes such as us or de, or w1 for worldwide; if it is not set, you are prompted during the download
- Custom public NuGet v3 feeds without authentication can be added, and al.useOnlyCustomFeeds limits downloads to those feeds
- The version to download is controlled by the application property in app.json

## Quotes

- "Previously, you had to have a running Docker container or a Sandbox environment just to click Download Symbols and start coding." (Explains the key problem solved by this feature - eliminating environment dependencies for symbol downloads)
- "A symbol file is essentially the source code for an extension." (Clarifies what symbols are and why developers need them when building AL projects)
- "Country/region codes must follow ISO 3166-1 alpha-2 or w1 for worldwide." (Specifies the exact format required for symbol localization configuration)
