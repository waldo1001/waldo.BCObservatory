# Dynamics 365 Business Central: How to quickly check if a field is a primary key field

[Read the post](https://yzhums.com/64478/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-11-28 · 498 words · tier community · reviewed (checked by Opus)

> Explains how to check in AL whether a field belongs to a table's primary key. Besides reading the Key virtual table, you can copy two local procedures from codeunit 9800 User. They use RecordRef and KeyRef to read the first key, report the number of primary key fields, and return whether the field is one of them.

## Key points

- Each table has exactly one primary key, defined only on table objects; any key defined in a table extension is a secondary key
- Secondary keys create SQL indexes and can be defined in both tables and table extensions
- Table 2000000063 Key can be used to check key fields, but codeunit 9800 User contains reusable helper procedures
- IsPrimaryKeyField opens the table with RecordRef, reads KeyIndex(1) and returns true if the field is in it, plus the count of primary key fields
- A test page extension on Customer List checks the No. field of Sales Header

## Quotes

- "Every table has a primary key, and there can only be one primary key per table. Primary keys are defined on table objects only." (Establishes the fundamental constraint that guides how developers structure table definitions and extensions)
