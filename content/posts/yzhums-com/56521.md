# Dynamics 365 Business Central: How to hide/disable New, Edit (Edit List), and Delete actions on the page

[Read the post](https://yzhums.com/56521/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-08-22 · 965 words · tier community · reviewed (checked by Opus)

> This post explains two methods to hide or disable the New, Edit (Edit List), and Delete actions in Business Central pages: using permission sets to exclude Insert, Modify, and Delete permissions, or setting the InsertAllowed, ModifyAllowed, and DeleteAllowed properties (available in BC25 wave 2 for page extensions).

## Key points

- New, Edit (Edit List) and Delete are not defined in AL code; they map to Insert, Modify and Delete permissions on Table Data
- Excluding those permissions in a permission set grays the actions out on list and card pages, but the New action in drop-down lists stays visible and raises a permission error when clicked
- Setting InsertAllowed, ModifyAllowed and DeleteAllowed to false removes the actions; before BC25 (runtime 13) this only worked on custom pages, and from runtime 14 page extensions can change them on standard pages
- For a list page with a card page, change the card page; for a list without a card page, change the list itself; for drop-down lists, change the page that opens when New is clicked
- These properties cannot be set from variables, so the author suggests using profiles to give different users different behavior

## Quotes

- "From Business Central 2024 wave 2 (BC25), we can modify these three properties in pageextension." (This marks a significant capability change that enables hiding these actions on standard pages without custom code on the page itself)
