# Dynamics 365 Business Central: How to hide/disable New, Edit (Edit List), and Delete actions on the page

[Read the post](https://yzhums.com/56521/) · Dynamics 365 Lab - Yun Zhu (Yun Zhu, MVP) · 2025-08-22 · 965 words · tier community · **unreviewed** (model text not yet checked)

> This post explains two methods to hide or disable the New, Edit (Edit List), and Delete actions in Business Central pages: using permission sets to exclude Insert, Modify, and Delete permissions, or setting the InsertAllowed, ModifyAllowed, and DeleteAllowed properties (available in BC25 wave 2 for page extensions).

## Key points

- Special actions like New, Edit, and Delete are not defined in AL code but correspond directly to Insert, Modify, and Delete permissions in Table Data
- Permission exclusion hides actions by graying them out for list pages, but errors occur when users click grayed-out actions in dropdown lists
- InsertAllowed, ModifyAllowed, and DeleteAllowed properties can hide these actions completely on custom pages and from BC25 on standard pages via extensions
- For list pages with card pages, restrict the card page properties; for list pages without card pages, modify the list page directly
- Dropdown list restrictions require identifying which card page opens and modifying its properties instead

## Quotes

- "These three actions correspond to the following three permissions of Table Data: New: Insert Permission, Edit (Edit List): Modify Permission, Delete: Delete Permission." (It explains the fundamental mapping between UI actions and permission system, essential for understanding both control methods)
- "From Business Central 2024 wave 2 (BC25), we can modify these three properties in pageextension." (This marks a significant capability change that enables hiding these actions on standard pages without custom code on the page itself)
