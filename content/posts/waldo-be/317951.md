# Obsoleted and “no longer invoked” events in v26 Business Central

> Business Central v26 removed invocation of 82 obsoleted events from the legacy invoice posting system while keeping them in the codebase for backward compatibility. Code subscribing to these non-invoked events will compile and publish but fail silently at runtime, creating a hidden risk for developers upgrading from earlier versions.

[Read the post](https://waldo.be/2025/06/30/obsoleted-and-no-longer-invoked-events-in-v26-business-central/) · waldo's blog (waldo (Eric Wauters), MVP) · 2025-06-30 · 1254 words · tier community · **unreviewed** (machine-generated)

## Key points

- The Extensible Invoice Posting Engine replaced the Invoice Post. Buffer system starting in v19, with v26 marking the end of the legacy events
- 82 events remain in code but are no longer invoked in v26, allowing apps to compile across versions but potentially failing at runtime
- Microsoft removed the validation check that previously prevented publishing apps subscribed to obsoleted events
- Developers should implement their own validation checks during upgrades to catch dependencies on non-invoked events before production issues occur
- Supporting multiple versions of an app across different BC releases without multiple AppSource versions creates this compatibility challenge
