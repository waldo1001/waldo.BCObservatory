# Troubleshooting Series – Ep5 – Telemetry

> Telemetry is essential for troubleshooting Business Central SaaS because it provides evidence about when issues occur, their frequency, affected customers, and performance metrics without SQL access or profilers. The post covers two telemetry channels (environment-level and app/extension-level), Microsoft-provided tools like Power BI apps and Azure Data Explorer, and the BC Telemetry Buddy tool that makes querying telemetry easier through AI assistance.

## Key points

- Telemetry enables data-driven troubleshooting by answering key questions about performance issues, errors, and user impact instead of relying on guesses
- Two telemetry channels exist: environment-level (configured in Admin Center) for platform events and app-level (via Application Insights) for extension-specific data
- Microsoft provides ready-made tools including Power BI telemetry apps, Azure Data Explorer for ad-hoc querying, KQL query samples, and structured Telemetry Event ID reference lists
- Additional logging feature provides 15 minutes of verbose telemetry including all SQL queries, functioning like a temporary SaaS SQL Profiler
- BC Telemetry Buddy MCP makes telemetry analysis accessible by generating KQL queries from natural language questions without requiring KQL expertise

## Quotes

- "Troubleshooting Business Central SaaS without telemetry is like debugging with your eyes closed." (Establishes why telemetry is critical for SaaS troubleshooting when direct access to systems is unavailable)
