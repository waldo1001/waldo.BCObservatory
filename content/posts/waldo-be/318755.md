# Agent Maron & waldo: Mission AL Runner

[Read the post](https://waldo.be/2026/11/11/agent-maron-waldo-mission-al-runner/) · waldo's blog (waldo (Eric Wauters), MVP) · 2026-11-11 · 2500 words · tier community · reviewed (checked by Opus)

> Stefan Maron's AL Runner executes AL code tests outside Business Central using Rust and an in-memory database, reducing test suite runtime from 4 hours 20 minutes to 4 minutes 24 seconds. The post chronicles how two AI agents - one operated by the author, one by Stefan - collaboratively debugged the runner against a real-world ISV test suite of 10,578 tests over one week, maintaining absolute fidelity with zero false passes.

## Key points

- AL Runner is a Rust-based test executor that runs AL tests without Docker, SQL Server, or BC service tier, using an in-memory database
- The runner's core principle is 'Refuse. Never guess' - it reports tests as not run rather than produce false passes
- Two AI agents coordinated continuously over one week, with the author's agent running tests every 10 minutes, comparing results, and reporting findings while Stefan's agents diagnosed and fixed issues
- Test performance improved from 58.1% passing to 94.6% in one week, with zero false passes maintained throughout
- The author established rules for agent autonomy including code change restrictions, no customer data exposure, and automatic memory monitoring to prevent crashes

## Quotes

- "Not a single test passed on the AL Runner that failed on BC. The runner might not know everything yet. But it didn't lie." (Demonstrates trustworthiness is built through consistency and honesty, not speed alone)
- "From 4 hours and 20 minutes, to 4 and a half minutes. With 94.6% of the suite running. In one week." (Shows dramatic performance improvement achieved through collaborative agent-driven debugging)
