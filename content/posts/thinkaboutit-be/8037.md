# Quick Tip: Runtime Version and Business Central Version Are Not the Same Thing

> Runtime version in app.json determines which AL language features are available and controls compatibility with platform versions. Developers often confuse runtime version with platform (internal) version or release wave name, but only runtime version matters for code compilation and customer system requirements.

[Read the post](https://thinkaboutit.be/2026/07/quick-tip-runtime-version-and-business-central-version-are-not-the-same-thing/) · think about IT - Steven Renders (Steven Renders) · 2026-07-24 · 646 words · tier community · **unreviewed** (machine-generated)

## Key points

- Runtime version is set in app.json and controls AL language features available; platform version is the actual service build shown in admin center
- Runtime version must be same or later than target environments support; extensions publish only to environments with equal or newer runtimes
- Setting runtime too low causes missing features; too high requires newer platform versions customers may not have reached
- Omitting the runtime property defaults to latest major version supported by VS Code, which changes with tool updates
- Lower runtime is preferred when serving customers on staggered update schedules to avoid blocking installation

## Quotes

- "An extension publishes only to environments running the same runtime or a later one, never an earlier one." (Establishes the core compatibility rule that runtime version is a forward-only contract between extensions and platforms)
- "Treat runtime version as a compatibility contract you actively manage, not a field VS Code fills in for you." (Emphasizes that developers must consciously choose runtime based on business requirements, not rely on tooling defaults)
