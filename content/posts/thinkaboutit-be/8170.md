# Plan, Custom Agents, and Session Target: What Actually Changed in Copilot Chat

[Read the post](https://thinkaboutit.be/2026/09/plan-custom-agents-and-session-target-what-actually-changed-in-copilot-chat/) · think about IT - Steven Renders (Steven Renders) · 2026-09-17 · 916 words · tier community · reviewed (checked by Opus)

> VS Code reorganised Copilot Chat by converting modes to agent roles, promoting Plan from preview to a built-in role alongside Agent and Ask. The new Session Target control lets you choose which harness runs your session (Local, Copilot, Claude, Codex, or Cloud), separate from model choice. Custom chat modes now use .agent.md files with configurable tool access and instructions per agent.

## Key points

- Plan is now a proper role that reads workspace context, creates structured implementation plans without editing files, and offers handoff to Agent for execution.
- Custom agents replace .chatmode.md files with .agent.md format, allowing per-agent tool access, instructions, and optional model selection.
- Session Target separates harness choice from model choice, enabling handoffs between Local, Copilot, Claude, Codex, and Cloud without losing conversation history.
- For AL work, Copilot or Local harnesses are recommended as they understand Business Central workspace context and AL language; Claude and Codex lack AL awareness.
- Planning agents can be configured with read-only tools to review code against a quality bar without touching files, useful for paired reviewer personas.

## Quotes

- "Plan reads your workspace, gathers context, and writes a structured implementation plan. It does not touch a single file while doing this." (Explains the core value of Plan mode: gathering context and creating structured plans before any code changes occur, reducing AL implementation errors from unclear scope.)
- "Session Target picks which harness runs your session. That choice is separate from which role or model you pick." (Clarifies the architectural change that allows multiple agent harnesses (Microsoft, Anthropic, OpenAI) to coexist in the same chat panel with shared history.)
- "For AL work, stay with Copilot or Local. Both understand Business Central workspace context, symbols, and the AL language extension." (Guides AL developers toward harnesses with Business Central awareness rather than general-purpose coding harnesses lacking AL-specific context.)
