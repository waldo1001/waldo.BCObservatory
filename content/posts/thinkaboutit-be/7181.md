> This session from BC TechDays 2025 covers report design in Business Central, explaining how datasets, layouts, and request pages work together. It provides practical guidance on choosing layout types (Word, RDLC, Excel), optimizing performance for cloud environments, and extending reports responsibly without modifying base applications.

## Key points

- Reports combine three layers: data (dataset), presentation (layout), and user input (request page) that should be treated separately
- Select layout types based on purpose: Word for documents and email, RDLC for advanced formatting, Excel for analytical output
- Optimize performance by keeping datasets lean, avoiding heavy data items, and using Word layouts over RDLC in SaaS environments
- Use report extensions to modify existing reports instead of changing the base application
- Push complex logic to AL code, keeping layouts focused on display rather than computation

## Quotes

- "A report object combines data (dataset), presentation (layout), and user input (request page)." (Understanding these three separate layers is fundamental to building effective reports and troubleshooting issues systematically)
- "Keep It Lean - Include only necessary data items and columns. Heavy datasets slow down SaaS reports." (Performance in cloud environments requires discipline in dataset design to avoid slowdowns)
- "Word layouts often perform better in SaaS than RDLC because of sandbox restrictions." (Layout choice directly impacts cloud performance and should be a deliberate decision based on environment constraints)
