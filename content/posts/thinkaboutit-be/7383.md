# Copilot Plan Mode in AL: Clarifying Intent Before Writing Code

[Read the post](https://thinkaboutit.be/2025/12/copilot-plan-mode-in-al-clarifying-intent-before-writing-code/) · think about IT - Steven Renders (Steven Renders) · 2025-12-23 · 787 words · tier community · **unreviewed** (machine-generated)

> Plan mode in GitHub Copilot for AL development clarifies architectural intent and design decisions before code generation. It is most valuable when features span multiple objects or when Agent mode will be used extensively, helping teams align on responsibilities and structure before implementation begins.

## Key points

- Plan mode produces a structured approach and explicit assumptions without writing or modifying code, functioning as a design conversation tool
- AL projects benefit from upfront clarity about where validation, business logic, and responsibilities belong across tables, codeunits, and pages
- Combining Plan mode with Agent mode makes Agent more predictable and focused by narrowing scope to specific implementation steps
- Plan mode is most useful for features touching multiple objects or complex architecture; it is unnecessary for small refactors or single-trigger fixes

## Quotes

- "Plan mode exists to address that problem. It creates a moment where nothing is executed, assumptions are surfaced, intent is made explicit." (Explains the core value of Plan mode - creating a deliberate pause before code generation to surface and align on design decisions)
- "Plan does not slow development down. It reduces rework." (Clarifies that upfront planning is an investment that prevents costly rework later in AL projects)
- "If Agent is about doing, Plan is about deciding." (Succinctly captures the distinct role of Plan mode in the Copilot workflow, emphasizing decision-making over execution)
