# Choosing a Language Model for AL Development in VS Code

[Read the post](https://thinkaboutit.be/2026/09/choosing-a-language-model-for-al-development-in-vs-code/) · think about IT - Steven Renders (Steven Renders) · 2026-09-23 · 950 words · tier community · **unreviewed** (machine-generated)

> When using Copilot Chat in VS Code for AL development, you can select different language models based on task complexity. Fast models suit simple tasks while reasoning models handle design decisions, but AL developers must validate model suggestions against actual BC symbols since models may confidently produce outdated code based on old training data.

## Key points

- Language models have training cutoffs and lack knowledge of BC versions released after their training, causing them to suggest outdated code with false confidence
- Fast models work best for simple repetitive AL tasks like standard validations, while reasoning models should be used for design decisions and complex problems
- Model choice applies uniformly across Ask, Plan, and Agent roles in VS Code, though custom agents can pin specific models in their frontmatter
- Always verify model suggestions against your actual BC symbols and objects rather than trusting model output alone
- Context window size and cost vary by model; check the Manage models view for current options and capabilities

## Quotes

- "A model trained before a given BC version shipped will write code with full confidence, using an older version of the standard application." (Highlights the core AL-specific problem: models confidently generate outdated code without warning, which is more dangerous than general coding mistakes)
- "Whenever you write AL code against a standard Business Central object, treat the model's first answer as a guess, not a fact." (Provides essential guidance for AL developers to validate model output against real symbols to catch knowledge gaps)
