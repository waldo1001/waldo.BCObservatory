# Rethinking LinterCop: Preparing for the Next Chapter

[Read the post](https://www.vondervoort.be/index.php/2025/10/31/rethinking-lintercop-preparing-for-the-next-chapter/) · Vondervoort.be (Arthur van de Vondervoort) · 2025-10-31 · 1326 words · tier community · **unreviewed** (machine-generated)

> LinterCop, a code analyzer for AL, faces architectural limitations that require fundamental redesign. The post explains tight coupling with the AL language, distribution challenges through GitHub, scope creep as a "Swiss Army Knife," and DevOps integration issues, leading to a proposed LinterCop 2.0 rebuild.

## Key points

- LinterCop generates 50 assets per release due to AL language version dependencies and breaking changes between versions
- GitHub release distribution has rate limiting issues; moving to NuGet would require creating new package versions whenever AL Language updates
- The analyzer scope has grown too broad, mixing language syntax rules with Business Central business logic recommendations, suggesting need for specialized analyzers
- DevOps integration breaks in pre-release AL Language versions due to tight coupling, requiring fundamental architectural changes

## Quotes

- "Maintaining backward compatibility with third-party analyzers would slow down their own development. It's a trade-off that makes sense for me." (Shows understanding of Microsoft's design decisions and the fundamental challenge for third-party tool developers)
