# Dynamics 365 Business Central: compressing API responses at max.

[Read the post](https://demiliani.com/2025/06/23/dynamics-365-business-central-compressing-api-responses-at-max/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2025-06-23 · 761 words · tier community · reviewed (checked by Opus)

> This post explains how to use Brotli compression instead of gzip to reduce the size of OData API responses from Business Central. Brotli significantly decreases bandwidth usage and transfer times for high-volume API calls by achieving better compression ratios than the default gzip algorithm.

## Key points

- Business Central APIs compress responses with gzip by default, negotiated via Accept-Encoding and Content-Encoding headers
- Sending Accept-Encoding: br makes the API return Brotli-compressed responses, which were much smaller in tests on a custom Item API
- For 10000 items the response dropped from roughly 11 MB with gzip to about 515 KB with Brotli
- In C#, an HttpClient with AutomaticDecompression set to Brotli and a br accept header handles decompression transparently
- Brotli may add slight server overhead, though the author saw no significant difference

## Quotes

- "Brotli is a high-efficiency, lossless compression algorithm developed by Google that achieves higher compression ratios compared to traditional algorithms such as gzip." (Explains why Brotli is superior to the default compression method for reducing data transmission size)
