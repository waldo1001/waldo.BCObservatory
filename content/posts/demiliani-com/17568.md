# Giving an AI agent the keys to Business Central: practical security tips.

[Read the post](https://demiliani.com/2026/11/04/giving-an-ai-agent-the-keys-to-business-central-practical-security-tips/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-11-04 · 1626 words · tier community · **unreviewed** (model text not yet checked)

> Securing AI agents that act on data in Business Central requires deliberate choices about identity, permissions, validation and oversight. The post provides a framework for deploying agents safely using existing tools like MFA, least privilege and change control, ensuring accountability stays with people rather than the agent.

## Key points

- AI agents need their own application identity with narrow permissions built from the task backwards, not shared logins or broad service accounts
- Treat all data the agent reads (PDFs, emails, fields) as untrusted input vulnerable to prompt injection and validate it with deterministic code before acting
- Require human approval with full evidence (source documents, matched orders, rule violations, agent identity) and enforce posting rights so only humans can finalize records
- Plan for failure before go-live: rehearse disabling the agent, audit trails to trace what it did, and point-in-time restore capability to repair damage
- AI-generated code in development must follow normal engineering gates (branch policies, analyzers, human review) and avoid closed-loop approval by multiple AI systems

## Quotes

- "The agent can do the work, but accountability stays with people." (Summarizes the core principle: agents execute but humans remain responsible, preventing delegation of accountability)
- "Permitted, plausible and wrong is the failure mode to design against." (Highlights that technical permissions alone cannot prevent incorrect decisions; additional controls and human judgment are required)
- "These checks are boring, testable and impossible to sweet-talk, which is exactly what you want from a control." (Emphasizes that deterministic validation rules are more reliable than trusting the agent's judgment to follow instructions)
