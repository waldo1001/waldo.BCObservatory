# Be careful with Visual Studio Code extensions…

> Visual Studio Code extensions run with full IDE privileges and pose security risks if compromised, as demonstrated by a malware-infected Nx Console extension that compromised GitHub. The post explains multiple strategies to control extension deployment, including allowlist policies, file system permissions, WDAC, private marketplaces, and Azure Artifacts.

[Read the post](https://demiliani.com/2026/05/21/be-careful-with-visual-studio-code-extensions/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-05-21 · 972 words · tier community · **unreviewed** (machine-generated)

## Key points

- VS Code extensions are not sandboxed and have full access to the file system, terminal, and credential stores, making them security-critical targets.
- Version 1.96+ introduces extensions.allowed policy enforceable via Group Policy to whitelist approved extensions and control auto-updates.
- File system permissions via icacls and Windows Defender Application Control (WDAC) can block unauthorized .vsix file installations.
- Private VS Code marketplace (for GitHub Enterprise) and Azure Artifacts provide controlled, private distribution channels for extensions.
- Developer machines accumulate secrets and control the supply chain start, making them equally critical to production infrastructure security.

## Quotes

- "A compromised extension is just a Node.js process running inside a trusted application, with the same access rights as the developer." (Clarifies the attack mechanism: malware executes with full developer privileges, exploiting VS Code's trust model.)
