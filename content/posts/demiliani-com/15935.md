# Dynamics 365 Business Central (and friends): where does your Copilot prompt go?

[Read the post](https://demiliani.com/2026/09/22/dynamics-365-business-central-and-friends-where-does-your-copilot-prompt-go/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-09-22 · 1846 words · tier community · **unreviewed** (machine-generated)

> Copilot features in Dynamics 365 Business Central may move prompts across geographies for processing even when your data stays local. The post explains how data residency, environment region, and Azure OpenAI geography work independently, including the Allow data movement toggle that controls consent and varies by geographic location.

## Key points

- Data residency location (where the environment database lives) is independent from where AI processing happens
- The Allow data movement toggle appears only when Business Central environment location differs from Copilot processing geography
- Agents are more geographically constrained than classic Copilot features, potentially creating different data flows in the same tenant
- Since update 25.0, data movement is enabled by default; administrators can disable it to block Copilot features
- Cross-geography network latency (tens to hundreds of milliseconds) rarely impacts performance compared to prompt size and model choice

## Quotes

- "When a user triggers a Copilot feature, the prompt and the generated output, including any personal data they contain, may leave your geography." (It clarifies the core risk: data can cross borders during inference, which is the key compliance concern)
- "Since update 25.0 this feature is on by default, so Copilot works without setup. An administrator can switch it off at any time." (It shows the default posture changed and explains how to enforce restrictions through governance)
