# Securing your Azure Storage Account: a guide to enabling Business Central-only access using Network Security Perimeter (part2) – now with Service Tags.

[Read the post](https://demiliani.com/2026/10/13/securing-your-azure-storage-account-a-guide-to-enabling-business-central-only-access-using-network-security-perimeter-part2-now-with-service-tags/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-10-13 · 390 words · tier community · reviewed (checked by Opus)

> Azure Network Security Perimeter gained public preview support, announced October 6, 2026, for service tags as the source of inbound access rules. Administrators can restrict an Azure Storage Account to Business Central traffic by choosing the Dynamics365BusinessCentral service tag instead of maintaining IP lists, while Microsoft keeps the ranges current. Tags are broad, so this means trusting the service as a whole.

## Key points

- Service tag support for NSP inbound rules eliminates the need to manually track individual IP addresses
- The Dynamics365BusinessCentral service tag can be used as the source for NSP inbound access rules
- Service tags are broad by design and cover multiple Microsoft service instances, requiring trust at the service level rather than per-instance
- Administrators should consider stricter isolation options like specific IP ranges or subscription-based rules if service-level trust is not acceptable

## Quotes

- "Microsoft automatically updates the IP address prefixes associated with a service tag." (Highlights the operational benefit of eliminating manual IP range maintenance)

## Heads up

- warning: "Allowing a tag means trusting the service as a whole, not just your own instance of it."
- warning: "A tag typically covers a wide set of IP prefixes and can include traffic from many Microsoft-owned service instances."
