# How can I move my Business Central-related Azure resources to a new Azure region?

> Guide for migrating Business Central-related Azure and Power Platform resources from West Europe or North Europe to the new Italy North region. Covers strategic reasons for migration, detailed step-by-step procedures for Azure services (Application Insights, Storage, Function Apps, Logic Apps, SQL Database, Azure OpenAI) and Power Platform environments, migration strategies to minimize downtime, cost considerations, and post-migration reconfiguration tasks.

[Read the post](https://demiliani.com/2026/08/10/how-can-i-move-my-business-central-related-azure-resources-to-a-new-azure-region/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-08-10 · 3849 words · tier community · **unreviewed** (machine-generated)

## Key points

- Italy North datacenter provides lower latency for Italian users, local data residency, and regulatory compliance benefits, with only 22ms average latency to Western Europe.
- Power Platform geo-to-geo migration requires Microsoft Support request with 10+ days lead time and causes unavoidable downtime; Azure services can migrate with parallel-run approach for zero-user downtime.
- Most Azure services (Application Insights, Storage, Function Apps, Logic Apps, SQL Database, Azure OpenAI) must be recreated in the new region since Azure lacks a built-in move function; existing configuration and data must be manually copied.
- Power Platform components outside solutions (canvas apps, cloud flows not in solutions, enterprise policies, DLP rules) do not automatically migrate and require manual recreation post-migration.
- Coordination between Power Platform (must request first) and Azure migrations is critical; run parallel environments briefly to minimize costs while ensuring complete testing before switching production traffic.
