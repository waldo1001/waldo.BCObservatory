# Fewer tools, better agents: curating the Dynamics 365 Business Central MCP catalog.

[Read the post](https://demiliani.com/2026/11/16/fewer-tools-better-agents-curating-the-dynamics-365-business-central-mcp-catalog/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-11-16 · 2540 words · tier community · reviewed (checked by Opus)

> Curating a tight MCP catalog for Dynamics 365 Business Central agents improves both security and agent performance. The post explains how to use configurations, permissions and feature toggles to expose only the tools each agent job needs, and shows why large catalogs with auto-discovery fail as both security and decision-making surfaces.

## Key points

- A large, loosely scoped MCP catalog widens the security surface and makes the agent more likely to pick the wrong tool; each tool should earn its place.
- Named MCP configurations let you choose API pages and queries and set read, create, modify, delete and action permissions per object. Writes need Unblock Edit Tools turned on.
- The built-in blank-named default runs in dynamic tool mode with read-only discovery, so agents can read anything the user can see. Replace it with a minimal named default, and send the Company header to pin the connection to one company.
- Use one configuration per agent job and expose business actions, such as a custom API codeunit that posts only approved invoices, rather than raw table operations.
- Small catalogs mean fewer wrong records and fewer tool calls, which matters because Microsoft has announced plans to charge per MCP tool call.

## Quotes

- "The catalog is the security boundary: prompts and agent instructions can be ignored or injected; what a configuration does not expose cannot be called." (It clarifies that configuration design is the actual security control, not training or prompts, so curators must be strict about what tools are listed)
- "An agent is only as safe as the catalog it can see. Keep yours small enough that you can explain every entry in it." (It sets the bar for curation: if you cannot defend a tool's presence, it should not be there, making governance explicit and defensible)

## Heads up

- gotcha: "with no setup at all, an agent can discover and read anything the signed-in user can see."
- warning: "A client that skips the Company header can move across companies too."
- gotcha: "One bad guess and a wrong invoice is posted to the ledger." (about table purchase invoices)
