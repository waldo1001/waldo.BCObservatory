# Dynamics 365 Business Central: checking for breaking changes on obsoleted, internal and OnPrem objects.

[Read the post](https://demiliani.com/2025/07/22/dynamics-365-business-central-checking-for-breaking-changes-on-obsoleted-internal-and-onprem-objects/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2025-07-22 · 695 words · tier community · **unreviewed** (machine-generated)

> AL extensions for Business Central can have obsoleted, internal, or OnPrem-scoped objects where breaking changes are not detected by default during AppSource validation. Microsoft added AppSourceCop configuration settings (validateObsoleteSymbols, validateInternalSymbols, validateOnPremSymbols) to enable breaking change validation on these previously excluded symbols.

## Key points

- AppSourceCop does not validate breaking changes on obsoleted objects, internal symbols, or OnPrem-scoped methods by default
- Breaking changes to internal symbols with internalsVisibleTo can silently break dependent extensions without being caught
- Three new AppSourceCop.json configuration parameters enable validation of these excluded symbol types
- validateInternalSymbols is particularly important for extensions using internalsVisibleTo that other apps depend on

## Quotes

- "By default, all these objects are not validated by AppSourceCop nor by the AppSource technical validation process." (Explains the core problem that unvalidated obsolete, internal, and OnPrem symbols can have breaking changes slip through)
- "AppSource validation is not checking for those problems…" (Emphasizes why developers must manually configure these new settings to catch such breaking changes)
