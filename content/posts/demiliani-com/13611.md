# From Chat Completions to Responses API: why Azure OpenAI’s new paradigm changes everything.

[Read the post](https://demiliani.com/2026/04/16/from-chat-completions-to-responses-api-why-azure-openais-new-paradigm-changes-everything/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-04-16 · 2827 words · tier community · **unreviewed** (machine-generated)

> Azure OpenAI's Responses API replaces Chat Completions as the recommended approach for new AI projects, offering stateful conversations, better token efficiency, and built-in agentic capabilities. Business Central currently wraps Chat Completions through System.AI, but this architecture can evolve to support Responses API for more complex scenarios involving long conversations, autonomous agents, and background execution.

## Key points

- Responses API stores conversation state server-side with unique IDs, eliminating the need to resend full history on each turn, reducing token costs and improving reliability.
- Responses API is agentic by default, enabling models to call multiple tools and external services within a single request, unlike Chat Completions which requires manual orchestration.
- Business Central's System.AI namespace currently wraps Chat Completions and provides guardrails, telemetry, and managed resources that make it worth using today, but the underlying design is extensible for future Responses API support.
- Responses API supports background execution mode for long-running tasks, context compaction for extremely long interactions, and richer streaming events, capabilities unavailable in Chat Completions.
- Chat Completions requires developers to manage conversation state client-side, causing quadratic cost growth as conversation length increases, while Responses API keeps state on the server.
