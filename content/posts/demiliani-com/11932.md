# High performance workflows with Azure Logic Apps: using Azure SQL as storage provider.

[Read the post](https://demiliani.com/2025/06/16/high-performance-workflows-with-azure-logic-apps-using-azure-sql-as-storage-provider/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2025-06-16 · 476 words · tier community · **unreviewed** (machine-generated)

> Azure Logic Apps can now use Azure SQL as a storage provider instead of Azure Storage for workflow state and runtime data, enabling better performance tuning, predictable costs, and enterprise-grade reliability features for standard logic app instances.

## Key points

- Azure Logic Apps traditionally use Azure Storage which can cause performance delays, especially in loops and connector actions
- Azure SQL as a storage provider allows fine-tuning throughput and scaling based on workflow needs
- Configuration requires enabling Azure services in SQL networking settings and selecting SQL storage type during Logic Apps creation
- SQL acts as primary storage while Azure Storage remains as secondary for platform configuration hosting
- Workflow state, run history, and runtime artifacts are stored in the SQL database in automatically created tables
