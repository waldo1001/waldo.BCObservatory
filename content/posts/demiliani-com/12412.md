# Visual Studio Code and autodiscovery of MCP servers: better to stay in control.

[Read the post](https://demiliani.com/2025/08/22/visual-studio-code-and-autodiscovery-of-mcp-servers-better-to-stay-in-control/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2025-08-22 · 267 words · tier community · **unreviewed** (machine-generated)

> Visual Studio Code's MCP server autodiscovery feature automatically imports configurations from AI tools like Claude and Cursor, but can be disabled or controlled to reduce token consumption and context window impact when running agents with unnecessary tools.

## Key points

- VS Code autodiscovery for MCP servers is enabled by default and imports configurations from other AI tools
- Running too many MCP servers consumes tokens just describing their capabilities, reducing available context window
- Autodiscovery can be disabled completely by setting it to FALSE or restricted to specific tools
- Microsoft plans to disable this feature by default in future VS Code versions

## Quotes

- "each MCP consumes token just for describing what is does, so IMO it's better to have a clean configuration" (Clarifies the performance impact of having unnecessary MCP servers installed and configured)
- "Microsoft Visual Studio Code Team is thinking to set the autodiscovery feature of MCP servers to DISABLE by default in future versions" (Indicates Microsoft recognizes the issue and plans to change the default behavior)
