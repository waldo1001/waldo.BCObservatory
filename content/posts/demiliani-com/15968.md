# Dynamics 365 Business Central: AL Query objects and the new ReadState property.

[Read the post](https://demiliani.com/2026/09/24/dynamics-365-business-central-al-query-objects-and-the-new-readstate-property/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-09-24 · 937 words · tier community · **unreviewed** (machine-generated)

> AL query objects now support the ReadState property in Dynamics 365 Business Central 2026 Wave 2 to control transaction isolation levels. This lets developers choose between ReadUncommitted (fast, unreliable), ReadCommitted (safe middle ground), ReadShared (stable until transaction end), and ReadExclusive (prevents other changes) based on whether the query displays data or drives business decisions.

## Key points

- Query objects describe result sets by declaring tables as data items and choosing columns, supporting filtering, grouping, and aggregation.
- ReadState property lets developers specify transaction isolation levels for individual queries, overriding CurrentTransactionType.
- Four isolation levels available: ReadUncommitted (default, fast but risky), ReadCommitted (sees only committed data), ReadShared (adds locks until transaction ends), and ReadExclusive (prevents others from changing rows).
- Strictest lock wins across multiple reads of the same row; stricter reads are safer but cause more waiting for other sessions.
- Display queries can use ReadUncommitted, but decision-driven and modification queries need ReadCommitted or stricter options.

## Quotes
