# Dynamics 365 Business Central: locking down IsolatedStorage reads.

> Starting with runtime version 18.0, the IsolatedStorage.Get method accepts an optional IsolationLevel parameter to prevent race conditions during concurrent read-modify-write operations. The new UpdLock isolation level holds an update lock on a key's row during reads, blocking other sessions until the transaction completes, protecting sensitive data like secret keys, feature flags, and cached tokens from concurrent corruption.

[Read the post](https://demiliani.com/2026/09/14/dynamics-365-business-central-locking-down-isolatedstorage-reads/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-09-14 · 409 words · tier community · **unreviewed** (machine-generated)

## Key points

- IsolatedStorage.Get now accepts an optional IsolationLevel parameter to control how the key row is locked during reads
- IsolationLevel::UpdLock holds an update lock until the transaction ends, preventing other sessions from reading or writing the same key
- This protects read-modify-write patterns commonly used for secret keys, feature flags, and cached tokens
- Available in runtime version 18.0 and later; earlier versions require alternative locking strategies
