# Azure Logic Apps: never share the same storage account between different apps.

[Read the post](https://demiliani.com/2026/02/04/azure-logic-apps-never-share-the-same-storage-account-between-different-apps/) · Stefano Demiliani (Stefano Demiliani, MVP) · 2026-02-04 · 1000 words · tier community · **unreviewed** (machine-generated)

> Sharing a single Azure Storage Account across multiple Azure Logic Apps instances causes scalability and reliability problems, including HTTP 429 throttling errors, increased latency, and state contention. The post demonstrates these issues through load testing and recommends using one storage account per Logic App for isolation and predictable performance.

## Key points

- Shared storage accounts hit Azure limits (20,000 requests/second) when multiple Logic App instances persist state and action outputs simultaneously
- Both Consumption and Standard Logic Apps experience throttling, cascading failures, and unpredictable performance during peak loads when using shared storage
- Contention occurs on table storage for session state and on queues for message processing when multiple apps access the same storage account
- Load testing showed average response time increased from 1355ms to 3097ms (with 12-second spikes) when moving from light to heavy workload on shared storage
- Using one storage account per Logic App provides complete isolation, eliminates locking issues, and ensures predictable performance
