# Dynamics 365 Business Central – Handling the message “Only the Posting No. Series can be filled in on recurring journals” in Recurring Journals

[Read the post](https://thedynamicsexplorer.com/2026/03/02/dynamics-365-business-central-handling-the-message-only-the-posting-no-series-can-be-filled-in-on-recurring-journals-in-recurring-journals/) · The Dynamics Explorer (Gavin Whittaker) · 2026-03-02 · 878 words · tier community · reviewed (checked by Opus)

> Business Central blocks a regular No. Series on Recurring General Journal batches; the author assumes this is because lines stay after posting, so numbers would repeat. Two workarounds are shown: set a Posting No. Series on the batch so posted entries get unique numbers, or put date placeholders in the Document No. field so each posting builds a unique number from the posting date.

## Key points

- Recurring journal lines remain after posting and their posting date moves forward by the recurring frequency
- The author believes the No. Series block exists to avoid the same number being reused on every posting
- A Posting No. Series on the batch header numbers the posted G/L entries, ignoring the document number typed on the lines
- Placeholders such as %1 day, %2 week, %3 month, %4 month name, %5 accounting period and %6 fiscal year are filled from the posting date
- Placeholders work the same way as in deferrals and remove the need to edit document numbers before each posting

## Quotes

- "After posting a Recurring General Journal the journal lines remain and the posting date is updated based on the recurring frequency." (Explains the core design of recurring journals that creates the document numbering challenge)
- "When I post this for May, there's no need to update the document number. The system automatically replaces the placeholders using the posting date." (Demonstrates the key benefit of using placeholders for automating unique document number generation)
