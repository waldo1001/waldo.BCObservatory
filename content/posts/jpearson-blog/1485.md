# Calling Business Central APIs Without a Client Secret

[Read the post](https://jpearson.blog/2025/07/04/calling-business-central-apis-without-a-client-secret/) · James Pearson (James Pearson) · 2025-07-04 · 1252 words · tier community · **unreviewed** (machine-generated)

> Calling Business Central APIs from Azure resources without client secrets is possible using managed identities and federated credentials for token exchange. This approach eliminates the need to store and rotate secret credentials, reducing security risks when integrating Static Web Apps or Azure Functions with Business Central.

## Key points

- Managed identities assigned to Azure resources can obtain access tokens without needing client secrets
- Federated credentials enable token exchange between the managed identity token and an app registration token
- An Entra Application must still be created in Business Central with appropriate permission sets
- Token exchange uses JWT bearer assertion to swap a managed identity token for an app registration token
- Establishes trust between managed identity issuer and app registration to authorize the token exchange

## Quotes

- "We need to exchange the token we've already got for a token issued for the app registration." (This explains the core mechanism: the managed identity token alone is insufficient; it must be exchanged for an app registration token that has Business Central permissions.)
- "It would be better if we had a solution that didn't rely on client secrets." (States the motivation: avoiding secrets eliminates expiration management, key vault dependencies, and credential compromise risks.)
