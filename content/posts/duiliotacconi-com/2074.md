# Use sqlServerSessionId to spot on blocking sessions in Dynamics 365 Business Central 2026 Wave 1

[Read the post](https://duiliotacconi.com/2026/07/22/use-sqlserversessionid-to-spot-on-blocking-sessions-in-dynamics-365-business-central-2026-wave-1/) · Duilio Tacconi (Duilio Tacconi, MVP) · 2026-07-22 · 1071 words · tier community · reviewed (checked by Opus)

> Business Central 2026 Wave 1 (v28) adds sqlServerSessionId to Long Running Queries telemetry (RT0005) and other signals that carry a SQL statement. When a Lock Snapshot (RT0013) shows a blocking SQL session without an AL stack trace because the blocker ran on another service tier, this ID can be traced through RT0005 to find the offending AL session and method.

## Key points

- sqlServerSessionId is now included in all telemetry traces containing sqlStatement values, making it possible to correlate lock timeouts across NSTs
- Lock Snapshot signals (RT0013) cannot provide AL Stack Trace for blocking sessions running on separate NSTs, creating a gap that sqlServerSessionId helps fill
- Investigation workflow involves isolating lock timeouts, filtering lock snapshots for the blocking sqlServerSessionId, then finding Long Running Queries with that same ID
- Concurrency issues can be resolved with ReadIsolation(IsolationLevel::ReadUncommitted) or by optimizing queries using AL Query objects with proper joins and aggregations
