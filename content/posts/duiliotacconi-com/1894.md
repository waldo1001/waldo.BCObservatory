# FlowFields with same filters and table in a single OUTER APPLY

[Read the post](https://duiliotacconi.com/2026/02/13/flowfields-with-same-filters-and-table-in-a-single-outer-apply/) · Duilio Tacconi (Duilio Tacconi, MVP) · 2026-02-13 · 1114 words · tier community · reviewed (checked by Opus)

> Starting with Business Central 27.0 (2025 Wave 2), SmartSQL puts all FlowFields that use the same table and the same filters into one OUTER APPLY, instead of one OUTER APPLY per FlowField. This removes duplicate data retrieval and changes the execution plan. It is always on by default.

## Key points

- Before v27, SmartSQL sent one SQL statement per record set, with one OUTER APPLY for each FlowField
- In v27, FlowFields with the same source table and the same filters share one OUTER APPLY
- Aggregations that can be grouped: SUM, AVERAGE and COUNT; MIN and MAX (with COUNT too if indexed); EXISTS and LOOKUP
- Maintained indexed views (V-SIFTs) are not grouped with non-indexed FlowFields
- The post suggests checking pageViews (CL0001) and long running SQL query (RT0005) telemetry after upgrading to see the effect

## Quotes

- "A good platform feature, then, that is turned always on by default since 27.0." (Confirms the feature requires no configuration and is automatically active)
