# About Online Upgrades to Dynamics 365 Business Central 2026 Wave 2 (v29)

> Dynamics 365 Business Central 2026 Wave 2 online upgrades take significantly longer than previous versions due to more table extensions, increased data volumes, additional columns, and Microsoft resource governance. The post analyzes upgrade SQL and extension footprints using telemetry, explains synchronization mechanics, and demonstrates how storing BLOBs in the database causes severe performance problems during upgrades.

## Key points

- Version 29 upgrades are slower than prior versions because of table extensions, larger databases, more columns, and stricter resource governance
- Upgrade synchronization follows an ALTER-UPDATE-DROP-INDEX cycle that can be traced through telemetry queries
- A new LC0065 event signals tables exceeding 256 fields, helping identify candidates for partial records or extension cleanup
- Storing large BLOB objects in the database instead of external storage like Azure Blob Storage dramatically slows upgrades

- "online upgrades are taking more time than any previous upgrades (that were not strictly dependent on data upgrades)" (Explains the key difference in version 29 upgrades and sets expectations for administrators planning upgrades)
- "DO NOT store BLOBs in the database (unless strictly necessary). It's a database not a file share!" (Provides the most actionable lesson learned, highlighting that moving BLOBs to external storage reduced upgrade time from 7 hours to 1 hour)
