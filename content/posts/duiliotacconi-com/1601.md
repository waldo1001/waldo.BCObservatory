# When Auditing meets Telemetry: a practical example.

[Read the post](https://duiliotacconi.com/2025/09/05/when-auditing-meets-telemetry-a-practical-example/) · Duilio Tacconi (Duilio Tacconi, MVP) · 2025-09-05 · 699 words · tier community · **unreviewed** (machine-generated)

> When investigating a deleted Default Dimension record, the author demonstrates how telemetry and Change Log together can identify unexpected data deletions caused by application logic. By combining audit trails with telemetry traces, the investigation revealed the user did perform the action unknowingly through a calculation process that incorrectly deleted temporary records.

## Key points

- Change Log records what changed (user, date, deletion event) but not always why or the context of the action
- Telemetry traces provide execution context showing which code triggered the deletion and when
- The combination of both auditing tools solved a mystery where the user was innocent but the Change Log was factually correct
- A late placement of a temporary record check caused real data deletion instead of temporary record deletion
- Moving the temporary record validation to the start of the OnAfterDeleteEvent prevented accidental dimension deletion

## Quotes

- "Telemetry can do A LOT of good things but unfortunately it was not meant to be used for pure AUDITING purposes." (Clarifies the intended scope of telemetry and sets expectations for when to use Change Log instead)
- "With a simple query that scanned both traces and page views, we were able to determine the innocence of the user" (Shows how telemetry provides execution context that audit logs alone cannot, solving investigations faster)
- "just one line, and where you place it, makes a big difference" (Demonstrates how code placement of validation logic directly impacts whether temporary or real data gets deleted)
