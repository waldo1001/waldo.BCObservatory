# How to choose the best Update Window in Dynamics 365 Business Central Online

> Understanding how to choose the optimal update window for Business Central requires analyzing when platform hotfixes are deployed using telemetry data. The post provides a KQL query to track platform hotfix deployments and recommends scheduling based on when Microsoft statistically deploys fewer updates to minimize disruptions to background jobs.

## Key points

- Application hotfixes respect the 6-hour update window configured in Tenant Admin Center, while platform hotfixes are deployed independently by Microsoft outside business hours
- A KQL query can analyze component version changes in Application Insights to determine when platform hotfixes occur and identify optimal update windows
- For Italy/Rome timezone, the 2-8 AM window shows the best distribution for minimizing platform hotfix conflicts with long-running processes
- Platform hotfixes deploy least frequently on weekends and on Tuesdays and Fridays, while Wednesday and Thursday see the most deployment activity

## Quotes

- "Application Hotfixes typically observe the 6-hours Update Window setup per environment in Tenant Admin Center." (Shows that application hotfixes are controllable, unlike platform hotfixes which deploy independently)
- "These are critical components and/or platform changes that are applied node by node in the cluster that is serving multiple customers." (Explains why platform hotfixes cannot follow the update window schedule and impact multiple environments)
- "If you want to plan the best update window for your customer, you must use telemetry to better understand when platform hotfixes are applied." (Provides the key strategy for minimizing disruptions by using data-driven analysis rather than assumptions)
