# Client Crash? Check Error Dialog signal

[Read the post](https://duiliotacconi.com/2025/08/06/client-crash-check-error-dialog-signal/) · Duilio Tacconi (Duilio Tacconi, MVP) · 2025-08-06 · 1219 words · tier community · **unreviewed** (machine-generated)

> Troubleshooting client crashes in online Dynamics 365 Business Central requires using telemetry signals rather than Event Viewer. The Error Dialog signal (RT0030) in Azure Data Explorer provides detailed crash diagnostics including stack traces, error messages, and affected objects to identify whether issues are application or platform-related.

## Key points

- Online environments lack Event Viewer access, so telemetry is the primary troubleshooting tool for client crashes
- Use the Error Dialog signal (RT0030) in Azure Data Explorer to filter and analyze crash details by operation_id and session_id
- Stack trace analysis combined with timing data can reveal whether crashes are caused by application code or platform race conditions
- Platform hotfixes are deployed automatically in online environments through standard pipelines and identified by component version numbers

## Quotes

- "When the client dies with a smile, it always leaves you with a timestamp AND an operation id." (Operation IDs are the starting point for tracing what caused a crash in telemetry when Event Viewer is unavailable)
- "See how many details you could squeeze out from one single signal? Mind blowing." (Demonstrates that telemetry signals contain comprehensive diagnostic information needed to distinguish application from platform issues)
