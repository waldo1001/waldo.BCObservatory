# Agents in Business Central – part 1 – the architecture

[Read the post](https://www.bertverbeek.nl/blog/2026/02/10/agents-in-business-central-part-1-the-architecture/) · Discover MS BC - Bert Verbeek (Bert Verbeek) · 2026-02-10 · 571 words · tier community · **unreviewed** (machine-generated)

> Agents in Business Central 27.4 allow you to create custom agents that process tasks asynchronously using an orchestrator architecture. The post explains how agents are triggered via task creation, how the orchestrator manages execution with separate sessions and transactions, and how to handle incoming and outgoing messages programmatically.

## Key points

- Custom agents require enabling the feature, assigning AGENT-ADMIN permissions, and setting up billing in a sandbox environment
- Agents are triggered by creating tasks using AgentTaskBuilder codeunit, with the orchestrator handling asynchronous execution in separate sessions
- Tasks can be managed (restarted, stopped, status checked) and support conversation tracking with message IDs for reply threads
- Incoming messages are processed via Job Queue triggers and can include attachments using AgentTaskMessageBuilder
- Outgoing messages must be retrieved by status and type, processed, and marked as Sent using the Agent Message codeunit

## Quotes

- "Since Business Central 27.4 minor update you can create your own agents inside Business Central." (Establishes when custom agents became available and marks the beginning of the feature capability)
- "Each task can be seen as a separate user session, thus uncommitted data may not be viewable and concurrent modifications can collide." (Important architectural consideration for developers implementing agent tasks to avoid data consistency issues)
