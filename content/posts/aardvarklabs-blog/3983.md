# Business Central v29: SQL Table Extensions Redesign Explained

> Business Central v29 completes a redesign of table extensions by storing all custom fields directly in the primary SQL table instead of creating separate extension tables, eliminating JOIN operations and improving performance. This architectural change simplifies indexing and reduces overhead for heavily customized systems but introduces a 1024-column SQL Server limit constraint.

[Read the post](https://aardvarklabs.blog/2026/10/02/business-central-v29-sql-table-extensions-redesign-explained/) · Aardvark Labs (Marcel Chabot) · 2026-10-02 · 381 words · tier community · **unreviewed** (machine-generated)

## Key points

- Pre-v23 created separate SQL tables for each extension, requiring multiple JOINs and hindering performance and indexing
- v23 consolidated all extension fields into a single extension table per base table, reducing to one JOIN
- v29 eliminates extension tables entirely by storing custom fields directly in the primary table
- SQL Server's 1024-column limit per table now applies as a practical constraint, with compiler warnings and errors when exceeded
- Best practices like avoiding unnecessary page fields and careful index design remain critical despite architectural improvements
