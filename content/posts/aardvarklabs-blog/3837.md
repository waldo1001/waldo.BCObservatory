# Background Page Tasks in Business Central Explained

[Read the post](https://aardvarklabs.blog/2026/08/07/background-page-tasks-in-business-central-explained/) · Aardvark Labs (Marcel Chabot) · 2026-08-07 · 982 words · tier community · reviewed (checked by Opus)

> Background page tasks enable pages to automatically refresh themselves or trigger actions when long-running processes complete. Introduced in Business Central 2019 Wave 2, they prevent users from repeatedly refreshing pages while waiting for operations to finish by using the OnPageBackgroundTaskCompleted trigger to update data and UI automatically.

## Key points

- Page background tasks arrived in BC 2019 Wave 2 (15.2) and let a page refresh itself so users do not have to keep refreshing by hand
- Refreshing a page also refreshes its background worker, so the design needs a static host page and a dynamic page that gets refreshed. The example uses a Card with an embedded ListPart, started through a StartRefresh procedure
- OnPageBackgroundTaskCompleted fires for any completed page background task, so the code compares the TaskId with the stored PbtTaskId before it requeues the task and calls RefreshData
- The codeunit only sleeps here, but it could do real long-running work such as posting. When the work finishes, the page could show a message, navigate somewhere else or start an AI process

## Quotes

- "When ANY page background task is completed the OnPageBackgroundTaskCompleted trigger fires." (This is the core mechanism that enables automatic response to background task completion without user action.)
- "The auto refresh example is fine, but the start long running work and auto refresh when complete is a much better use case." (Identifies the practical value of background tasks beyond simple refresh scenarios, such as monitoring posting routines or long-running operations.)
