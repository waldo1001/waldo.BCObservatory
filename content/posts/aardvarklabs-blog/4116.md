# Business Central v29: Using AL Interfaces with Default Method Support

[Read the post](https://aardvarklabs.blog/2026/11/20/business-central-v29-using-al-interfaces-with-default-method-support/) · Aardvark Labs (Marcel Chabot) · 2026-11-20 · 1786 words · tier community · **unreviewed** (model text not yet checked)

> Business Central 29.0 introduces default interface methods in AL, allowing interfaces to provide complete procedure implementations that codeunits may override while maintaining backward compatibility. This feature reduces duplicate code and lets developers evolve interfaces without breaking existing implementations.

## Key points

- Default interface methods let interfaces provide full implementations that codeunits can override or inherit automatically
- Abstract methods still require implementation in codeunits; default methods do not
- Adding new procedures as defaults first, then marking them as RequiredPending, allows gradual migration to mandatory procedures without breaking existing code
- Interface references must be used to access default implementations, not direct codeunit references
- Default methods improve AI code generation by providing strict contracts that eliminate ambiguity

## Quotes

- "A default method lets the interface provide a full implementation that codeunits may override if needed." (This is the core capability that solves the problem of adding functionality to interfaces without breaking existing implementations)
- "To access default implementations, you must call the interface variable not the code unit directly." (Understanding this distinction is critical for developers to correctly implement the feature; calling the wrong reference type will cause compilation errors)
- "Default Interface Methods make interfaces far more flexible and reduce the risk of breaking existing implementations when requirements evolve." (This summarizes the main business value of the feature for maintaining stable systems while evolving architecture)
