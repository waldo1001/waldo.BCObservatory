# Leveraging RecordRef and FieldRef for Dynamic Coding

[Read the post](https://aardvarklabs.blog/2026/03/06/leveraging-recordref-and-fieldref-for-dynamic-coding/) · Aardvark Labs (Marcel Chabot) · 2026-03-06 · 1499 words · tier community · reviewed (checked by Opus)

> This post explains how to use weakly typed RecordRef and FieldRef objects in Business Central AL for dynamic, flexible code when you don't know the record type at compile time. It contrasts weakly typed objects with strongly typed ones and demonstrates practical use cases like summing amounts across different table types and exporting any record set to Excel.

## Key points

- Strongly typed objects provide compile-time validation, IntelliSense, safer refactoring, and better performance, while weakly typed objects offer flexibility for dynamic access to tables and fields
- RecordRef and FieldRef are reference objects that provide the minimal common properties and procedures found in all strongly typed objects
- RecordRef can be populated from a strongly typed record using GetTable(), and individual fields are accessed via FieldRef using either field ID or field index
- Common use cases include logging, auditing, import frameworks, and generic code that works across multiple table structures without knowing the specific type
