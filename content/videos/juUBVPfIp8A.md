# What's New: AI Development Toolkit (2026 release wave 1)

> AI Development Toolkit updates in Business Central 2026 release wave 1: the renamed toolkit, simpler BC AI Resources authentication, content filtering and prompt injection protection for Azure Open AI, and evaluation features (suite configurations, multi-language, Copilot credit insights, agent evaluation).

[Watch on YouTube](https://www.youtube.com/watch?v=juUBVPfIp8A) · Microsoft Dynamics 365 Business Central (YouTube) · 2026-04-01 · 20:06 · tier official · reviewed (checked by Opus)

## Overview

The toolkit formerly known as the development tools for extending Copilot is now called the AI Development Toolkit. It covers using Azure Open AI from AL code and also designing and coding agents in Business Central. Agent development has been in public preview since February, with almost 1,500 agents built by the community.

The video walks through authentication changes for BC AI Resources, content filtering policies, prompt injection protection, and the renamed evaluation tool. Evaluations gain suite configurations, language categorization of test inputs, Copilot credit insights, and early agent evaluation support. Most of these were demoed.

## Key points

- The toolkit was renamed AI Development Toolkit; the AI test tool is now called AI Development Toolkit evaluation.
- BC AI Resources no longer require your own partner subscription. The set managed resource authorization method has a new signature without subscription details; the old one is obsoleted but still works.
- Content filtering supports low and medium levels, with low as the default. High is not supported in managed resources and needs your own Azure Open AI subscription with approval. Levels are set through the Azure Open AI policy parameters codeunit.
- Prompt injection protection uses Azure AI content prompt shields. You must call the detection tags for untrusted prompts and enable XPI detection separately.
- Evaluation suite configurations define capability, test type and frequency (daily, weekly, manual). The frequency enum is extensible, and pipelines must adopt the configurations manually because they do not run evaluations automatically.
- Multi-language evaluations require name and language in data sets, and data set names must be common across languages. Copilot credit use shows per run, line and data set entry.
- Agent evaluation is in the early stages and lets you inspect agent tasks per run, line and entry. An agent library is announced as coming soon.
