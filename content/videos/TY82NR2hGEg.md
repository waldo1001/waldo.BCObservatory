## Key points

- Namespaces are declared as the first statement in a source file and can be nested. Use using directives or fully qualified names to reference namespaced objects, and code actions can add either.
- Wait to namespace your own code until all your dependencies are namespaced, otherwise later namespacing of those dependencies breaks your references. Renaming a namespace is a breaking change.
- Namespace naming advice: start with company name, product, area, feature. Keep the root company-specific and stable, and avoid names like Microsoft, utility or common. Prefixes (fixes) on object names are still needed for now.
- AL Doc has an init command (once per documentation repository) and a build command that produces YAML from .app files. DocFX turns the YAML into HTML, which can be hosted on GitHub Pages.
- The explore page and explore field options in Visual Studio Code need the troubleshooting tools permission. The first symbol download can take time, and a shared symbols path lets you reuse symbols.
- Secure text hides values from normal and snapshot debugging, but it must be constructed in non-debuggable methods. It does not protect data shared outside Business Central.
- The AL profiler sampling interval can be 50, 100 (default) or 150 ms. The debug console supports IntelliSense but does not evaluate methods.
