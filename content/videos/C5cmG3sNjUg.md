# MCP Server for Business Central - Advanced Topics (Part 3)

> The Business Central MCP server (in public preview) is covered in depth: default vs named configurations, dynamic tools (search, describe, invoke), API page design with about text, tool limits (about 70 in Copilot Studio at recording), and the sample bcmcp proxy for other MCP hosts.

[Watch on YouTube](https://www.youtube.com/watch?v=C5cmG3sNjUg) · Microsoft Dynamics 365 Business Central (YouTube) · 2026-01-21 · 18:15 · tier official · **unreviewed** (machine-generated)

## Overview

This is part 3 of a series on the MCP server for Business Central, published 2026-01-21. It explains how the server exposes built-in APIs and lets you add custom APIs, and how the default configuration differs from named configurations that pre-load an explicit tool list.

It also covers the dynamic tools system, how API pages are named and described for language models, and the limits on tool counts in MCP hosts. It closes with agent instructions, model selection, and the sample proxy for hosts other than Copilot Studio. The proxy is sample code that is delivered as is, and an update is expected to remove the need for it.

## Key points

- The MCP server is in public preview. It exposes all built-in APIs for data, and custom APIs can be added. API queries might be opened up in the future.
- The default configuration offers three dynamic tools: search, describe and invoke. The client passes keywords, a semantic search returns the top relevant tools, and the model then describes and invokes API pages over OData.
- Named configurations pre-load an explicit tool list for a specific business process, so no tool search is needed. Too many tools fill the model context and hit host limits.
- Copilot Studio supported around 70 tools when the video was recorded. The limit will likely change.
- API page tool names append the object type and ID to stay unique. Descriptions and the about text property help the model reason about what each API does.
- The discover additional objects setting exposes more readonly API pages. It can raise the chance of model errors, use more context and reduce performance.
- For hosts other than Copilot Studio, the bcmcp proxy sample is on BCTech samples. It is not production ready, not part of the product, and is expected to be replaced by a simpler setup.
