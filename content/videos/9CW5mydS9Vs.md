# Microsoft presents: Tests, dependencies, runners and evals for BC applications

> Microsoft session on testing Business Central apps: propagated dependencies, test explorer support in AL, new test codeunit properties, internal visible to, AI test agents, and data-driven AI tests and evals. Also covers CI/CD test selection, MCP-based test execution and token consumption. Native data-driven tests are not yet in the product.

[Watch on YouTube](https://www.youtube.com/watch?v=9CW5mydS9Vs) · mibuso.com / BC TechDays · 2026-10-01 · 43:04 · tier community · reviewed (checked by Opus)

## Overview

The session from BC TechDays covers deterministic testing in AL and then moves to testing AI features. It demos propagated dependencies for refactoring apps without breaking external contracts, the application test library, internal visible to for test facades, and test explorer support that runs and debugs tests in the editor without a custom AL test runner. New test codeunit properties cover required permissions, test type and test isolation.

The second half covers AI. It shows an agent that writes tests interactively in GitHub Copilot Chat, and it separates AI tests from agent tests. AI tests use data sets of input, prompt, model and expected-outcome permutations, with repeated runs because results are non-deterministic. It also covers test selection by type and coverage, MCP server execution, token consumption tracking and model choice for cost.

## Key points

- Propagated dependencies lift dependencies as proxies in the manifest so apps can be split without breaking external contracts. They work for one level only and cannot point to another propagated dependency.
- Test explorer support in AL runs and debugs tests in the editor, with results, call stacks and assert messages inline. It needs codeunits marked with the test attribute.
- New test codeunit properties cover required test permissions, test type (unit or integration) and required test isolation, to support test explorer and CI/CD pipelines.
- Internal visible to exposes internal procedures to specified apps, for example test facades. Anyone can specify an app ID in production, which the speaker flags as a security concern.
- AI tests use data sets with permutations of inputs, prompts, models and expected outcomes, and are rerun several times because AI output is non-deterministic. Copilot feature tests run in the eval suite, not the standard test tool.
- Native data-driven tests with test data source attributes and a custom context interface are not part of the product yet. They may be in a pre-release.
- Tests that use GUI-related code behave differently when run from VS Code versus the client. This is a known issue; for now use the classic test explorer in the client or the PowerShell cmdlets.
