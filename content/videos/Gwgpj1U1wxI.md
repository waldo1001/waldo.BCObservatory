## Overview

The session from November 2023 walks through the Business Central cloud migration tooling end to end. It covers the setup wizard, the self-hosted integration runtime, automatic company creation, data replication, data upgrade and completing the migration to go live.

It also covers preparation (aligning SQL definitions, data cleanup), table mappings that move custom fields into table extensions, delegated admin consent, how replication works, limits such as 300 companies per SaaS environment, post-upgrade steps like user mapping, and troubleshooting with telemetry and a Power BI app.

## Key points

- Cloud migration uses Azure Data Factory SQL to SQL copy. On-premises sources need a self-hosted integration runtime installed in the private network. Migrating from Azure SQL is faster and more stable, and skips the blob storage staging step.
- Version 14 is the lowest supported version for direct migration or upgrade. The direct path from version 14 stops in April 2025 with version 26. A jump version is planned every five versions, and the next one would be 30.
- Setup applies changes to the on-premises database through stored procedures. Try the first migration on a backup of production, and a sandbox test is also recommended.
- Table and field definitions must match exactly in name and type, and primary keys must be aligned. Table mappings move custom fields into table extensions. They can be exported and imported as JSON, or generated by subscribing to an event in codeunit 401.
- Run the data upgrade as the very last step. No more replication or company additions are possible afterward. Do not change data in the SaaS database during replication.
- Postpone environment updates in the admin center during migration, because running them forcefully stops the migration.
- SaaS has a hard limit of 300 companies, and 250 is recommended. User mapping can run only once per environment, as the last step. Moving more companies into a live tenant is not officially supported.
