# What’s new: ALGraph (2026 release wave 2)

> AL Graph, a tool in the AL tools package that builds call graphs of AL code, is shown in a 2026 release wave 2 video. It covers querying callers, exporting to DGML and SARIF, and auditing the non-debuggable to debuggable boundary for security.

[Watch on YouTube](https://www.youtube.com/watch?v=i0gBrA1tx50) · Microsoft Dynamics 365 Business Central (YouTube) · 2026-10-01 · 6:31 · tier official · reviewed (checked by Opus)

## Overview

The video introduces AL Graph, a tool in the AL tools package that constructs call graphs. These graphs show caller-callee relationships, external integration points and dependencies, and can be used for code auditing and security analysis.

The demo builds a meta model of an app once, stores it as JSON and queries it repeatedly. It then runs two audits: finding all callers of the HTTP client and tracing call paths that reach HTTP requests, and finding callees of non-debuggable methods to see where debugging could expose secrets. Query syntax is documented on MS Learn.

## Key points

- AL Graph builds call graphs to show caller-callee relationships, external integration points, dependencies and possible security issues.
- The meta model is built once with the 'extract whole' method, stored as JSON and then queried many times.
- The query language can build complex queries, such as callers of an object, methods that interact with tables, or paths from your own sensitive objects. Syntax is documented on MS Learn.
- Query results can be exported as DGML for human analysis of call relationships, or as SARIF, which is flat and meant to be easy for agents to consume.
- An HTTP client caller query lists all callers and the call paths that can reach HTTP requests, which helps audit external integrations.
- The non-debuggable to debuggable boundary audit finds callees of non-debuggable methods. A breakpoint in a debuggable method reached from non-debuggable code can leak secrets.
