# Business Central 2021 release wave 1

> Business Central 2021 release wave 1 (version 18) on-premises upgrade documentation. It answers questions about upgrade paths from versions 14, 15, 16 and 17, C/AL to AL conversion, moving tables between extensions, permission set upgrades and installing a version 18 update.

## Overview

This section covers upgrading on-premises Business Central to 2021 release wave 1 (version 18). The entry page, "Upgrade to Business Central 2021 Wave 1", describes the two main routes: a technical upgrade, or application refactoring to the system application. The compatibility matrix helps check valid upgrade paths between versions.
The path depends on the starting version. From versions 15, 16 or 17 there is a technical upgrade page and a full base application upgrade page. From version 14 there are separate pages for an unmodified C/AL application, a customized C/AL application moving to the Microsoft Base Application, and a general technical upgrade to version 18. A separate page covers installing a version 18 update.
Supporting pages cover code conversion from C/AL to AL with Txt2Al, upgrading permission sets to AL objects, and migrating tables and fields between extensions with migration.json, either down or up the dependency graph. Start with the entry page and the compatibility matrix, then pick the page that matches your source version and level of customization.

## Key points

- Version 18 upgrades can be a technical upgrade or application refactoring to the system application.
- Versions 15, 16 and 17 have a technical upgrade page and a base application upgrade page covering extension publishing, tenant synchronization, data upgrade, control add-ins and license import.
- Version 14 has separate procedures for unmodified C/AL applications (replace the base application with System and Base Application extensions) and customized C/AL applications.
- Customized version 14 upgrades use DestinationAppsForMigration, migration.json and table migration extensions.
- C/AL to AL conversion uses the Txt2Al tool, with notes on .NET interoperability, test libraries and assembly declarations.
- Permissions move from legacy data-based permissions to AL Permission Set and Permission Set Extension objects.
- Table and field moves between extensions use migration.json: one step down the dependency graph, a two-stage transition extension up the graph.
- Installing a version 18 update involves converting databases to the new platform and recompiling extensions, with an optional application update.
