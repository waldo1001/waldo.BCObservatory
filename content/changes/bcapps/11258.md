# #11258 [GB] IdealPostcodes: fix provider selection and address retrieval through the Postcode Service Manager framework

> The IdealPostcodes postcode provider now correctly registers with the Postcode Service Manager framework and retrieves addresses by caching search results and resolving unmapped IDs through the API's resolve endpoint instead of a non-existent fetch endpoint.

[Pull request](https://github.com/microsoft/BCApps/pull/11258) · merged into `main` (BC30) on 2026-10-23 by sergey-idealpostcodes (community contribution) · 6 files (+416 -69), 3 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Fixed provider key registration so the framework correctly recognizes configured IdealPostcodes service
- Address retrieval now uses cached search results instead of making unnecessary API calls
- Unknown address IDs are resolved through the correct resolve endpoint instead of a non-existent route
- New address cache codeunit stores search results for the session to avoid duplicate lookups
- Tests verify correct provider configuration, search result caching, and proper ID resolution
- Behaviour changes for users or extensions.
