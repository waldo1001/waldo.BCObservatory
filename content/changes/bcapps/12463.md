# #12463 Fix Email upgrade writing during no-transaction upgrade test

> Email Installer no longer re-registers email tables based on allowed-table row presence, only checking upgrade tags or forced refresh to prevent unwanted database writes during upgrade tests.

[Pull request](https://github.com/microsoft/BCApps/pull/12463) · merged into `main` (BC30) on 2026-10-07 by darjoo · 1 file (+1 -3), 1 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- Removes the IsAllowedTable trigger that caused unnecessary registration of email tables
- Registration now only occurs when upgrade tags are missing or on forced refresh
- Prevents Retention Policy Log Entry writes that violated no-transaction test requirements
- Tag-based behavior from previous change remains intact
- Users can still refresh allowed tables manually via Retention Policy Setup
