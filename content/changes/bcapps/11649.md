# #11649 [29.x]: When receiving a payment from an SEZ (Special Economic Zone) customer under the "Without Payment of Duty" scenario, GST is being calculated incorrectly in the Bank Receipt Voucher in the Indian version.

> Fixed GST calculation for SEZ customers using the Without Payment of Duty scenario in the Indian Bank Receipt Voucher by triggering tax engine recalculation and correcting the use case configuration to properly zero out IGST and generate required ledger entries.

[Pull request](https://github.com/microsoft/BCApps/pull/11649) · merged into `releases/29.x` (BC29) on 2026-09-22 by v-ajaztabrez · 3 files (+770 -121), 2 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Bank Receipt Voucher now triggers tax engine recalculation when GST Without Payment of Duty is validated
- SEZ General Journal use case updated to calculate zero IGST instead of the previous incorrect value
- GST Posting Setup table metadata and posting-table definitions added to the use case configuration
- Use case version increased to ensure updated configuration is imported during deployment
- GST ledger entries will now be properly generated during posting for this scenario
- Behaviour changes for users or extensions.
