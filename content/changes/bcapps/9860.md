# #9860 [Bug]: [DE] XRechnung/ZUGFeRD - Item Charge lines exported without a valid unit of measure code (BR-CL-23 / BR-23 on BT-130)

> Item charge lines are now correctly exported as allowances or charges in XRechnung and ZUGFeRD documents instead of fabricated invoice lines, with configurable mapping strategies to comply with EN 16931 validation rules.

[Pull request](https://github.com/microsoft/BCApps/pull/9860) · merged into `main` (BC30) on 2026-09-05 by miljance (community contribution) · 21 files (+5873 -54), 14 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Item charges can be classified as document-level or line-level allowances/charges, or as regular lines with unit codes via new Item Charge E-Invoice Mapping enum
- Per-item-charge override configuration added to store mapping type, reason text, reason code, and fallback unit code
- Codeunit resolves export structure automatically based on charge assignment matching, with integration events for customization
- Document and line totals recalculated to maintain monetary accuracy after charges leave the line set
- XRechnung and ZUGFeRD exporters updated to emit charges in appropriate cac:AllowanceCharge or ram:SpecifiedTradeAllowanceCharge structures
- Breaking: existing extensions can stop compiling or working.
