# #12307 Make UpgradeDefaultDimensions ParentId backfill set-based (via DataTransfer)

> The UpgradeDefaultDimensions procedure now uses set-based DataTransfer operations instead of row-by-row processing to backfill ParentId fields in Default Dimension records, significantly reducing upgrade runtime on large tables.

[Pull request](https://github.com/microsoft/BCApps/pull/12307) · merged into `main` (BC30) on 2026-10-05 by dcenic · 8 files (+224 -72), 8 AL · performance · tier official · **unreviewed** (machine-generated)

## What changed

- Replaces per-row Get and Modify operations with four set-based DataTransfer joins (Item, Customer, Vendor, Employee)
- Scopes destination rows by Table ID and blank ParentId to prevent cross-matching between entity types
- Preserves existing behavior while reducing SQL round-trips from millions to a single set-based operation
- Applied consistently across all localization layers (W1, AT, BE, CH, IT, NL, NO, RU)
- Audit fields are intentionally not restamped, consistent with other upgrade DataTransfer operations
