# #13598 Fix concurrent initialization of My Notifications

> My Notifications no longer fails with an 'already exists' error when two sessions of the same user initialize the same notification row at once. The losing session reloads the row the winning session inserted and does not overwrite its saved settings.

[Pull request](https://github.com/microsoft/BCApps/pull/13598) · merged into `main` (BC30) on 2026-11-06 by darjoo · 3 files (+170 -6), 1 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Fixed race condition where concurrent sessions would both find no notification row and attempt to insert, causing the second session to fail with 'already exists' error
- Implemented shared insert-or-get operation for all three default-insert helpers to handle concurrent initialization gracefully
- Added five deterministic regression tests covering all three table helpers and the platform get/set paths with competing row insertions
- Solution avoids locks or commits while ensuring the notification page opens successfully for all concurrent sessions
- Covers platform notification status initialization and table-specific/filtered default helpers
- Behaviour changes for users or extensions.
