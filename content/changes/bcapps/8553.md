# #8553 [Bug][SubscriptionBilling]: Performance: Billing document creation does not scale to large datasets (4M+ subscription lines)

> Billing document creation now scales to millions of subscription lines through code optimizations, database indexes, transaction checkpoints, and progress tracking, eliminating redundant lookups and event dispatch overhead.

[Pull request](https://github.com/microsoft/BCApps/pull/8553) · merged into `main` (BC30) on 2026-07-30 by miljance (community contribution) · 14 files (+770 -170), 14 AL · performance · tier official · **unreviewed** (machine-generated)

## What changed

- New Progress Tracker codeunit provides reusable ETA dialog for long-running operations with Job Queue safety
- Transaction commits added at intervals (per 10 contracts, per document) to prevent timeout on large datasets
- Dictionary-based aggregation and SetLoadFields replace O(n) loops and uncached Gets for performance
- Database indexes added or extended on BillingLine, SubscriptionLine, UsageDataBilling, and related tables
- Removed redundant event subscribers by inlining logic into hot paths to reduce dispatch overhead
