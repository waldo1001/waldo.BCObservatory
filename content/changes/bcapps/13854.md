# #13854 [Main]-All VAT Entries are gone through without filters with "Set G/L Account No." function.

> VAT Entries page and G/L - VAT Reconciliation report now respect user filters and selections when setting G/L Account numbers, preventing unintended updates to all entries in the database.

[Pull request](https://github.com/microsoft/BCApps/pull/13854) · merged into `main` (BC30) on 2026-11-23 by DhavalMore88 (community contribution) · 11 files (+184 -55), 9 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- SetGLAccountNo action now uses SetSelectionFilter to process only selected or filtered VAT entries instead of all entries
- Bucket processing range adjusted to run from first to last selected entry without overlaps
- G/L Account No. adjustments in VAT reconciliation report now apply only to VAT Entry Totaling lines, not Account Totaling lines
- Filter group 10 used for bucket range to prevent overwriting existing selection filters
- Significantly improves performance for large companies with millions of VAT entries
- Behaviour changes for users or extensions.
