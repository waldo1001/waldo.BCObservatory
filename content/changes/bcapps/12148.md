# #12148 [E-Documents Core] [Peppol] - Make PEPPOL Order Response conformant with BIS 28 (T76) and report the seller's decision

> PEPPOL Order Response messages now conform to BIS 28 (T76) standard by including mandatory endpoint identifiers, order lines with status tracking, delivery dates, and seller's actual business decisions on sales orders.

[Pull request](https://github.com/microsoft/BCApps/pull/12148) · merged into `main` (BC30) on 2026-10-16 by GediminasGaubys (community contribution) · 26 files (+2766 -98), 14 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Both parties now get the mandatory cbc:EndpointID with schemeID, echoed from the inbound order or taken from GLN/VAT identification; missing setup raises an error
- Response code follows the seller's decision: AP with no lines when nothing changed, CA with every order line when something changed
- Each line is reported as accepted (5), changed (3), not accepted (7) or added (1), with quantities, net prices and promised delivery periods in the buyer's unit
- Order lines are compared with the sales lines linked via E-Doc. Record Link; Shipment Date and Planned Delivery Date are snapshotted on the draft line
- PEPPOL Order Resp. Builder takes primitives only, Build resets it, and calling SetLine* before AddLine raises an internal error
- Behaviour changes for users or extensions.
