# #13442 [SCM] Post Inventory Cost to G/L: stop using marks, add clean-up for Post Value Entry to G/L

> Report 1002 now stops using marks to delete processed rows and instead filters by value entry numbers, adds automatic cleanup of stale rows, and introduces a new page and report for managing value entries to post to G/L.

[Pull request](https://github.com/microsoft/BCApps/pull/13442) · merged into `main` (BC30) on 2026-11-06 by alexei-dobriansky · 6 files (+1114 -19), 5 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Report 1002 collects processed entries in a temporary table and deletes by filtered ranges instead of using marks, fixing platform issues with row-by-row deletes on large datasets
- Stale rows (fully posted or orphaned entries) are now automatically removed from table 5811 when posting, preventing accumulation that can block future runs
- New page 5813 shows value entries to post to G/L with amounts, accessible from the Inventory Cost Adjustment overview
- New report 5813 allows customers to manually clean up stale rows with a count-only option
- Page 5801 Inventory Cost Adjustment replaces show/hide actions with views and hides obsolete actions
- Behaviour changes for users or extensions.
