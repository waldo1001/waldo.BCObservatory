# #10477 [Bug Fix] #249: Raise populated ErrorInfo for Subscription Billing failures

> Subscription Billing error handlers now raise the fully populated ErrorInfo object instead of plain-text errors, enabling interactive users to navigate to the offending record when document creation fails.

[Pull request](https://github.com/microsoft/BCApps/pull/10477) · merged into `main` (BC30) on 2026-10-23 by ventselartur · 2 files (+28 -2), 1 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- DisplayOrLogErrorFromBillingTemplate and DisplayOrLogErrorFromBillingLine now call Error(ErrorTextInfo) instead of Error(ErrorText)
- The ErrorInfo already held the error type, message, RecordId, SystemId and TableId but was previously discarded
- Interactive users now get an error with a navigation link to the offending Billing Template or Billing Line
- Added a regression test in codeunit 139688 checking that an ErrorInfo-based error is raised
- Automated billing still logs errors without raising an interactive error
- Behaviour changes for users or extensions.
