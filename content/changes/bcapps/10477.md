# #10477 [Bug Fix] #249: Raise populated ErrorInfo for Subscription Billing failures

> Subscription Billing error handlers now raise the fully populated ErrorInfo object instead of plain-text errors, enabling interactive users to navigate to the offending record when document creation fails.

[Pull request](https://github.com/microsoft/BCApps/pull/10477) · merged into `main` (BC30) on 2026-10-23 by ventselartur · 2 files (+28 -2), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Changed DisplayOrLogErrorFromBillingTemplate and DisplayOrLogErrorFromBillingLine to raise Error(ErrorTextInfo) instead of Error(ErrorText)
- ErrorInfo objects are now fully populated with client error type, message, RecordId, SystemId, and TableId for navigation links
- Interactive users can now navigate to the record causing the error instead of receiving a dead-end error message
- Added regression test to verify ErrorInfo is raised correctly for billing failures
- Automated billing continues to log errors without raising interactive errors
- Behaviour changes for users or extensions.
