# #9774 [Extensibility Request] issue 30378: add OnItemVariantOnAfterGetRecordOnBeforePrintOnlyIfSalesCheck event in Item Sales Statistics report

> A new integration event allows extensions to influence whether item variant rows are printed in the Item Sales Statistics report when "Only Items with Sales" and "Breakdown By Variant" are both enabled, by exposing the skip decision and related data to subscribers.

[Pull request](https://github.com/microsoft/BCApps/pull/9774) · merged into `main` (BC30) on 2026-08-27 by AleksandricMarko · 1 file (+12 -6), 1 AL · feature · tier official · **unreviewed** (machine-generated)

## What changed

- New event OnItemVariantOnAfterGetRecordOnBeforePrintOnlyIfSalesCheck fires after Item.CalcFields and before the skip check in the Item Variant OnAfterGetRecord trigger
- Event parameters expose Item, ItemVariant, and the PrintOnlyIfSales flag to subscribers
- Extensions can override the SkipRecord variable via a var parameter to fold in their own sales figures
- Solves the issue that extensions could not influence the row skip decision for custom sales quantities
- Event raised at the variant level, enabling subscribers to control row visibility per variant
- Behaviour changes for users or extensions.
