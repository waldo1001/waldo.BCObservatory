# #14135 [Job Queue] Don't cancel the executed task when scheduling the next run

> When the Job Queue schedules the next run after a successful recurring run or a retry, it no longer sends a platform cancel for the task that is still executing. System Task ID is still cleared, and other task IDs are still cancelled, which cuts redundant cancellation notifications.

[Pull request](https://github.com/microsoft/BCApps/pull/14135) · merged into `main` (BC30) on 2026-11-17 by darjoo · 4 files (+141 -3), 3 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Executed tasks are no longer cancelled when the next run is scheduled
- New internal FinalizeRun overload preserves the executed task ID
- CancelTask still clears System Task ID but skips platform cancel for executing tasks
- Replacement tasks and other scenarios still cancelled as before
- No public API or event signature changes
- Behaviour changes for users or extensions.
