# #14485 [Job Queue] Apply Job Timeout to tasks re-created by the dispatcher

> Job Queue entries are now terminated according to their configured Job Timeout when re-created by the dispatcher, instead of using the platform default 12-hour timeout.

[Pull request](https://github.com/microsoft/BCApps/pull/14485) · merged into `main` (BC30) on 2026-11-27 by darjoo · 3 files (+93 -9), 2 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Reschedule and RescheduleAsWaiting methods now pass the job timeout to CreateTask calls
- New internal GetJobTimeout procedure returns the entry timeout or the default if zero
- Tasks running entries in Waiting state or outside Starting/Ending Time now respect configured timeouts
- Prevents long-running jobs from holding locks past their intended timeout during business hours
- Tests added to verify timeout is applied on both rescheduling paths
- Behaviour changes for users or extensions.
