# #13112  [Main][ALL-E] Canceling a posted purchase invoice fails or misallocates item charges assigned to posted document types other than Purchase ReceiptsInitial commit

> Fixed a bug where canceling a posted purchase invoice could fail or misallocate item charges when those charges were assigned to documents other than Purchase Receipts. The fix ensures all supported document types are handled and correct cost amounts are used.

[Pull request](https://github.com/microsoft/BCApps/pull/13112) · merged into `main` (BC30) on 2026-11-25 by sanjmaurya · 10 files (+982 -124), 8 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Item charge assignments are now recreated for all supported targets (Purchase Receipt, Transfer Receipt, Purchase Return Shipment, Sales Shipment, Sales Return Receipt) during corrective document creation
- Correct cost amount types are applied based on document type: Cost Amount (Non-Invtbl.) for Purchase Return Shipment and Sales Shipment; Cost Amount (Actual) for others
- Rounding adjustments now only affect supported value entries, preventing quantities from shifting to incorrect assignments
- Changes applied across all localization layers (W1, ES, IT, NA, NL, RU)
- Behaviour changes for users or extensions.
