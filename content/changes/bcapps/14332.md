# #14332 Bug 660000: [64bit] Overflow in item application entry

> Some variables in the Item Application Entry table were declared as Integer instead of BigInteger. This happened because a cost calculation optimization crossed the switch to 64-bit integers. They are now BigInteger, which prevents overflow errors.

## What changed

- A cost calculation optimization crossed the move to 64-bit integers and left some variables as Integer
- Those variables in table 339 Item Application Entry now use BigInteger
- Changed in both the W1 and RU layers
- Prevents overflow errors in item application entry processing
- Behaviour changes for users or extensions.
