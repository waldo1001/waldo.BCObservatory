# #14224 Fix duplicate expense vendor numbers during receipt submission

> Expense vendor number assignment now skips occupied numbers and surfaces numbering errors during receipt submission, preventing duplicate vendor key failures.

[Pull request](https://github.com/microsoft/BCApps/pull/14224) · merged into `main` (BC30) on 2026-11-20 by Alexander-Ya · 3 files (+162 -21), 2 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Matched and unmatched expense vendor creation both use the table's insert trigger for consistent numbering logic
- Numbering follows the standard Vendor table pattern to skip already-occupied numbers
- Number-series errors and warnings are no longer suppressed, surfacing actionable errors
- Blank vendor keys from missing error handling are prevented
- Four regression test scenarios validate the fix for normal and sequence series
- Behaviour changes for users or extensions.
