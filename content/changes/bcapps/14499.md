# #14499 Job Queue: resume interrupted finalization on task retry

> When a task is retried after the job already finished but its bookkeeping failed, the Job Queue Dispatcher now completes the pending log entry and runs FinalizeRun instead of exiting. The job is not re-run, and recurring entries no longer stop being scheduled.

[Pull request](https://github.com/microsoft/BCApps/pull/14499) · merged into `main` (BC30) on 2026-11-27 by darjoo · 3 files (+219 -1), 2 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Acts only when a locked re-read shows the entry is still Finished, Manual Recurrence is off, and a log entry for the same System Task ID is In Process or Success
- Sets the pending log entry to Success and calls FinalizeRun, which schedules the next run or deletes a non-recurring entry
- Activates the next waiting job in the same category
- Emits new warning telemetry 0000WW6 (Job queue entry finalization resumed)
- Tests cover rescheduling a recurring entry, deleting a non-recurring entry, and leaving entries untouched when there is no matching log or Manual Recurrence is on
- Behaviour changes for users or extensions.
