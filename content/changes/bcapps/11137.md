# #11137 Composite Report Parts: seed via a report extension instead of install/upgrade code

> Composite report parts are now seeded via a declarative report extension instead of install/upgrade code, removing the need for elevation and simplifying the data model.

[Pull request](https://github.com/microsoft/BCApps/pull/11137) · merged into `main` (BC30) on 2026-09-15 by MSlenejennum · 35 files (+139 -869), 8 AL · refactor · tier official · **unreviewed** (model text not yet checked)

## What changed

- Report extension replaces SeedPart-based install/upgrade code for seeding header/footer designs and themes
- Removes Composite Report Parts Mgt. codeunit, upgrade logic, and associated test suite
- Report part resources moved from .resources to Foundation/Reporting directory
- Platform now owns registering report extension layouts natively
- Eliminates permission-elevation issues from the previous approach
