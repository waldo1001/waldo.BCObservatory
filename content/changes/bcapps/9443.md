# #9443 [Extensibility Request] issue 30222: add handled event before RecreatePurchLines in Pay-to Vendor No. validation

> A new handled integration event OnValidatePayToVendorNoOnBeforeRecreatePurchLines was added to the Pay-to Vendor No. field validation in Purchase Header, allowing extensions to take ownership of purchase line recreation logic instead of being forced to replicate the entire validation trigger.

[Pull request](https://github.com/microsoft/BCApps/pull/9443) · merged into `main` (BC30) on 2026-07-24 by AleksandricMarko · 14 files (+154 -28), 14 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- New integration event raised before RecreatePurchLines call in Pay-to Vendor No. field validation
- Event includes IsHandled flag that allows subscribers to skip the standard recreation logic
- Exposes Rec and xRec parameters for subscribers to access purchase header data
- Applied across all localization layers (W1, APAC, BE, CH, DACH, ES, FI, GB, IT, NA, NL, NO, RU, SE)
- Enables custom purchase line recreation logic that preserves extension-specific information
