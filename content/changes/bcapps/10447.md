# #10447 [Bug][Subscription Billing] Price Update Template filters on Subscription Lines are overwritten by the proposal's own default filters

> Price Update Template filters on Subscription Lines are now correctly preserved instead of being overwritten by default filters. Two defects in the filter application logic were fixed: mandatory filters now use a separate filter group to intersect with template filters, and the Subscription Line record parameter is passed by reference to carry filters correctly.

[Pull request](https://github.com/microsoft/BCApps/pull/10447) · merged into `main` (BC30) on 2026-09-28 by miljance (community contribution) · 2 files (+206 -5), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Mandatory default filters moved to FilterGroup(2) so they intersect with template filters instead of replacing them field by field
- Subscription Line record parameter changed from pass-by-value to pass-by-reference to preserve caller's filters
- Removed dead code checking Closed field since it's now a mandatory default filter
- Added comprehensive tests covering filter preservation, filter intersection, and exclusion scenarios
- Fixes issue where filtered-out subscription lines were still included in price update proposals
- Behaviour changes for users or extensions.
