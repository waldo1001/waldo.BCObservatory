# #12261 Stop repeated rescheduling of Dataverse synch jobs on bulk changes

> The Dataverse synchronization job reschedule logic now checks both the scheduled task's next run time and the job queue entry's earliest start date to avoid repeated rescheduling during bulk changes, reducing unnecessary Service Bus costs.

[Pull request](https://github.com/microsoft/BCApps/pull/12261) · merged into `main` (BC30) on 2026-10-06 by darjoo · 2 files (+117 -17), 1 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- Added guard check for job queue entry's earliest start date in addition to scheduled task's next run time
- Job queue entries are now locked before calling SetTaskReady to serialize concurrent reschedules
- Extracted reschedule logic into testable internal procedure RescheduleJobQueueEntriesForTable
- Production telemetry showed hundreds of reschedule messages per second that have been eliminated
- Tests added to verify correct rescheduling behavior and detect stale task scheduler state
- Behaviour changes for users or extensions.
