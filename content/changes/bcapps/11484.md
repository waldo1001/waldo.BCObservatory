# #11484 [E-Documents Core] - Supported type direction configuration

> E-Document services now support per-document-type direction configuration (Incoming, Outgoing, or Both), allowing administrators to control which document types each service can process and preventing implicit document exchanges.

[Pull request](https://github.com/microsoft/BCApps/pull/11484) · merged into `main` (BC30) on 2026-09-29 by GediminasGaubys (community contribution) · 19 files (+1248 -93), 15 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- Adds Direction field to E-Doc. Service Supported Type table with new closed enum E-Doc. Supp. Type Direction
- Enforces direction restrictions in outbound document creation and inbound processing, logging errors when type direction doesn't match
- Upgrade migration converts existing implicit permissions to explicit direction rows, preserving fallback relationships for seven document types
- Seeds built-in services (PDF reader, ForNAV, Payables Agent, Contoso demo) with minimal Incoming-only supported-type rows
- Optimizes supported-type evaluation with single lookup caching and guards batch export against rejected document types
- Behaviour changes for users or extensions.
