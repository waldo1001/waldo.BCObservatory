# #13499 [Expense Agent] Defer per-diem policy invalidation until the parent line is saved

> Per-diem policy invalidation on expense report lines is deferred until the parent record saves, preventing stale parent buffers when child records are added during bulk generation. Policy state changes are now coalesced into a single version increment rather than multiple invalidations.

[Pull request](https://github.com/microsoft/BCApps/pull/13499) · merged into `main` (BC30) on 2026-11-10 by encimita · 4 files (+561 -12), 3 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Child-record insert/modify/delete triggers retain normal policy invalidation for direct API calls
- Parent invalidation is suppressed only for local child instances used by bulk generation
- Pending child-detail changes are marked on the parent buffer and consumed during parent save
- Policy evaluation confirmation is rejected if pending child changes haven't been saved yet
- Four new tests cover location-triggered generation, child-only regeneration, date-range extension, and pending change validation
- Behaviour changes for users or extensions.
