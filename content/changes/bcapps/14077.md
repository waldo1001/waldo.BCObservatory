# #14077 [Master Data Management] Avoid duplicate excluded record insertion after match-based coupling

> Master Data Management's match-based coupling now handles records excluded by the local table filter correctly by logging an error instead of attempting duplicate creation, preventing misleading insertion failures.

[Pull request](https://github.com/microsoft/BCApps/pull/14077) · merged into `main` (BC30) on 2026-11-24 by dcenic · 3 files (+608 -57), 2 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Match-based coupling repeats lookups without the local filter when no match is found inside the filter, then logs an error pointing to the excluded record
- The local table filter column on Synchronization Tables page is renamed to Local Table Filter and always visible
- Fixed a latent bug where coupling crashed when source and local tables differed due to reading local field numbers from source records
- Wildcard characters in text matching values are now properly escaped to prevent false matches when filter characters appear in source values
- Added MatchExcludedByLocalTableFilter dimension to existing telemetry event 0000J8E to track excluded record scenarios
- Behaviour changes for users or extensions.
