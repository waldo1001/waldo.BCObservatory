# #14077 [Master Data Management] Avoid duplicate excluded record insertion after match-based coupling

> Master Data Management's match-based coupling now handles records excluded by the local table filter correctly by logging an error instead of attempting duplicate creation, preventing misleading insertion failures.

[Pull request](https://github.com/microsoft/BCApps/pull/14077) · merged into `main` (BC30) on 2026-11-24 by dcenic · 3 files (+608 -57), 2 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- If no match is found inside the local filter, match-based coupling repeats the lookup without it, then logs an error pointing to the excluded record instead of coupling it or queuing it for creation
- On the Synchronization Tables page, the Table Filter column is renamed Local Table Filter and is always visible
- Fixed a latent crash on the no-match path when the source and local tables differ
- Text matching values that contain filter characters such as * or ? now keep only exact case-insensitive matches
- Telemetry event 0000J8E gets a new MatchExcludedByLocalTableFilter dimension
- Behaviour changes for users or extensions.
