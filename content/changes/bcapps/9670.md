# #9670 [Main] - Posting from Released production order affects Firm planned production order with same ID.

> A status check was added to prevent Firm Planned production orders from incorrectly reading capacity ledger entries of same-numbered Released orders, which was causing their allocated capacity to be miscalculated.

[Pull request](https://github.com/microsoft/BCApps/pull/9670) · merged into `main` (BC30) on 2026-07-27 by DhavalMore88 (community contribution) · 2 files (+67 -0), 1 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- Added status guard in CalcActuallyPostedCapacityTime that returns 0 for non-Released/Finished statuses
- Prevents Firm Planned, Planned, and Simulated orders from reading capacity ledger entries
- Ensures allocated capacity for Firm Planned orders is calculated correctly as full needed time
- Fixes data corruption where allocated time was wrongly reduced by another order's posted capacity
- Test coverage added for the capacity requirements scenario
- Behaviour changes for users or extensions.
