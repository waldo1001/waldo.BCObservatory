# #11660 Fix #11377: Prevent invalid FatturaPA CAP values

> FatturaPA validation now requires domestic CAP (postal code) values to contain exactly five numeric characters, preventing invalid values like '1234A' from being written to the XML schema.

[Pull request](https://github.com/microsoft/BCApps/pull/11660) · merged into `main` (BC30) on 2026-11-18 by marcus905 (community contribution) · 2 files (+184 -0), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Validates company and domestic customer post codes before FatturaPA document generation
- Enforces five-digit numeric CAP requirement only for domestic Italian addresses
- Foreign recipient behavior unchanged, still emits '00000' for non-Italian postal codes
- Invalid values reported through existing FatturaPA error validation flow
- Standard Post Code field remains unrestricted for normal Business Central use
- Behaviour changes for users or extensions.
