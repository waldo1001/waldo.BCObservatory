# #11612 Multiple runs of email retrieval on the same emails don't persist again

> Email retrieval no longer creates duplicate entries when the same emails are retrieved multiple times. A new centralized FindRetrievedEmail method helps connectors check if an email was already stored, and attachments are added only when needed.

[Pull request](https://github.com/microsoft/BCApps/pull/11612) · merged into `main` (BC30) on 2026-09-21 by mynjj · 7 files (+262 -5), 6 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- The Outlook connector now checks if an email was previously retrieved before persisting it again
- A new centralized FindRetrievedEmail method on the Email module consolidates this logic for all connectors
- Attachments are added to already-retrieved emails only if they weren't previously stored
- A new AddAttachment overload allows adding attachments without triggering validation that prevents modifying received emails
- The fix prevents the email message Modify subscriber from blocking legitimate attachment additions
- Behaviour changes for users or extensions.
