# #9146 [Shopify] Fix GraphQL rate limiter under-waiting after elapsed time

> The Shopify connector's GraphQL rate limiter was waiting incorrectly when time had elapsed between requests, causing it to re-issue requests too early into the throttle window. The fix anchors the wake time to the current moment plus remaining wait time instead of incorrectly subtracting the elapsed gap twice.

[Pull request](https://github.com/microsoft/BCApps/pull/9146) · merged into `main` (BC30) on 2026-07-07 by onbuyuka · 2 files (+27 -2), 1 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- Rate limiter under-waited after elapsed time between Shopify responses and next request, producing avoidable GraphQL throttling on high-volume shops
- Bug was double-subtracting elapsed time when calculating the next request's allowed time
- Fix anchors wake time at CurrentDateTime plus remaining wait instead of anchoring at LastRequestedOn
- Eliminates redundant assignment that subtracted elapsed gap a second time
- Added test case that verifies correct wait time remains when elapsed time has passed since last request
- Behaviour changes for users or extensions.
