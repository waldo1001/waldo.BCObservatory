# #11847 Use matching key for workflow event step instance lookup

> A workflow step instance lookup key is redefined to match the actual filter and sort order, improving query performance from table scans to index seeks on large datasets.

[Pull request](https://github.com/microsoft/BCApps/pull/11847) · merged into `main` (BC30) on 2026-09-25 by darjoo · 2 files (+3 -2), 2 AL · performance · tier official · **unreviewed** (model text not yet checked)

## What changed

- Key6 on Workflow Step Instance table changed from (Type, Status, Function Name, Previous Workflow Step ID) to (Type, Status, Function Name, Sequence No.) with Previous Workflow Step ID as included field
- SetCurrentKey call updated to use the redefined key for proper index selection
- Performance improved from 4.26M logical reads and ~3 seconds to index seeks completing in 13-227ms depending on workload
- Existing lookup behavior preserved; sort order unchanged as records come back ordered by Sequence No. then primary key
- On upgrade, Key6 index is dropped and rebuilt, requiring about 6 seconds per 1M table rows
