# #13630 [NL] Fix CBG applies-to ID length handling

> In the NL CBG Statement Line, New Applies-to ID now returns Code[50] and payment tolerance handling stores the ID as Code[50], matching the existing field length. Longer valid applies-to IDs no longer fail during generation, increment or payment tolerance processing.

[Pull request](https://github.com/microsoft/BCApps/pull/13630) · merged into `main` (BC30) on 2026-11-05 by JesperSchulz · 4 files (+222 -6), 2 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- New Applies-to ID return type and the PmtTolCBGJnl local variable changed from Code[20] to Code[50]
- First bank ID can keep the full 20-character statement document number plus its numeric suffix
- Existing increment, suffix, cash-journal selection and payment tolerance logic are unchanged
- Five tests added covering 10, 20, 21 and 50 character IDs, numeric carry, persistence and payment tolerance
- Existing 10,000-line counter test updated to use a Code[50] variable
- Behaviour changes for users or extensions.
