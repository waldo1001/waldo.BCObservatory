# #9313 [Shopify] Fix Product Sync deleting mapped variants on stale Updated At timestamp

> The Shopify variant sync now correctly distinguishes between variants that have stale local timestamps (should be kept) and variants deleted on Shopify (should be removed), preventing incorrect deletion of mapped variants during asynchronous bulk operations.

[Pull request](https://github.com/microsoft/BCApps/pull/9313) · merged into `main` (BC30) on 2026-07-13 by onbuyuka · 2 files (+154 -6), 1 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- RetrieveShopifyVariant now returns true when the Shopify variant exists regardless of timestamp comparison, and false only when the variant is genuinely absent
- UpdateShopifyVariantFields no longer returns a Boolean since the timestamp guard skip is no longer interpreted as a deletion signal
- Fixed a logic conflict where skipping a field update due to a stale local timestamp was incorrectly treated as evidence the variant was deleted on Shopify
- Added comprehensive unit tests using HttpClientHandler mocking to verify correct behavior for both stale timestamps and actual deletions
- Behaviour changes for users or extensions.
