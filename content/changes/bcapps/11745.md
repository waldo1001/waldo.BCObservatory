# #11745 Bug 648781: check the party identifier that the PEPPOL export will use

> PEPPOL validation now uses the same party identifier provider as export to ensure EndpointID is never empty, fixing cases where validation passed but export created invalid documents.

[Pull request](https://github.com/microsoft/BCApps/pull/11745) · merged into `main` (BC30) on 2026-09-25 by Explorer986 · 7 files (+543 -19), 5 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Validation and export now use the same party identifier source instead of different logic
- Purchase order validation now covers all document types instead of missing the Purchase Header branch
- Users receive clear error messages indicating which settings need adjustment when EndpointID cannot be determined
- Documents that previously exported invalid empty EndpointID values are now caught during validation
- PEPPOL 3.0 Setup provider is consulted at validation time instead of hardcoding identifier logic
- Behaviour changes for users or extensions.
