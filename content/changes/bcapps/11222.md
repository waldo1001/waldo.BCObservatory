# #11222 Improve Low-Level Code Calculator performance

> Low-Level Code Calculator performance improved by filtering out items without a Production BOM and replacing a List with a Dictionary for node key tracking, reducing calculation time significantly in real-world scenarios.

[Pull request](https://github.com/microsoft/BCApps/pull/11222) · merged into `main` (BC30) on 2026-10-26 by duiliotacconi (community contribution) · 1 file (+15 -9), 1 AL · performance · tier official · reviewed (checked by Opus)

## What changed

- Production BOM query now filters for non-empty BOM numbers before opening
- NodeKeysAddedToTree changed from List to Dictionary to improve lookup and insert performance from O(n) to near-constant
- Eliminates unnecessary cache invalidation and item loading for items without Production BOMs
- New extensibility point OnBeforeItemProductionBOMsOpen added to allow query customization
- Combined changes reduced calculation time from 10 hours to 2 hours in tested scenario
