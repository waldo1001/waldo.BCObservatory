# #9531 [Master]- Report 152 "Calculate Low Level Code" terminates with error: "Cannot add instance as another with key %1 has already been added." after upgrade to v28.1

> Report 152 now correctly handles items with multiple SKUs sharing the same Production BOM by replacing enumeration-based lookup with a direct dictionary key search in the BOM tree node logic.

[Pull request](https://github.com/microsoft/BCApps/pull/9531) · merged into `main` (BC30) on 2026-07-17 by DhavalMore88 (community contribution) · 4 files (+72 -8), 3 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Fixed a regression where Report 152 crashed when an item and its SKUs referenced the same Production BOM
- Changed IsChild procedure from enumeration-based to O(1) key lookup to avoid leaving the shared enumerator in an incorrect state
- Added regression test for items with multiple SKUs sharing one Production BOM
- The issue occurred because exiting mid-enumeration left the shared enumerator stranded, preventing duplicate detection
- Behaviour changes for users or extensions.
