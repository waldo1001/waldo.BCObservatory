# #8556 [Quality Management] Enforce rules and restrictions with indirect and implicit permissions

> Quality Management now uses InherentPermissions to enforce rules when inspections are automatically created, requiring users to hold the new QltyMgmt - I. Create permission set if generation rules are triggered, preventing silent failures.

[Pull request](https://github.com/microsoft/BCApps/pull/8556) · merged into `main` (BC30) on 2026-07-08 by JakovljevicDusan · 31 files (+373 -103), 29 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- InherentPermissions added to Quality Inspection Setup and Generation Rule tables to control access
- New QltyMgmt - I. Create permission set grants indirect permissions for inspection creation
- Users without QM permissions get standard permission errors instead of silent skips when generation rules trigger
- Automatic inspection creation checks setup and rules before requiring permissions
- Create Quality Inspection actions use AccessByPermission to hide views from users with only creation permissions
- Behaviour changes for users or extensions.
