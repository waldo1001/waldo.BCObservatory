# #10295 #10288 - Always load attachments

> Email retrieval from Outlook now processes inline attachments that were previously skipped because they don't set the `hasAttachments` flag on Graph messages.

[Pull request](https://github.com/microsoft/BCApps/pull/10295) · merged into `main` (BC30) on 2026-11-20 by g-Bergsma (community contribution) · 4 files (+217 -6), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Removes the `hasAttachments` gate that prevented processing of inline-only attachments
- Attachments are now always processed when present in the response, with inline/regular distinction applied via `isInline` and `contentId`
- Backfills previously retrieved emails with inline attachments when Load Attachments is enabled later
- No extra Graph API calls; uses existing `$expand=attachments` when enabled
- Duplicate prevention and message tracking behavior preserved
- Behaviour changes for users or extensions.
