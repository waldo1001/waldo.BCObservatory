# #12813 [GB] Fix reverse charge VAT sales posting

> GB reverse-charge VAT sales posting now correctly handles zero-quantity lines and uses line-based applicability checks instead of header-copied state, with legacy item validation isolated behind the feature flag.

[Pull request](https://github.com/microsoft/BCApps/pull/12813) · merged into `main` (BC30) on 2026-10-20 by ventselartur · 5 files (+417 -17), 4 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Fixed reverse-charge calculation to skip zero-quantity sales lines during posting
- Changed applicability checks to read from the sales line's posting state rather than a copied header
- Isolated legacy item flag validation behind the reverse-charge feature status to preserve backward compatibility
- Added eight regression test scenarios covering feature states, conflicting setups, partial invoicing, thresholds, and edge cases
- Behaviour changes for users or extensions.
