# #14344 [SOA] Keep setup buffer current after instruction sync (AB#660003)

> The SOA Setup timestamp helper now saves through the caller's buffer instead of a separate record, ensuring the row version stays current and preventing stale-record errors during scheduling.

[Pull request](https://github.com/microsoft/BCApps/pull/14344) · merged into `main` (BC30) on 2026-11-20 by qasimikram · 1 file (+2 -2), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Fixed stale-record error 85132286 that could occur when ScheduleSOAgent tried to modify an outdated SOA Setup record
- Timestamp helper now persists to the existing caller's buffer instead of a separate CurrentSOASetup record
- Prevents the caller's row version from becoming stale after instruction sync updates
- Maintains optimistic concurrency and avoids unnecessary reloads of pending values
- Preserves existing behavior for missing-record checks, scheduling logic, and 30-minute refresh intervals
