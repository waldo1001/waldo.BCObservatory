# #12696 Fix Norwegian SAF-T 1.30 debit and credit totals

> Norwegian SAF-T 1.30 export now correctly calculates debit and credit totals from actual G/L entry amounts instead of stored columns, ensuring totals match exported line amounts even with reversals or negative entries.

[Pull request](https://github.com/microsoft/BCApps/pull/12696) · merged into `main` (BC30) on 2026-10-28 by AleksanderGladkov · 5 files (+248 -8), 3 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Debit and credit totals in SAF-T 1.30 now calculated from G/L Amount using SQL aggregation instead of stored debit/credit columns
- Fixes discrepancies when exports contain reversals or negative entries
- Complete selection totals are repeated in every split file for consistency
- SAF-T 1.20 behavior remains unchanged
- Extensive test coverage added for reversals, negative entries, multiple journals, and split scenarios
- Behaviour changes for users or extensions.
