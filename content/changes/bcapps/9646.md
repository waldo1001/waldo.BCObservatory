# #9646 [Bug]: [DE] XRechnung/ZUGFeRD — no posting-time error when SELLER CONTACT (BG-6) source data is incomplete, producing non-compliant e-invoices

> E-Document posting now validates that seller contact information (from salesperson or company data) is complete before generating XRechnung/ZUGFeRD e-invoices, preventing non-compliant XML that would fail validation.

[Pull request](https://github.com/microsoft/BCApps/pull/9646) · merged into `main` (BC30) on 2026-09-22 by miljance (community contribution) · 5 files (+717 -0), 3 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- New mandatory check for seller contact fields (name, phone, email) during e-document posting
- Validation mirrors the export logic by checking salesperson first, then falling back to company information
- Error messages identify which field is missing and from which source it was expected
- Applies to both XRechnung and ZUGFeRD formats with dedicated test coverage for each
- Existing documents with incomplete contact data will now fail to post
- Breaking: existing extensions can stop compiling or working.
