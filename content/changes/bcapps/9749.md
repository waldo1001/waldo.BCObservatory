# #9749 OIOUBL fixes after schematron update

> OIOUBL export now correctly handles discounts by reporting them with proper VAT categories per tax type instead of using a synthetic ReverseCharge, ensuring compliance with updated schematron validation rules.

[Pull request](https://github.com/microsoft/BCApps/pull/9749) · merged into `main` (BC30) on 2026-08-10 by mynjj · 10 files (+817 -347), 8 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Discounts are now exported with the correct VAT category matching each line's tax type instead of always using ReverseCharge
- Tax totals and subtotals are now split per VAT category to match all reported tax categories
- Line-level taxable amounts are reported before discounts to allow header-level allowances to subtract correctly
- Header-level allowance charges are now emitted multiple times per VAT type pair instead of a single ReverseCharge entry
- Validation against the OIOUBL schematron now passes for documents with header or line discounts
- Behaviour changes for users or extensions.
