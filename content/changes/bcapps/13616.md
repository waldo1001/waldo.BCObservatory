# #13616 [main] but 657849 - Refactor TableRelation logic and disable validation for Bank Account fields in multiple table extensions

> SWIFT Code validation is made consistent across Czech localization by disabling table relation validation on SWIFT fields in purchase and sales headers and ledger entries, allowing codes not in the SWIFT Code table to work like bank accounts do.

[Pull request](https://github.com/microsoft/BCApps/pull/13616) · merged into `main` (BC30) on 2026-11-09 by DavidHolusa · 4 files (+12 -20), 4 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Disables ValidateTableRelation for SWIFT Code fields in purchase headers, sales headers, vendor ledger entries, and customer ledger entries
- Allows SWIFT codes that don't exist in the SWIFT Code table to be used, consistent with vendor bank account behavior
- Fixes an issue where Update Document action on posted purchase invoices failed when changing unrelated fields like Constant Symbol
- Table relations are retained but validation is disabled
- Applies only to Czech Core Localization Pack extensions
- Behaviour changes for users or extensions.
