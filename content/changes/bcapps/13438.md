# #13438 Fix Cloud Migration recovery when Tenant Media is unavailable

> Cloud migration recovery now handles Tenant Media read failures gracefully by using a shared try function that logs skipped checks and preserves saved counts, allowing replication to complete and retry instead of aborting.

[Pull request](https://github.com/microsoft/BCApps/pull/13438) · merged into `main` (BC30) on 2026-11-04 by onbuyuka · 4 files (+129 -6), 2 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Shared read-only try function for media counts prevents replication webhook abort when table access fails
- Unavailable counts are logged and skipped rather than causing failure
- Previous media counts are preserved across retry attempts
- Added regression tests for normal comparisons, unavailable counts, and retry scenarios
- No schema or public API changes
- Behaviour changes for users or extensions.
