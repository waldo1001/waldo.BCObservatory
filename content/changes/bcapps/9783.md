# #9783 [Master] Purchase Return Order Posting Fails for Manually Reserved Lot-Tracked Items with Exact Cost Reversing Mandatory Enabled: "Applies-to Entry must not be filled out when reservations exist in Item Ledger Entry Entry No.='XXX'"

> Purchase return order posting now correctly handles manually reserved lot-tracked items when exact cost reversing is mandatory by automatically deriving the applies-to entry from the existing reservation during posting.

[Pull request](https://github.com/microsoft/BCApps/pull/9783) · merged into `main` (BC30) on 2026-07-31 by Shikhverma · 3 files (+121 -5), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Fixes posting failure for lot-tracked purchase returns with manual reservations when exact cost reversing mandatory is enabled
- Automatically restores the exact-cost reversing link from the reserved item ledger entry when applies-to entry is blank
- Eliminates the need for manual intervention to fill the applies-to entry when a return line is fully reserved
- Preserves reservation integrity throughout the posting process
- Added test coverage for this specific scenario
- Behaviour changes for users or extensions.
