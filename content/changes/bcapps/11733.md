# #11733 Fix external storage migration for unsafe attachment filenames

> Attachments with unsafe filenames now migrate to external storage because generated storage paths are sanitized while displayed names stay unchanged. Each sync step runs in isolation so one failure rolls back only that step, failures are registered per attachment, and the app no longer deletes remote files, only retiring local references under a guard.

[Pull request](https://github.com/microsoft/BCApps/pull/11733) · merged into `main` (BC30) on 2026-10-09 by darjoo · 15 files (+1544 -164), 9 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Generated storage filenames are sanitized; displayed File Name and File Extension are unchanged
- Each synchronization step runs through a worker; failures roll back that step and processing continues
- Failed attachments are registered locally; interactive runs show Error Messages, background runs do not fail the job queue entry
- Uploaded files are retained after failed persistence and their logical paths recorded for recovery
- All remote deletion calls are removed; local references are retired only under a guarded check
- Behaviour changes for users or extensions.
