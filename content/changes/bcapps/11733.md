# #11733 Fix external storage migration for unsafe attachment filenames

> Fix external storage migration of document attachments with unsafe filenames by sanitizing paths while retaining uniqueness and preserving displayed names.

[Pull request](https://github.com/microsoft/BCApps/pull/11733) · merged into `main` (BC30) on 2026-10-09 by darjoo · 15 files (+1544 -164), 9 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Filenames like 'Invoice Nov'25.pdf' that violate storage validation are now sanitized without changing displayed File Name or extension
- Failed attachment synchronizations are isolated and roll back individual steps while processing continues
- Remote deletion calls are eliminated; worker explicitly uses RetireExternalReference for local reference retirement only
- Failed attachments are registered locally and can be recovered; interactive and background runs handle errors differently
- Added extensive test coverage for restored, external-only, and stale file scenarios
- Behaviour changes for users or extensions.
