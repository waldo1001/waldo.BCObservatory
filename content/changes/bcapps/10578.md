# #10578 [Extensibility Request] issue 30429: add events to disambiguate CRM integration table mappings

> Four integration events are added to allow extensions to select the correct CRM integration table mapping when multiple mappings share the same table ID, enabling proper disambiguation in order-status updates, coupling, uncoupling, and match-based coupling scenarios.

[Pull request](https://github.com/microsoft/BCApps/pull/10578) · merged into `main` (BC30) on 2026-08-28 by onbuyuka · 3 files (+25 -0), 3 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- Four new IntegrationEvent publishers added: OnUpdateSalesOrdersOnBeforeFindIntegrationTableMapping, OnAfterInitialize, OnRemoveCouplingOnBeforeGetIntegrationTableMappingForUncoupling, OnMatchBasedCouplingOnBeforeGetIntegrationTableMappingForMatchBasedCoupling
- Events use read-only RecordRef parameters to allow subscribers to inspect source records without mutating caller state
- Addresses scenario where extensions have multiple same-table mappings (e.g., Sales Header quotes alongside standard orders)
- Thin event publishers marked with [IntegrationEvent(false, false)]
- Enables correct mapping resolution during CRM sync operations
