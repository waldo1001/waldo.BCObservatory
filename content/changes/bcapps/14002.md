# #14002 External File Storage: reject "." and ".." path segments

> External File Storage now rejects any path where a whole segment is "." or "..", for all operations and connectors, so calls like DeleteDirectory('A/B/..') no longer act on folder A. Dots inside names stay valid. Callers that pass relative segments now get an error.

[Pull request](https://github.com/microsoft/BCApps/pull/14002) · merged into `main` (BC30) on 2026-11-16 by jorisvanduyse (community contribution) · 2 files (+96 -0), 1 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- CheckPath in External File Storage Impl. rejects whole "." or ".." segments with a new error
- Stops connectors such as SharePoint from resolving relative segments and acting on the wrong folder
- Dots inside names, such as v1..2.pdf, ..hidden or a., remain valid
- Public API behavior change: try functions return false for such paths, so outside callers must pass normalized paths
- New test codeunit 134754 File Storage Path Test covers the rejected and allowed cases
- Breaking: existing extensions can stop compiling or working.
