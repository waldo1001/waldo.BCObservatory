# #11517 [29.x]-export/import of a report definition fails if the statuses in the originating company do not exist in the destination company

> Exporting and importing financial report definitions across companies no longer fails when status values don't exist in the destination company. Status fields in the imported definition are cleared to allow successful import.

[Pull request](https://github.com/microsoft/BCApps/pull/11517) · merged into `releases/29.x` (BC29) on 2026-09-21 by DhavalMore88 (community contribution) · 10 files (+808 -0), 4 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Added a procedure to clear non-existing status values from imported packages before applying them
- Status codes are company-specific and are not included in exports, causing validation failures
- Imported row definitions now accept empty status values that users can set after import
- Fixes import failure when destination company lacks financial report statuses from source company
- Added test cases across multiple localization layers to verify the fix
- Behaviour changes for users or extensions.
