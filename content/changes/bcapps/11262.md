# #11262 Fix retention policy deletion-limit stop propagation

> The retention policy deletion limit now stops further policy processing correctly by propagating the stop flag through the temporary setup record after each policy runs, preventing additional limit events after the batch should have ended.

[Pull request](https://github.com/microsoft/BCApps/pull/11262) · merged into `main` (BC30) on 2026-09-23 by darjoo · 3 files (+105 -0), 2 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- The `EndCurrentRun` flag is now transported through the temporary retention policy setup record instead of being lost during isolated codeunit execution
- The outer loop can now check the stop condition after each policy completes instead of continuing blindly
- Per-policy error isolation is preserved while allowing proper batch termination
- Added regression test cases covering limit boundary conditions and multiple runs
- No changes to event signatures, scheduling, or the deletion allowance configuration
- Behaviour changes for users or extensions.
