# #13579 Fix synchronization error event record context

> The LogSynchError method in Integration Synch. Job Errors table now passes the newly inserted error record to the OnAfterLogSynchError event instead of the ambient record, allowing subscribers to receive the correct error data. Two regression tests were added to verify the fix.

[Pull request](https://github.com/microsoft/BCApps/pull/13579) · merged into `main` (BC30) on 2026-11-05 by JesperSchulz · 2 files (+104 -2), 1 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- LogSynchError passes the populated, inserted IntegrationSynchJobErrors record to OnAfterLogSynchError event
- Subscribers now receive the newly logged error instead of empty or unrelated caller record
- Two regression tests added covering empty and existing caller record contexts
- Tests verify event invocation, entry numbers, job/source/destination IDs, messages, timestamp, and exception details
- No new infrastructure or country-layer overrides required
- Behaviour changes for users or extensions.
