# #9987 Fix Payment Management FR data update paths and per-company feature status

> Centralizes the French payment data migration in a new codeunit so the Feature Management path also remaps payment step object IDs, and adds an upgrade tag to repair companies migrated before remapping existed. Feature status is no longer copied to every company after a data update, in the Payment Management FR app and the three GB apps.

[Pull request](https://github.com/microsoft/BCApps/pull/9987) · merged into `main` (BC30) on 2026-08-18 by ventselartur · 7 files (+332 -389), 7 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- New codeunit 10844 holds the single migration implementation, so the Feature Management data update also remaps object IDs
- Separate upgrade tag for remapping repairs companies that migrated before remapping was added
- Removed cross-company ModifyAll from AfterUpdate in the FR and GB feature codeunits that wrongly marked other companies as Complete
- Fixed bank account field transfer direction so RIB data moves from base application fields into the app fields
- Data update check now counts all migrated tables and no longer writes upgrade tags
- Behaviour changes for users or extensions.
