# #9988 [Expense Agent] Fix Employee subscriber permissions

> Expense Agent permissions are restructured to isolate API access, making subscriber permissions mandatory for Employee synchronization and deletion, while narrowing agent-facing APIs to an agent-only permission set.

[Pull request](https://github.com/microsoft/BCApps/pull/9988) · merged into `main` (BC30) on 2026-08-13 by t-prda · 8 files (+361 -4), 3 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- New entitlement 'EA - Azure AD Application API' grants Expense Agent application API.ReadWrite.All access mapped to 'Expense Mgmt. Edit'
- Employee event subscribers now have method-scoped inherent permissions for synchronization and deletion logic
- Internal APIs (Expense Capabilities, Expense Projects, and Expense Project Tasks Query) moved to agent-only 'Expense Agent - Objects' permission set
- Existing customer and partner Employee permission sets unaffected by changes
- Comprehensive test suite added covering synchronization, deletion guards, and multiple permission profiles
- Behaviour changes for users or extensions.
