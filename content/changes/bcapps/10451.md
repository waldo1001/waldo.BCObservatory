# #10451 [Bug 647233] Fix User Confirmed copied into Canceled when posting expense report lines

> Fixed a data corruption bug where the User Confirmed field from expense report lines was being incorrectly copied into the Canceled field of posted expense report lines during posting, by introducing a new non-colliding field and adding data migration logic.

[Pull request](https://github.com/microsoft/BCApps/pull/10451) · merged into `main` (BC30) on 2026-08-24 by v-rohangarg20 · 4 files (+119 -3), 3 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- The Canceled field in Posted Expense Report Line had the same field number (92) as User Confirmed in Expense Report Line, causing silent data corruption via TransferFields mapping
- Field 92 (Canceled) was obsoleted and replaced with new field 94 (Is Canceled) to eliminate the collision
- Upgrade logic was added to migrate existing data from the old field 92 to a temporary storage field 999 during module upgrade
- The Cancel Posted Expense Report codeunit was updated to use the new Is Canceled field
- Regression tests were added to prevent this issue from recurring
- Breaking: existing extensions can stop compiling or working.
