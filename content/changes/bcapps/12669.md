# #12669 [Main]Subcontracting Order Date does not account for lead time before the routing operation starts

> Subcontracting order dates now correctly calculate backward from the routing operation start date using the purchase lead time, and prices are refreshed when the order date changes on existing orders.

[Pull request](https://github.com/microsoft/BCApps/pull/12669) · merged into `main` (BC30) on 2026-10-14 by sanjmaurya · 6 files (+309 -13), 5 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Order Date calculation now accounts for purchase lead time from routing start date
- SetSubcontractingOrderDate method added to handle consistent date logic across Calculate Subcontracts and direct routing creation flows
- Carry Out Action no longer overwrites worksheet dates with purchase header order date for subcontracting lines
- Price refresh logic improved to treat pre-price fallback costs as automatic so correct prices apply to the calculated order date
- Expected and Requested Receipt Dates also set correctly on new and rescheduled purchase lines
- Behaviour changes for users or extensions.
