# #11896 [Master Data Management] Cross-env over-cap blob clears the subsidiary blob

> In cross-environment Master Data Management sync, a source blob over 512 KB is no longer sent inline, and now a skip marker keeps the existing destination blob instead of clearing it. The inline media cache now uses last-write-wins per record and field, so the newest media state is applied.

[Pull request](https://github.com/microsoft/BCApps/pull/11896) · merged into `main` (BC30) on 2026-09-28 by dcenic · 5 files (+833 -3), 3 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- Source blobs over 512 KB are not sent inline, which previously cleared the destination blob
- A skip marker carried from materialization to transfer keeps the destination blob unchanged
- Inline media cache is last-write-wins per (SystemId, field) for records arriving on several pages in one batch
- Regression tests added for both cases
- Forward-port of a 29.x fix
- Behaviour changes for users or extensions.
