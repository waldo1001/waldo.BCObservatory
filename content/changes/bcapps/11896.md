# #11896 [Master Data Management] Cross-env over-cap blob clears the subsidiary blob

> Master Data Management now correctly preserves destination blobs when source blobs exceed capacity limits, and improves inline media cache handling to apply the newest media state for records arriving on multiple pages.

[Pull request](https://github.com/microsoft/BCApps/pull/11896) · merged into `main` (BC30) on 2026-09-28 by dcenic · 5 files (+833 -3), 3 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Over-capacity source blobs (>512 KB) are skipped during transfer; a marker prevents clearing the destination blob instead of leaving it empty
- Inline media cache now uses last-write-wins logic per (SystemId, field) to handle records with multiple pages in one batch
- Destination blobs remain unchanged when source is over-capacity rather than being cleared by empty temp values
- Regression tests added to cover both the skip marker behavior and media state application scenarios
- Forward-port of a 29.x fix to 30.x
- Behaviour changes for users or extensions.
