# #13824 Implement namespace normalization for Fabric Data and Logging in setup pages and platform management

> Fabric namespace fields on the setup pages and API now convert entered values to lowercase on validation, and new setup records default to businesscentral and businesscentral_log. This avoids casing mismatches in Fabric landing zone folder paths. Existing stored values are not renamed.

[Pull request](https://github.com/microsoft/BCApps/pull/13824) · merged into `main` (BC30) on 2026-11-12 by Bertverbeek4PS (community contribution) · 4 files (+111 -12), 3 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- Namespace values entered through the Fabric setup pages or API are lowercased on validation
- New setup records use lowercase defaults businesscentral and businesscentral_log
- Existing stored namespace values are not migrated, so exported tables, reports and models are not disrupted
- Direct AL writes that bypass the page validation can still store uppercase values
- Tests cover the lowercase defaults and the namespace normalization
- Behaviour changes for users or extensions.
