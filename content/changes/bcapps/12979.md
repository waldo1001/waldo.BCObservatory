# #12979 [Main] Consistent Error Posting GST Distribution Reversal

> GST Distribution Reversal posting now correctly handles rounding differences when distributed GST amounts contain decimals, applying the rounding adjustment to the first matching component line credit amount.

[Pull request](https://github.com/microsoft/BCApps/pull/12979) · merged into `main` (BC30) on 2026-10-26 by Shikhverma · 1 file (+77 -20), 1 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- GST amounts are rounded per component line during distribution, creating rounding differences
- Normal distributions apply rounding difference to the debit amount, but reversals did not
- Reversals failed because total credit amounts differed from original GST amount by the rounding difference
- Solution applies the same rounding logic to reversals by adding the difference to the first matching component line credit amount
- Whole amount reversals were not affected and continue to work
- Behaviour changes for users or extensions.
