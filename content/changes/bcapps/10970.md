# #10970 [Master] -SubBilling BillingLine doesn't consider entries for usage date ranges crossing periods

> Fixed subscription billing to correctly include usage data entries whose charge periods span across billing rhythm periods, preventing lost billing and reconciliation errors.

[Pull request](https://github.com/microsoft/BCApps/pull/10970) · merged into `main` (BC30) on 2026-09-11 by DhavalMore88 · 3 files (+321 -0), 2 AL · fix · tier official · **unreviewed** (model text not yet checked)

## What changed

- Usage entries that span multiple billing periods are now captured entirely in one billing line
- New GetUsageDataChargeEndDateCrossingPeriodEnd method detects entries crossing period boundaries
- Billing period is extended to encompass crossing entries using CalculateNextBillingToDateForServiceCommitment
- Prevents duplicate billing lines by starting the next period after the stretch point
- Resolves reconciliation issues between billing lines and usage data totals
- Behaviour changes for users or extensions.
