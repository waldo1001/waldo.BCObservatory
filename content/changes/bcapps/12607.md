# #12607 [BE] Improve Purchase Ledger report performance

> The Belgian Purchase Ledger report now uses a single left-joined query with temporary buffering instead of per-entry lookups to reduce database calls and improve performance.

[Pull request](https://github.com/microsoft/BCApps/pull/12607) · merged into `main` (BC30) on 2026-10-22 by dcenic · 4 files (+275 -3), 3 AL · performance · tier official · **unreviewed** (model text not yet checked)

## What changed

- Replaces multiple per-entry VAT link queries and VAT Entry.Get calls with one left-joined query per journal template and period
- Introduces an internal temporary buffer table and query to aggregate results
- Filters on G/L entry dates rather than VAT entry dates to avoid filtering assumptions
- Uses SetLoadFields and SetAutoCalcFields optimizations for supporting lookups
- Maintains existing error handling and currency display behavior
