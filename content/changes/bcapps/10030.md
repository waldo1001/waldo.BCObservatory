# #10030 [main]planning worksheet requires second runof calculate regenerative plan

> The low-level code calculation engine now processes SKU-level production BOMs correctly, ensuring planning worksheets generate all required planning lines in a single run for multi-level assemblies when BOMs are defined at the SKU level rather than the item card.

[Pull request](https://github.com/microsoft/BCApps/pull/10030) · merged into `main` (BC30) on 2026-08-27 by Shikhverma · 3 files (+241 -2), 2 AL · fix · tier official · **unreviewed** (machine-generated)

## What changed

- CalcLevels procedure now traverses SKU-level BOMs in addition to item-card BOMs when computing low-level codes
- New RecalcSKULowerLevels procedure propagates low-level codes downward through SKU-referenced BOMs
- SKU Production BOM No. OnValidate now persists the recalculated low-level code instead of only computing it
- Eliminates the need for users to run Calculate Regenerative Plan twice for SKU-only multi-level BOM structures
- Behaviour changes for users or extensions.
