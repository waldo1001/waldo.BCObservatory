# #148 Add Job Queue reliability and scheduling guidance

> Six new performance guidance articles document reliability and scheduling practices for Job Queue and Task Scheduler workloads, including idempotency requirements, UI independence, failure propagation, category-based serialization, on-hold behavior, and duplicate task prevention.

[Pull request](https://github.com/microsoft/BCQuality/pull/148) · merged into `main` on 2026-09-14 by demiliani · 24 files (+574 -25), 21 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- Require external side effects in Job Queue handlers to be idempotent across retries using unique idempotency keys
- Job Queue handlers must be independent of client UI and operate in background sessions
- Execution failures must propagate so the dispatcher can log and retry according to configuration
- Use Job Queue Category Code to serialize jobs that require mutual exclusion
- Putting an entry on hold prevents future runs but does not stop currently executing work, requiring cooperative cancellation
