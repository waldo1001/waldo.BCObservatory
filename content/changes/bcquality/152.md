# #152 knowledge(events): ChangeCompany leaves triggers and trigger-event subscribers running in the calling company

> A knowledge article documents that ChangeCompany does not move trigger execution context to the target company; triggers and trigger-event subscribers still run in the calling company. StartSession is recommended for cross-company operations that require proper trigger handling.

[Pull request](https://github.com/microsoft/BCQuality/pull/152) · merged into `main` on 2026-09-15 by waldo1001 · 4 files (+219 -1), 4 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- ChangeCompany redirects only the data access of a record variable
- Triggers, field validation and database trigger-event subscribers keep running in the calling company
- Passing RunTrigger false skips trigger code, but subscribers still receive the trigger events
- The recommended approach is StartSession with the company parameter, so the code runs in the target company
- Direct cross-company writes should be limited to trigger-free hand-off tables owned by the extension
