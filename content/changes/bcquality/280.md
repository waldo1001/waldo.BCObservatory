# #280 knowledge(testing): ExpectedError must identify the intended error

> The testing knowledge article on assertion errors now clarifies that ExpectedError and ExpectedErrorCode match by substring, and adds guidance to avoid weak verification patterns that cannot distinguish between different errors.

[Pull request](https://github.com/microsoft/BCQuality/pull/280) · merged into `main` on 2026-11-19 by MichaelDieringer · 1 file (+2 -2), 1 AL · other · tier official · **unreviewed** (model text not yet checked)

## What changed

- Both ExpectedError and ExpectedErrorCode match only by substring, not exact match
- Best practice is to use full error labels built with StrSubstNo to uniquely identify intended errors
- ExpectedErrorCode alone only identifies the error kind, not the specific error message
- Anti-patterns include using ExpectedErrorCode alone, GetLastErrorText(), or error fragments that appear in multiple messages
- Tests using weak patterns may stay green when wrong errors fire instead of the intended one
