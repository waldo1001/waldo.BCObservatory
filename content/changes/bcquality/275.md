# #275 knowledge(performance): Get behind a key-is-set check in and-condition wastes a DB call

> The performance rule for boolean operators now detects when Record.Get() calls happen behind a key-is-set check in an and-condition, which can be wasteful even though it is not unsafe.

[Pull request](https://github.com/microsoft/BCQuality/pull/275) · merged into `main` on 2026-11-18 by pri-kise · 3 files (+27 -2), 3 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- Extends detection to identify Record.Get() calls guarded by key-is-set checks (like Key <> 0 or Key <> '')
- Recommends moving the guard clause before the Get() call to avoid unnecessary database operations
- Applies when only a field value or default is returned and the guard intentionally means the key is not set
- Updated with code samples in both bad and good AL patterns
- Provides best practice guidance for conditional record retrieval
