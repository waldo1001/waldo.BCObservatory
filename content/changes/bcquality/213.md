# #213 knowledge(events): database trigger setup flags may only be set to true

> Adds a knowledge article and review check: subscribers to GetDatabaseTableTriggerSetup (Global Triggers) or OnAfterGetDatabaseTableTriggerSetup (codeunit 49) should only set the shared trigger flags to true. Assigning false or a lookup result can clear flags that other features or apps rely on.

[Pull request](https://github.com/microsoft/BCQuality/pull/213) · merged into `main` on 2026-10-05 by MichaelDieringer · 5 files (+177 -2), 4 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- Flags subscribers that assign false or a lookup result to the shared database trigger setup flags
- Clearing flags can turn off Dataverse sync, API webhooks, data archive or another app's triggers; a direct Global Triggers subscriber can also clear the change log flags
- Demo data tool and Backup Management test library usages are carved out
- Recommends codeunit 49's integration events over direct system codeunit subscriptions, or table-specific mechanisms when the tables are known
- Wired into al-events-review and review fixtures with good and bad samples; applies to version 15 and later
