# #211 knowledge(error-handling): a bare [TryFunction] call propagates its error

> AL quality knowledge clarifies that bare calls to TryFunction procedures propagate errors rather than suppressing them, preventing false defect reports about error handling.

[Pull request](https://github.com/microsoft/BCQuality/pull/211) · merged into `main` on 2026-11-17 by pri-kise · 9 files (+95 -20), 8 AL · fix · tier official · reviewed (checked by Opus)

## What changed

- New article documents that bare TryFunction calls propagate errors and should not be flagged as suppressed failures
- Updated anti-pattern examples to require visible error handling code like GetLastErrorText checks to match the documented anti-pattern
- Corrected misleading wording in related articles that suggested try functions always catch errors regardless of return value usage
- Agent review rules updated to reference both bare-call and error-catching articles with matching evidence requirements
- Prevents incorrect suggestions to wrap bare calls with if-not-then-Error logic that could expose customer content
