# #159 3 AL/BC testing patterns from an external BC testing expert's blog (Luc van Vugt, fluxxus.nl)

> Three AL testing patterns from an external BC expert's blog are documented as best practices: using events to exclude invalid table relations in tests, committing shared test fixtures before lazy initialization, and using Assert.IsFalse for boolean checks instead of asserterror.

[Pull request](https://github.com/microsoft/BCQuality/pull/159) · merged into `main` on 2026-09-29 by MichaelDieringer · 12 files (+394 -4), 12 AL · feature · tier official · **unreviewed** (machine-generated)

## What changed

- Table Relation Test's OnAfterRemoveTableRelation event hook for excluding relations during test setup
- Shared fixture data requires explicit Commit() to persist across tests, otherwise changes roll back silently
- Assert.IsFalse is the correct assertion for boolean checks, not asserterror wrapped around Assert.IsTrue
- Patterns verified against current BCApps source code and cleared for inclusion in quality rules
- Three candidates were included; one was rejected as unverifiable in supported versions, and two others were excluded as too narrow or obsolete
