# #210 knowledge(upgrade): upgrade code must not use ChangeCompany

> New quality rule and knowledge article prevent upgrade code from using ChangeCompany, which can cause data races, duplicate upgrades, and trigger misexecution in the calling company context.

[Pull request](https://github.com/microsoft/BCQuality/pull/210) · merged into `main` on 2026-10-02 by JesperSchulz · 6 files (+186 -8), 5 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- Adds detection rule for ChangeCompany in upgrade codeunits, Feature Data Update implementations, and helpers reachable from upgrade triggers
- Explains why ChangeCompany is prohibited: per-company upgrade triggers already run in each company's own session, and using it duplicates or races upgrades and records upgrade tags in wrong companies
- Documents best practices: use OnUpgradePerCompany for per-company work with per-company tags, reserve PerDatabase for shared data, and use TaskScheduler for per-company work in other companies
- Updates al-upgrade-review skill with ChangeCompany, Feature Data Update, and UpdateData as worklist tokens to route findings to the new article
- Rule applies to all countries and application areas; reads are intentionally included due to unknown company upgrade order
