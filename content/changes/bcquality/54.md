# #54 Emit human-readable domain label on review findings

> BCQuality review leaves now set an optional human-readable domain label on every finding, so BCQuality owns the display label instead of the consumer engine's static map. Once the BC-ALAgents counterpart is merged, new review domains can render with their own label rather than Other.

[Pull request](https://github.com/microsoft/BCQuality/pull/54) · merged into `main` on 2026-07-15 by JesperSchulz · 19 files (+91 -56), 18 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- Adds optional findings[].domain to the shared review output schema
- Each AL review leaf sets a domain label on every finding; cross-cutting super-skill findings use Agent
- al-code-review preserves a leaf finding's domain verbatim during rollup
- Domain is display text that consumers must preserve exactly, without lossy slugification
- Additive and optional: consumers may fall back to the legacy from-sub-skill mapping when domain is absent
- Behaviour changes for users or extensions.
