# #226 Performance knowledge: justify low-selectivity fields in key columns

> New performance guidance for justifying low-selectivity fields in table keys, requiring evidence such as filtered reads or skewed distributions before including Boolean, Option, or status fields in key columns.

[Pull request](https://github.com/microsoft/BCQuality/pull/226) · merged into `main` on 2026-10-20 by miljance · 5 files (+122 -1), 4 AL · feature · tier official · reviewed (checked by Opus)

## What changed

- Adds burden-of-proof rule for low-selectivity fields in keys to prevent over-indexing
- Includes bad and good code examples showing a key with unfiltered leading flag being rewritten by ModifyAll
- Requires evidence like equality filters on rare values, SIFT keys, unique combinations, or usage data
- Performance review workflow now checks new or changed keys for Boolean, Option, Enum, or status fields
- Applies to all BC versions with guidance on IncludedFields requirement for runtime 8.0+
