# #273 knowledge(style): SetFilter date operands as replacement values; product name via ProductName

> Two new code style rules guide developers to use replacement values for date operands in SetFilter strings and to reference the product name via ProductName methods instead of hardcoded text in user-facing messages.

[Pull request](https://github.com/microsoft/BCQuality/pull/273) · merged into `main` on 2026-11-13 by MichaelDieringer · 8 files (+141 -1), 7 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- SetFilter rule prevents date text parsing issues by requiring date operands as replacement values like '%1|>=%2' instead of '0D|>=%1'
- ProductName rule directs user-facing labels to use ProductName.Short()/Full()/Marketing() methods per Learn guidance
- SetFilter rule excludes user-entered filters, GetFilter/GetView round trips, and DateFormula fields
- ProductName rule excludes locked labels, telemetry, captions, tooltips, and deliberate legacy product references
