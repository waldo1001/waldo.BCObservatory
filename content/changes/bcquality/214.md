# #214 UI knowledge: notification recall needs a known Id; open mixed-type documents through Page Management

> Two new UI design guidance articles added to help developers properly manage notifications by using known IDs for recall and handle multi-document routing through Page Management instead of hard-coded mappings.

[Pull request](https://github.com/microsoft/BCQuality/pull/214) · merged into `main` on 2026-10-06 by MichaelDieringer · 8 files (+365 -7), 7 AL · feature · tier official · **unreviewed** (machine-generated)

## What changed

- Notification recall requires a fixed GUID ID set before sending; without it, later recall calls fail to dismiss notifications.
- Use codeunit 1511 Notification Lifecycle Management to track and recall notifications for specific records when multiple records are visible.
- Avoid duplicating Page Management routing logic with hand-written case statements; use Page Management events for new tables instead.
- Two good/bad code examples provided covering notification lifecycle and document routing patterns.
- Guidance includes documented Learn references and specific Base App examples showing correct implementation.
