# #149 knowledge(web-services): under schema 2.0 an API enum field is a contract by member name, under 1.0 by caption

> A knowledge article clarifies how API enum fields are published: under schema 2.0 by member name with captions in entityDefinitions, under schema 1.0 by en-US caption as Edm.String. Good and bad code samples demonstrate the contract implications.

[Pull request](https://github.com/microsoft/BCQuality/pull/149) · merged into `main` on 2026-09-02 by waldo1001 · 3 files (+150 -0), 3 AL · feature · tier official · **unreviewed** (model text not yet checked)

## What changed

- Schema version determines how enum fields are published in custom APIs, not the ordinal
- Schema 2.0 (BC 24 default) uses strongly typed enums with member names in metadata and responses
- Schema 1.0 (legacy) uses Edm.String with en-US captions in responses
- Renaming enum members breaks schema 2.0 APIs even if captions remain unchanged
- Virtual tables match by External Name, a separate mechanism from API schema contracts
