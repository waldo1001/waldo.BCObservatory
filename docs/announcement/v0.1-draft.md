## Blog post (waldo.be)

### Title: I built an observatory for Business Central (and your AI agent can use it too)

Business Central knowledge lives in a dozen places. Learn has the docs. BCApps and the code history have the truth.
The Microsoft 365 roadmap has what is coming. The launch event has 38 videos. And then there is us: the community
blogs and channels that explain what actually happens when you press the button.

Nobody can keep all of that in their head. And our AI agents certainly cannot: ask one about a field on the Customer
table and you get a confident number that does not exist.

So I built **BC Observatory**: https://waldo1001.github.io/waldo.BCObservatory/

It is one cross-referenced knowledge base, rebuilt every night, with every claim pointing at its evidence:

- **605 topic hubs** seeded from the Learn table of contents, each summarising and linking what Learn documents there.
- **16,425 AL object pages** for BC28, BC29 and BC30, extracted from the actual code (W1 and Microsoft's first-party
  apps): fields, keys, events, public procedures, obsolete state, which versions an object exists in and what changed,
  which countries replace it, and which Learn pages document it.
- **22 localizations**: what the Belgian, Dutch, German (...) layer adds to or changes in W1, down to the field.
- **80 roadmap features** with their status taken from the Microsoft 365 roadmap, and the videos and Learn pages that
  cover them.
- **227 videos** as timestamped evidence, and community posts as derived summaries with short quotes and a link to the
  original (your words stay on your blog; more on that below).
- A **weekly digest** with a deprecation radar: 1,217 obsolete or CLEAN-guarded elements in BC29 today, and which ones
  are due for cleanup.
- **5,336 links** between Learn pages and the code, and a drift report of where they disagree (42 obsolete objects
  that Learn still documents, 39 new pages nobody documented yet).

And because it is built for agents first, every page has a markdown twin, every section an `llms.txt`, and there is
an MCP server:

```
claude mcp add bc-observatory -- npx -y bc-observatory@latest      [CHECK: after the npm publish]
```

Ask it for table 18, what changed in Sales-Post between BC29 and BC30, or what Belgium does differently, and it
answers with the page, the tier (official or community) and the evidence. There is a Claude Code plugin too:
`claude plugin marketplace add waldo1001/waldo.BCObservatory`.

**How it works.** A Mac Mini runs a nightly pipeline on a Claude subscription: deterministic extraction first (the
code is parsed with tree-sitter, never summarised by a model), Haiku for facts, Sonnet for prose, Opus to review.
Pages a model wrote say so until Opus has checked them. The galaxy on the home page is the data model drawn: systems
are domains, stars are hubs, localizations are constellations.

**For bloggers.** Community content is derived only: a summary in our words, at most three quotes under 25 words,
and a link to you. A leak scanner fails the build if more than that ever reaches the public repo. Your blog is in
`sources.yaml`; if you want it removed, or want full text included, open a PR.

It is open source, it is unofficial, and it is very much v0.1. Tell me what is wrong, missing or useful:
https://github.com/waldo1001/waldo.BCObservatory/issues
