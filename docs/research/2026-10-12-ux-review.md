# UX review of BC Observatory, 2026-10-12

Scope: the live site (https://waldo1001.github.io/waldo.BCObservatory/, built from origin/main `3f4daea`) at 1280 and 375 px,
dark and light, plus the MCP server through the plugin. Source read from origin/main. Every number below was measured in
this session; "judgement" marks an opinion with no measurement behind it.

Not in scope: the pipeline, the content policy, the galaxy's data model (D66 decided that; see `docs/specs/galaxy-views.md`).

## What works

- The page skeleton: identity row (type, tier, review badges), title, stat tiles that jump to sections, actions, locator,
  Related, provenance. Consistent on every page type.
- Search: tabs with counts, a status line, grouped results, the Ctrl+K palette with `t18`, `cu 80`, `field:` queries.
- Object pages: the version timeline, the neighbourhood diagram with the full list under it, calls and called-by, the
  "Ask your agent" paragraph.
- The galaxy: the star intro with "Got it" (D87), the Questions menu, keyboard and reduced motion, the list view, the
  390 px fallback (static strip, panel as the page).
- Video pages: click-to-load player, chapters that seek, quotes that link to the second.
- About and MCP pages: voice, the telescope drawing, the "what to ask" table.
- Light theme contrast is fine (wordmark `#131722` on `#F4F5F8`).

## Proposals

Cost: XS = under an hour, S = half a day, M = a few days, L = a spec. Order within a group is by impact.

### A. Navigation and wayfinding

**A1. The header is too heavy on phones and wraps on laptops.** At 375 px the header (wordmark, two rows of nav, the week
pill, the search row) ends at about 430 of 812 px on every inner page; the reader gets half a screen of content. At 1280
and below the header is two rows; one row only from 1440 (Base.astro, D84 note). The nav has 11 entries.
Proposal: below 900 px, a 56 px bar with wordmark, search icon, and a "Browse" menu holding the 11 entries; keep the week
pill but drop the "unofficial, made by waldo" sub-line into the menu. On laptops, group the nav as Browse (Topics,
Objects, Countries, Roadmap), Follow (Changes, Videos, Posts, Weekly, Sources), Use (MCP, About). Cost S to M.
Files: `site/src/layouts/Base.astro`, `site/src/styles/site.css`, `site/src/scripts/chrome.ts`.

**A2. One section has three names.** Nav says Objects, Countries, Roadmap, Weekly; breadcrumbs say AL objects,
Localizations, Features, Weekly; h1s say "25,646 objects", "80 features", "5 weeks"; home cards say AL objects,
Localizations, Roadmap, Weekly, Code changes. Proposal: a single `sections.ts` map (id, nav label, crumb label, h1
noun, card text) used by Base.astro, List.astro, the home cards and the About counts. Cost S.

**A3. Breadcrumbs mix two hierarchies.** "Galaxy / Finance / Topics / Business functionality / Finance" and
"Galaxy / Sales & Receivables / AL objects / tables / Table 18 "Customer"": the galaxy system is inserted before the
section (Page.astro `sysCrumb`). The word Finance appears twice on the topic page. Proposal: crumbs follow the section
tree only; the system becomes a coloured chip in the identity row (the type label already carries the system colour)
and stays in the locator caption. Cost S. File: `site/src/layouts/Page.astro`.

**A4. The instruments are footer-only.** Version lens, Deprecation radar, Events, Coverage, Drift and the Neighbourhood
explorer are reachable from the footer line and the Objects lede, nowhere else. This is direction E of the
six-directions canvas (the instrument panel), the one part of it D66 did not build. Proposal: an "Instruments" strip on
the home page under the galaxy, one card per instrument with a live number (events and subscriptions, obsolete elements
in the current major, objects changed between the last two majors, countries by areas, drift counts, this week's
digest) and the same strip as an "Instruments" heading on `/objects/`. The counts exist in `data/index` and
`data/code`; `site/src/lib/about.ts` `countRows` is the pattern. Cost S.

**A5. The week pill loses its meaning in its most common state.** "6 new · 35 PRs": Base.astro drops " this week"
exactly when PRs exist (`week.changes > 0 ? "" : " this week"`). Proposal: "This week · 6 new · 35 PRs". Cost XS.

**A6. Platform-blind shortcuts and glyph buttons.** The header button reads "⌘K" on every platform while its title says
Ctrl+K; the theme button is "◐" with no text. Proposal: label from `navigator.platform` (Ctrl+K on Windows and Linux),
and a text label "Theme" next to the glyph from 900 px up. Cost XS.

### B. Object pages (25,666 of the 28,850 pages)

**B1. No in-page navigation on 50-screen pages.** Table 18 "Customer" is 49,238 px tall at 1280, 157 KB of HTML, 18 h2
sections in the main column, 170 table rows. Codeunit 80 "Sales-Post" is 257 KB with 530 events listed. The stat tiles
jump to eight sections; Keys, Relations, Referenced by, Extended by, Recent changes, Deprecations and Ask your agent
have no entry. Proposal: a sticky "On this page" list in the side column (the h2s with their counts, current one
highlighted by an IntersectionObserver) and a back-to-top control after the first screen. The side column is empty
below Related, so it costs no space. Cost S. Files: `Page.astro` (side slot), `chrome.ts`, `site.css`.

**B2. Member tables are flat, full and unfiltered.** The design handoff (section 4, "object member table") asked for
tabs Fields / Procedures / Events over one table; the page renders the full markdown. The Explanation column carries
whole tooltips, three to eight lines per row, so Fields alone is about 15 screens. Proposal, all in the browser, no
pipeline change: a filter box per member table ("filter 165 fields"), a toggle that clamps Explanation to one line
(full text in a title and on click), and sort by No., Name, Type, Changed in. Cost M. New file:
`site/src/scripts/member-table.ts`, mounted from Page.astro on `#fields`, `#procedures`, `#events-published` tables.

**B3. Changed-in markers crowd the Name column.** "No. Δ BC25 Δ BC26" repeats on most rows (`markMembers`), while the
version timeline above already tells the version story. Proposal: render the markers as one compact mono tag at the row
end ("25 26") and add a "changed in BC29" chip above the table that filters the rows, tying it to the version pill. Cost S.
File: `site/src/lib/versions.ts`, the member-table script.

**B4. Stat tiles on phones are a full screen of numbers.** Eight tiles in two columns, four rows, before any content.
Proposal: under 600 px, one wrapping line of chips ("165 fields · 160 procedures · ...") that still jump. Cost XS (CSS).

**B5. The version timeline hides its oldest major.** At 1280 the row scrolls horizontally and starts at the newest
(chrome.ts), so BC23 is off-screen left with only a scrollbar as a hint. Proposal: collapse leading "present, unchanged"
majors into the first dot ("BC23 to 24: present"), and wrap to two rows under 900 px. Cost S.
File: `site/src/components/VersionTimeline.astro`.

**B6. Neighbourhood diagram: truncated labels, no key.** Labels cut at about 18 characters ("Table 379 "Detailed
Cust. Le…"), edge kinds are not explained, the diagram shows 40 of 311. Proposal: full name in a `title`, a one-line
key of the edge kinds under the diagram, and "Open in the neighbourhood explorer" styled as the section's primary
action. Cost XS to S. File: `site/src/components/Neighbourhood.astro`.

**B7. Provenance on every page is owner-facing.** Input hash and pipeline version matter to the pipeline, not to a
developer looking up a table. Proposal: keep tier and review as badges (they already are) and fold the `dl` into a
closed `details` "Provenance". Cost XS. File: `Page.astro`.

**B8. "Ask your agent" is the last thing on the longest pages.** It is the most useful hand-off for developers.
Proposal: a third action in the actions row ("Ask your agent") that opens a small popover with the three bcatlas calls
to copy, and keep the paragraph at the end. Cost S. Files: `Page.astro`, the object route, `chrome.ts`.

### C. List pages and page weight

**C1. Whole lists in one HTML file.** `/changes/` is 596 KB (1,083 rows with summaries), `/videos/` 622 KB (616 rows
with posters and summaries); `/posts/` has 602 rows. Every visit downloads and parses the whole list, and the Pages size
budget (D76) pays for it on every rebuild. Proposal: render the first 50 rows statically (crawlers, noscript), then
"Show more" from the media shard the search index already ships (`index/pages-media-*.json`); the atlas table already
works this way. Cost M. Files: `changes/index.astro`, `videos/index.astro`, `posts/index.astro`, `index-loader.ts`.

**C2. Filters where the data invites them.** Changes: the kinds line ("2 breaking · 353 feature · 619 fix ...") sits
right under the repository pills, looks like pills, does nothing. Videos and posts: no source, year or reviewed filter.
Proposal: kinds as a second pill row with "breaking only" and a major pill (the D82 pills-core helpers are generic);
source and year pills on videos and posts. Cost S per page.

**C3. The digests index is five bullets, with the empty running week on top** ("0 videos, 0 posts, 0 Learn commits").
Proposal: a card per week with the headline numbers and the deprecation radar count; the running week marked "in
progress" and dimmed. Cost S. File: `digests/index.astro`.

**C4. Sources index is a flat list.** Source pages have favicons and avatars (D60). Proposal: cards with icon, kind, tier,
count, top three systems and the last flight-path stop. Cost S. File: `sources/index.astro`.

**C5. Roadmap tracker cells do not link.** The wave by status table on `/features/` is a good summary; each count could
filter the table below. Add status and area pills. Cost S.

### D. Home and galaxy

**D1. The galaxy owns the first screen and nothing says there is more.** The home galaxy is `100svh` minus the header;
Newly lit, Sections and About sit below with no cue. Proposal: cap the galaxy at about 70svh on the home page, or a slim
"this week" strip docked in the galaxy's bottom fade with the newest two items and a link down. Cost XS to S.
File: `site/src/pages/index.astro`.

**D2. The six-line help paragraph under the galaxy duplicates the star intro** (D87) and nobody reads a paragraph of
keyboard hints. Proposal: delete it; a "?" button in the tools row opens a shortcut sheet (Esc, arrows, + and -, F, T,
list view). Cost XS.

**D3. The lens bar mixes six control shapes.** Questions menu, version pill with a caret, "this week" toggle, a native
"more lenses" select, "list view" toggle, and at system level a tilt slider and "planes". Proposal: two groups.
Left: Questions, then one segmented Lenses control (version, this week, type, tier, coverage, country, source). Right,
with Show panel and Full screen: list view and tilt, which are view modes, not lenses. Cost S to M.
Files: `Galaxy.astro`, `galaxy.ts`.

**D4. On phones the lens bar clips its last pills** with no affordance (static galaxy, 375 px: "this week" then a cut
pill). Proposal: wrap to two rows under 480 px (vertical space is cheap there), or a right-edge fade mask. Cost XS.

**D5. Mobile home order buries the content.** Header, 150 px static strip, lens bar, "21 systems", the intro, a 21-row
system list, and only then Newly lit and Sections. Proposal: under 480 px, Newly lit and the Sections cards come before
the system list, or the system list becomes a closed `details`. Cost XS to S.

**D6. System level is dense (judgement, one system measured).** On Finance at 1280 the port chips overlap the ring labels
and each other, and the top-five captions sit on the stars. Proposal: ports only for the focused star (today the system
draws them), and a collision pass that skips a caption overlapping the previous one. Measure three more systems before
deciding. Cost M. File: `galaxy.ts`.

### E. Media pages

**E1. Post pages open with a 70vh iframe of someone else's site.** `.stage-frame--page` is `clamp(480px, 70vh, 960px)`
and sits above the observatory's own key points, quotes and AL objects mentioned. While the blog loads, or when it
refuses framing, the first screen after the title is an empty box (seen on `posts/aardvarklabs-blog/1609/`).
Proposal: default to the source card (favicon, byline, first quote, "Read it here") and load the frame on click, the
way the video stage uses its poster; the "Read it here" action already exists. Cost S.
Files: `site/src/components/SourceStage.astro`, `site/src/scripts/source-stage.ts`.

**E2. Video Features tables repeat the same status on every row** ("status not stated, demoed" seven times on
`videos/-SGaVGOkiF0/`). Proposal: when every row shares a status, print it once above the table. Cost XS, a render
change (`pipeline/render/video.ts`), no LLM, rewrites those video pages on the next nightly.

### F. Small fixes

- **F1.** "1 videos" in digest summaries: `pipeline/render/digest.ts` line 89 hard-codes plurals. XS.
- **F2.** Search results print the markdown path under every hit (`objects/codeunit/80.md`) in mono; readers do not need
  it. Move it to the hover title. XS. File: `site/src/scripts/search.ts`.
- **F3.** The search tab row shows all thirteen tabs including the empty ones; on a phone that is five rows of tabs
  before the first result. Hide empty tabs (the `.empty` class exists) behind "+n more". XS.
- **F4.** Theme toggle persists but has no text label; see A6.
- **F5 (judgement).** "Open in Claude" is the primary action on every page type. Per type the human primary is
  arguably Watch here (video), Read it here (post), Source on GitHub (object). Consider per-type primaries.
- **F6 (judgement).** Straight quotes in h1s, Table 18 "Customer": the type label already says table; the quotes could go.

### G. Agent UX (MCP server and plugin)

**G1. `get_object` returns the whole page, and big objects do not fit a tool result.** Codeunit 80 "Sales-Post" came
back as 177,746 characters over 925 lines (max line 788 characters); in this session the call exceeded the client's
tool-result limit and had to be read back from a file. `search` is compact by contrast (five hits in about 1.5 KB).
Proposal: a `section` parameter (properties, fields, keys, events, subscriptions, procedures, triggers, relations,
calls, called_by, changes, versions, countries, deprecations) with `offset` and `limit` for long sections; the default
answer is the frontmatter facts, the counts, the first 20 rows of each section and one line per section saying how to
get the rest. The same `section` on `cat`. Say in the tool description that symbol search (`event:`, `field:`,
`proc:`) answers "does this exist" without fetching the object. Cost M. Files: `packages/mcp/src/server.ts`, the
`bc-lookup` and `bc-grounding` skills.

**G2 (judgement).** Tool descriptions are long (`search` about 1,900 characters) and cost tokens in every session that
has the server. Keep the capability list, move the examples into the plugin skills. XS.

## Method

Pages seen: home (galaxy level and Finance system level), `objects/table/18/`, `objects/codeunit/80/` (through the
MCP), `topics/.../finance/`, `localizations/be/`, `search/?q=sales-post`, `changes/`, `about/`, `mcp/`, `digests/`,
`digests/2026-W41/`, `videos/`, `videos/-SGaVGOkiF0/`, `posts/aardvarklabs-blog/1609/`, `objects/`, `sources/`,
`sources/aardvarklabs-blog/`, `neighbourhood/`, `features/`. Viewports 1280x900 and 375x812, both themes. HTML sizes by
`curl`. Page height and section list by script in the page. MCP: `search` and `get_object` through the installed plugin.
