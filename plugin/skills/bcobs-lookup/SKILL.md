# Business Central lookup

If no `bc-observatory` tool (`bc_search`, `bc_cat`, `bc_get_object`, ...) is available, even after ToolSearch, say so before answering, and give the install steps for the user's app from https://waldo1001.github.io/waldo.BCObservatory/mcp/#install (Claude in the browser or on your phone: the observatory's search is not available there yet; Claude Desktop: the extension; Claude Code: the plugin). Do not invent object ids, field numbers or versions while the server is missing.

Use the `bc-observatory` MCP tools; never answer object ids, field numbers or versions from memory. If the `bc_*` tools are deferred, load them with ToolSearch first.

For a web client link (`…?company=…&page=22&filter=…`): `bc_search("Web client URL", type: "learn", mode: "keyword")` finds Microsoft's article; read its url with `microsoft_docs_fetch`. Confirm each page id with `bc_search("page 22", kind: "page")`, not `bc_get_object`.

0. `bc_brief(query)` for a question that wants the whole picture (how it works, the code, what changed, warnings, gaps): one call, five layers, every line with its tier and source; then `bc_cat` or `bc_get_object` on the lines you need. A line under "Gaps" or labelled "possibly related" is not a stated fact: say so.
1. `bc_search(query)` for anything: a name (`Sales Header`), a reference (`t36`, `cu 80`, `table 11300 BE`), a bare id (`36`), a field, event or procedure (`Posting Date`, `OnAfterPostSalesDoc`, `event: OnAfterPost`, `proc: CopyToTempLines`). Filter with `type` (object, topic, learn, app, feature, localization, video, post, change, source, digest, release), `tier` (official, community), `system` (finance, sales, development, ... or an alias such as `g/l`), `country` (`BE`), `app` (`Subscription Billing`), `object_type` (`table`) or `kind` (page, field, event, proc, value). Hits marked `[meaning]` were found by meaning only: check them.
2. `bc_get_object(type, idOrName, country?)` for an AL object by id, reference (`t36`, `36-be`), name or caption: fields, keys, events published, public procedures, calls, obsolete state, versions it exists in, countries that replace it, Learn pages naming it. When it lists candidates, pick one by its path. A page over 30,000 characters (Table 36, Codeunit 80 and about 140 more) comes back compact: the frontmatter, the first 5 rows of each section and the section keys; read the part you need with `section` (`fields` on a table, `controls` on a page, `events`, `procedures`, `calls`, ...) and page with `offset` and `limit` as the answer's last line says. A `No section` answer lists the keys: retry once with one of them before repeating the call for other objects. To check that an id and a name go together, `bc_search("page 22", kind: "page")`, one call per id, is cheaper than `bc_get_object`; to check that a field, event or procedure exists, `bc_search("event: OnAfterPostSalesDoc")` is cheaper than the page, and `bc_cat` of the hit's path (`objects/codeunit/80#event-OnAfterPostSalesDoc`) returns just that member. The frontmatter's `counts.procedures` counts every procedure (public, local, events, subscribers); the summary's "public procedures" excludes locals and events.
3. `bc_cat(path)` to read a page; its frontmatter carries `evidence` (URLs, commits, video seconds) and `links`. `bc_cat` takes the same `section`, `offset` and `limit`.
4. `bc_diff_object(type, id, from, to)` for what changed between two versions (28 -> 29, 29 -> 30).
5. To read a Learn page: when a hit is a Learn article (it carries `url=`), or a hub's `links.learn` holds the answer, read the page with the Microsoft Learn MCP's `microsoft_docs_fetch(url)` before answering a how-to, setup or concept question. For AL code examples use `microsoft_code_sample_search(query, language: "al")`. Search Learn directly (`microsoft_docs_search`) only when the observatory found nothing or the topic is not Business Central; Learn search alone may return NAV, GP or Dynamics 365 Finance pages, so check the URL is under `/dynamics365/business-central/`. Never answer object ids, fields or versions from Learn text: those come from the observatory. If the user already has a Learn MCP under another name, use that one.

For procedure bodies and the call graph, see `bcobs-grounding`.

Answer with the tier of each claim (official = Microsoft, community = everyone else), the version it applies to, and the evidence link. If a page is marked unreviewed, say it is machine-generated. If nothing is found, say so; do not guess.
